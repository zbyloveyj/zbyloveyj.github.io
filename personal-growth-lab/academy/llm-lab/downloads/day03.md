## Embedding 是一张可学习的表

设词表大小 V=6，向量维度 D=3，embedding 就是一张 [6,3] 的参数表。输入 ID 2 时取第 2 行；输入 [2,1,2] 时依次取三行，其中第一个与第三个初始向量相同。查表本身没有读到相邻 token，也没有执行语义搜索。它只是把离散身份变成后续网络能处理的连续坐标。

为什么这些坐标会有用？因为训练损失沿计算图传回 embedding，使被用于预测的表示逐步改变。向量关系来自任务和数据，并不是随机初始化时已经藏着知识。一个未训练 embedding 中两个物种名余弦相似度高，没有生物学意义；即便训练之后，也要问相似性反映了共现、语法、来源偏好还是实际功能。

Embedding 可以理解为可学习的特征设计。在传统建模里，你人工决定一个对象用哪些特征；这里先给对象一组可优化坐标，再让任务决定如何利用它。维度 D 是容量选择，不是“模型理解了 D 种独立科学属性”。解释每个维度前需要额外证据。

## 查表与 one-hot 乘法为何等价

如果 ID 为 2，可写成长度六的 one-hot 向量 [0,0,1,0,0,0]。它乘 embedding 表只保留第 2 行，所以与查表结果相同。对批量序列，可以把每个 ID 变成 one-hot 后一起乘矩阵，但当词表很大时，这会建立大量零值，查表在表达和存储上更直接。

下面给参数表一个固定的人工数值，避免随机结果妨碍手算。输入的第二轴是位置，输出最后一轴是向量坐标。代码中的 assert 不只是确认 API 能运行，而是在检验我们对计算含义的理解。先手写期望的三维数组，再运行，才算完成这个练习。

注意数学表达中的行向量约定可能与代码权重布局不同。PyTorch 的 Linear 权重通常存成 [输出维,输入维]，前向等价于 x 乘权重转置；Embedding 存成 [词表,向量维]，直接按行索引。看到 W 与 W 转置时，先核对维度，不用死记某一种论文记号。

```python
import torch
import torch.nn.functional as F
E = torch.arange(18, dtype=torch.float32).reshape(6, 3)
ids = torch.tensor([[2, 1, 2], [0, 5, 3]])
lookup = E[ids]
onehot = F.one_hot(ids, num_classes=6).float()
assert lookup.shape == (2, 3, 3)
assert torch.equal(lookup, onehot @ E)
assert lookup[0, 0].tolist() == [6., 7., 8.]
print(lookup)
```

## 同一个 token，为何在不同位置需要不同表示

不考虑上下文时，相同 token ID 查到同一行。“菌群影响药物”和“药物影响菌群”包含相近词汇，却表达不同方向。序列模型需要某种方法表示顺序，否则仅仅把词向量放成一堆，很难区分这些关系。位置编码为模型提供“在哪里”的信息，token embedding 提供“是什么”的信息。

最直观的方案是可学习绝对位置表 P，形状为 [Tmax,D]。序列第 t 个位置取 P[t]，与对应 token 向量相加。位置表在所有 batch 样本共享，所以 [T,D] 可以广播到 [B,T,D]。相加要求最后一维相同；把二者拼接也可设计，但后续投影维度和参数量都要相应改变。

绝对位置表只为定义范围内的位置存了参数。若训练与实现只支持长度 32，不能在推理时随意输入长度 64 并期待正确外推。裁剪历史、重新设计位置机制和扩大训练上下文是不同方案。课程先明确上限并检查边界，后面再认识 RoPE 等方法。

## 位置编码没有“越先进越适合一切”的顺序

正弦位置编码用不同频率的正弦、余弦构造确定向量，无需学习位置表；可学习位置表由训练调整；旋转位置编码在注意力的查询与键上施加与位置有关的旋转。它们把顺序信息放入计算的方式不同，不能把换一个名字当作必然提升性能。

语言具有自然先后顺序，因果遮罩也会提供“能看到多少前缀”的结构，但顺序信号不等于单独一个位置向量，实际效果由完整架构决定。本课用显式位置编码，便于直接检查位置如何影响表示。实验中若去掉位置项，应把它当作一个有定义的消融，并在相同训练预算下比较。

菌群丰度表没有“排在第三列的物种在时间上早于第四列”的含义。后面的模型使用物种身份与丰度，避免把任意 CSV 列序当作语言位置。若引入系统发育信息，应作为有生物学依据的额外关系，而不是把表格排序伪装成进化距离。输入设计服务于科学对象。

## 从输入到输出，逐轴核对

以 B=2、T=4、D=8、V=10 为例，输入 ID 是 [2,4]，查词表得到 [2,4,8]，位置项为 [4,8]，相加仍是 [2,4,8]。之后 Transformer 保持这个主干形状，最后输出投影把每个位置的 8 维表示映射为 10 个候选分数，得到 [2,4,10]。

最后一层产生的数值叫 logits，可以为正或负，也不要求和为一。softmax 沿词表轴把它们转为概率；沿错误轴做归一化也可能得到看起来合理的数组，但那不再是每个位置的候选 token 分布。交叉熵实现通常直接接收 logits，在内部进行稳定计算，不需要你先手工 softmax。

在调试表中，为每个节点写四件事：形状、dtype、device 和语义。输入 ID 常为 long，embedding 输出为浮点，两者要在同一设备。把模型放到某设备而忘记移动位置索引，是实际编码里很常见的错误。对小模型而言，先统一在 CPU 使用 float32 最便于理解。

| 阶段 | 形状 | 类型 | 含义 |
| --- | --- | --- | --- |
| 输入 ID | [B,T] | 整数 | 词表索引 |
| token 向量 | [B,T,D] | 浮点 | 身份表示 |
| 位置表切片 | [T,D] | 浮点 | 序列位置 |
| 上下文表示 | [B,T,D] | 浮点 | 经过信息混合 |
| logits | [B,T,V] | 浮点 | 候选分数 |
| 目标 | [B,T] | 整数 | 右移 token |

## 写出最小预测器，并准确说明它的限制

下面的模块只有 token embedding、位置 embedding 和输出投影。它足以演示数据接口及损失形状，却没有把不同位置的信息混合起来。位置 t 的预测只能使用当前 token 向量和位置向量，无法依据更早上下文区分同一个 token 的不同用法。这是后面加入注意力的直接动机。

运行时只检查输出形状与数值有限，不检查它能否写出自然语言。随机初始化的模型没有接受训练，输出概率接近某种无知识的初始分布才正常。如果一个复杂系统在初始化后就能输出完整科学回答，那通常说明你调用了已有模型或外部内容，而不是刚刚训练出知识。

读完整工程时，找到同样的三个接口，再定位它们之间新增的 Transformer blocks。这样即便代码变长，你仍能知道每部分承担什么。不要把 embedding 之后的所有内容一概叫“黑箱”，每天只增加一种能解释的变换。

```python
import torch
from torch import nn
class TokenPositionHead(nn.Module):
    def __init__(self, vocab=10, dim=8, context=4):
        super().__init__()
        self.token = nn.Embedding(vocab, dim)
        self.position = nn.Embedding(context, dim)
        self.head = nn.Linear(dim, vocab, bias=False)
    def forward(self, ids):
        B, T = ids.shape
        pos = torch.arange(T, device=ids.device)
        h = self.token(ids) + self.position(pos)
        return self.head(h)
model = TokenPositionHead()
ids = torch.tensor([[1, 2, 3, 4], [4, 3, 2, 1]])
logits = model(ids)
assert logits.shape == (2, 4, 10)
assert torch.isfinite(logits).all()
print(sum(p.numel() for p in model.parameters()))  # 192
```

## 参数量与内存，先算后改

上面的小模块有词表参数 10×8=80、位置参数 4×8=32、无偏置输出参数 8×10=80，总计 192。参数量可以手算，也可以用 numel 汇总，两者对不上时要查是否包含 bias、归一化参数或共享权重。模型名称中“多少参数”应来自实际实现，不照抄别人的结构估计。

如果 V=256、D=64、Tmax=64，词表参数是 16384，位置表是 4096，独立输出表又增加 16384。输入与输出权重共享时，两处使用同一组参数，总量会降低；这是建模选择，不能仅把数值复制一遍就叫共享。真正共享还意味着来自两条路径的梯度会共同更新同一参数对象。

参数内存只是训练内存的一部分。float32 参数每个通常占四字节，还要考虑梯度、优化器状态、中间激活、注意力矩阵和缓存。小模型可用手算建立量级感觉，大模型要实际测量峰值。把训练失败简单归因于“参数太多”，可能忽略了上下文长度带来的更大开销。

## Embedding 的梯度会更新哪些行

在纯查表后求和的例子中，只有被索引的行收到梯度，重复出现的 ID 会让梯度累加。输入 [1,1,3] 时，第一行出现两次，第三行一次，其余行没有参与这条计算路径。这是一个适合手算的局部事实，也能帮助理解罕见 token 在小语料中为什么可能学得不足。

不要把这个结论直接推广成“语言模型每步只更新出现过的词表行”。若输出投影与输入 embedding 共享权重，softmax 预测的输出路径会对候选行贡献梯度；不同的优化器设置也会影响参数变化。区分“这条局部路径的梯度”和“整个模型参数的总梯度”，是读懂共享权重的重要一步。

下面只验证纯查表路径。运行后检查 grad 数值，再把 loss 从 sum 改为 mean，观察梯度按参与元素数缩放。梯度大小与损失的归一化规则直接相关，这个结论到第六课的梯度累积时会再次出现。

```python
import torch
from torch import nn
emb = nn.Embedding(5, 2)
ids = torch.tensor([1, 1, 3])
emb(ids).sum().backward()
expected = torch.tensor([[0.,0.],[2.,2.],[0.,0.],[1.,1.],[0.,0.]])
assert torch.equal(emb.weight.grad, expected)
print(emb.weight.grad)
```

## 静态向量、上下文向量与样本向量

静态 embedding 对同一 token 返回固定初始向量，经过注意力与非线性层后，同一 token 的表示会因上下文改变。最后可以选择某个位置、做有效位置平均或使用特定汇聚方式，把一段文本压成一个向量。汇聚方式定义了保留与丢失的信息，应根据任务验证。

在菌群模型中，每个物种先有身份向量，再结合该样本丰度，经双向信息混合后得到样本内物种表示，最后汇聚为样本向量。这个向量可以用于线性探针或其他下游任务，但聚类图上分得开不等于疾病信号可泛化；它也可能按研究、测序流程或人群结构分开。

比较向量时，余弦相似度关注方向，欧氏距离同时受尺度影响。归一化、汇聚和训练目标都会改变距离含义。今天可计算相似度熟悉操作，但不要给随机向量贴“产丁酸功能”“炎症轴”等标签。科学解释必须由独立分析支持。

## 今天的调试清单：把接口固定下来

遇到 embedding 报索引越界，先检查最小和最大 token ID 是否处于零到 V−1，再检查 tokenizer 与模型词表版本。遇到矩阵乘法形状错误，打印出错层输入最后一维与权重输入维，不要凭直觉连续 reshape。reshape 能改变排列解释，却不能修复语义错位。

给工程做一次接口走查：输入的 batch 从哪里来；位置 ID 在哪里产生；token 与位置在哪一行相加；blocks 是否保持 D；输出 head 是否得到 V；目标是否只在损失处使用。训练前的前向过程不应该读取验证标签或未来 token。把每个问题对应到具体函数，就完成本课的代码导读。

最后用一张纸画出自己的形状链和参数公式，再运行同样输入，比较模型处于训练与评价模式时的行为。若架构包含 dropout，训练时重复前向可以不同，评价时在固定输入和环境下应稳定。不同现象要用模块行为解释，而不是统称“随机性”。

## 论文导读

### Efficient Estimation of Word Representations in Vector Space (2013)

https://arxiv.org/abs/1301.3781

理解离散词如何通过训练任务获得连续表示；它与上下文化 Transformer 不是相同架构。

- 阅读向量表示的任务动机与架构概念。
- 关注作者用什么评价向量，而不只看可视化。

**参考思路：** 训练目标、数据及评价共同确定，坐标本身没有先验语义。

**阅读问题：** 词向量相似就代表两个物种功能相同吗？

**参考思路：** 不能。文本共现和生物功能是不同关系，需要独立验证。

### RoFormer: Enhanced Transformer with Rotary Position Embedding (2021)

https://arxiv.org/abs/2104.09864

作为位置方法扩展，认识旋转如何进入查询与键；今天不要求替换主线实现。

- 阅读 rotary position embedding 的方法动机。
- 对比与 token 向量直接相加的位置表。

**参考思路：** 不能保证；训练长度、频率设置与外推策略仍影响表现。

## 练习与完整参考解答

### 练习 1. V=1000、D=32、Tmax=64，无偏置且不共享输出权重，仅三张表共有多少参数？

提示：词表、位置、输出分别计算。

参考解答：1000×32＋64×32＋32×1000=66048。共享输入输出后为34048。

### 练习 2. 最小模块去掉位置表后，同一批中相同 ID 的 logits 是否相同？

提示：模块没有 attention 与 dropout。

参考解答：相同，因前向只由相同 embedding 经同一输出投影得到。它无法利用上下文差异。

### 练习 3. 若在 embedding 中输入负数或等于 V 的 ID，应怎样处理？

提示：不要依靠取模掩盖问题。

参考解答：视为编码或词表不匹配并明确报错；检查 unknown 策略和版本。取模会把未知符号误映射为另一个真实 token。

### 练习 4. 能否从样本向量的疾病聚类直接证明跨研究泛化？

提示：考虑队列与标签是否混杂。

参考解答：不能。需要按研究划分评价，并检查向量是否主要编码研究或技术批次。

## 验收自测

### 1. Embedding 参数形状通常是什么？

A. [B,T]
B. [V,D]
C. [D,B]
D. [T,V]

参考答案：B。V 行各对应一个 token，D 是表示维数。

### 2. Logits 是否必须和为一？

A. 必须
B. 必须非负
C. 不必
D. 必须在0到1之间

参考答案：C。logits是未归一化分数，概率才按词表轴归一化。

### 3. 纯查表中相同 ID 返回什么？

A. 随机新行
B. 不同位置必不同
C. 同一参数行
D. 只返回ID本身

参考答案：C。上下文差异在之后的信息混合中形成。

### 4. 为什么菌群 CSV 列序不应直接当语言位置？

A. Transformer不能处理表
B. 列没有天然时间词序
C. 所有物种完全相同
D. 丰度不是数字

参考答案：B。应根据科学对象选择位置与关系编码。

### 5. 权重共享是什么意思？

A. 复制相同初值
B. 保存两个文件
C. 两处引用同一参数对象
D. 输出维度随意改变

参考答案：C。共享对象由两条路径共同贡献梯度。
