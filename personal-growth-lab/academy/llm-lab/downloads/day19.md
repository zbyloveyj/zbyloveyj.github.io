## 先把“模型多大”拆成四份账

参数个数只描述权重张量的元素数量，不能单独决定训练显存。训练还要保存梯度、优化器状态和反向需要的激活；生成时通常不需要优化器，却会随着输入与输出长度增加KV缓存。比较资源需求前，先说清是在加载、训练、prefill还是逐token解码。

对N个参数，一种明确的混合精度账本是每参数2字节计算权重、2字节梯度、4字节FP32主副本和8字节Adam两份矩，共16N字节。这是一种实现约定，实际框架可能保留FP32梯度或使用不同优化器状态。FP32 Adam的4+4+8也为16，但分项不同，不能据同一个总数推断存储结构。

7×10^9参数的两字节权重约13.04GiB，上述训练参数状态约104.31GiB，还未加激活、logits、工作区、通信缓冲与碎片。量化权重的理想4bit载荷约3.26GiB，缩放因子和解量化缓冲也要空间。因此“权重能放下”与“任务能运行”是两个不同的容量检查。

| 项目 | 示例字节/参数 | 何时存在 |
| --- | --- | --- |
| 低精度权重 | 2 | 训练与推理 |
| 低精度梯度 | 2 | 此训练约定 |
| FP32主权重 | 4 | 此混合精度优化约定 |
| Adam一阶与二阶矩 | 8 | 此优化器训练 |
| 激活与KV缓存 | 另算 | 依模式、batch、长度改变 |

## KV缓存按键值头计算，激活按实际图计算

假设每层保存键和值，batch为B、层数L、历史总长度T、KV头数H_kv、头维d、每元素s字节，则缓存载荷为2LBTH_kvds。T包括提示与已生成内容；GQA下不能误用查询头数。若不同请求长度不等，固定长度预分配与动态分页的实际浪费也不同。

示例L=32、B=1、T=8192、H_kv=8、d=128、s=2，恰好为1GiB。把batch与长度各翻倍会变成4GiB；只增加生成上限也会增加峰值。缓存分片、窗口裁剪、量化和共享前缀会改变这份账本，但必须说明采用了哪一种策略。

训练激活更依赖实现。普通注意力显式分数矩阵形状为[B,H,T,T]，其元素随T²增长；MLP与残差激活往往包含BTD及隐藏扩展项。不要用一个固定“每参数几字节”把序列长度的影响抹掉。预算实验只做载荷算术，不申请这些大张量。

```text
KV_bytes = 2 L B T H_kv d s
```

```python
N, L, B, T, Hkv, dh, s = 7_000_000_000, 32, 1, 8192, 8, 128, 2
kv = 2*L*B*T*Hkv*dh*s
assert kv == 2**30
ledger = {'bf16_weight_gib':2*N/2**30,
          'example_adam_state_gib':16*N/2**30,
          'kv_gib':kv/2**30,
          'double_batch_double_context_kv_gib':4*kv/2**30}
print(ledger)
```

## DDP：复制模型，用不同数据求平均梯度

数据并行让每个rank保存模型副本，处理不同样本，通过梯度通信得到一致更新。DDP通常不替你划分输入，数据分片和每轮shuffle需要由sampler负责。它减少每个rank承担的数据量，却没有把每份参数或Adam状态除以设备数量。

若各rank有效token数相同，局部平均loss的梯度再平均就对应全局平均。若数量不同，仍要按全局有效目标总数M加权：在R个rank梯度最终求平均的约定下，局部使用R×S_r/M，其中S_r是本rank的目标损失和。这样最终梯度才是Σ∇S_r/M，而不是对短序列rank过度加权。

累积时可暂缓部分同步，但所有rank必须遵循兼容的通信调用顺序。DDP的no_sync需要覆盖相应前向与反向，不能只包backward。原始官方接口说明见https://docs.pytorch.org/docs/2.14/generated/torch.nn.parallel.DistributedDataParallel.html。本课程解释机制，没有运行多GPU训练。

## ZeRO与FSDP：把冗余状态分片

ZeRO阶段一分片优化器状态，阶段二进一步分片梯度，阶段三再分片参数。其基本思想是让不同数据并行进程共同承担原本重复保存的训练状态，而在需要时通信获取。理想常驻状态可以随设备数下降，但临时完整参数、预取和通信缓冲仍构成峰值。

FSDP采用与完全分片相近的思路：模块计算前all-gather所需权重，反向后reduce-scatter梯度，并在适当时机释放完整副本。分组过大时临时峰值高、重叠少；过细则通信次数与调度开销增加。选择包装边界需要同时看显存和时间，而不是只追求最低常驻字节。

以上述16N的示例参数状态账本，八路完全均匀分片的理想常驻部分可写16N/8，但不能据此保证一张对应容量的卡足够。官方FSDP资料（https://docs.pytorch.org/docs/2.14/distributed.fsdp.fully_shard.html）明确了计算前聚合与梯度分散的生命周期；实现时还要核对当前版本的保存和混合精度契约。

## 其他并行：切的是数据、矩阵、层还是专家

张量并行把一个线性层的矩阵沿输入或输出维分给多个设备，因此单层计算也需要协调；流水线并行把不同层放到不同设备，用微批次交错减少空闲。流水线开头和结尾会有气泡，更多microbatch能改善利用率，却会改变调度和缓存需求。

专家并行把MoE专家分布到不同设备，路由后的token需要搬到相应专家再汇合。总参数与活跃参数的区分仍然重要：活跃计算较少，并不消除存储全部专家以及路由通信的需求。序列或上下文并行则尝试分摊长序列相关的激活和计算，具体通信依实现而异。

并行维度可以组合，但组合后样本全局batch、参数归属、通信组和检查点都会更复杂。对当前CPU教学模型，增加分布式架构没有必要；正确决策是能说出哪一份账超限，以及哪一种并行能降低它，避免把所有缩写同时加入工程。

| 方式 | 主要切分对象 | 常见代价 |
| --- | --- | --- |
| 数据并行 | 样本 | 梯度同步 |
| 完全分片 | 训练状态 | 按层聚合/分散 |
| 张量并行 | 层内矩阵 | 频繁激活通信 |
| 流水线并行 | 模型层 | 气泡与阶段平衡 |
| 专家并行 | 专家与路由token | all-to-all与负载不均 |

## 通信账本：设备增加不等于线性加速

理想环形all-reduce可看作reduce-scatter与all-gather两阶段，各传送R−1次大小约G/R的分块，因此每rank发送总量约2(R−1)G/R，G为梯度字节数。这个推导忽略启动延迟、拓扑、拥塞和计算重叠；它帮助建立量级，而不是预测真实墙钟时间。

假设G为28GB、R为8，发送量约49GB。若人为设定有效链路吞吐100GB/s，纯传输下界约0.49秒；该吞吐是算术假设，没有对应本项目的硬件测量。小batch使计算时间短时，通信难以被隐藏，增加设备可能收益很小。

性能分析应分别报告有效token每秒、单步延迟、通信等待、峰值显存和扩展效率。把padding算进token吞吐会高估有效工作；只记录GPU利用率也无法判断忙于有效矩阵乘法还是频繁数据移动。先定位瓶颈，再选择融合、预取、batch或并行的调整。

## FlashAttention：改变数据搬运，不改变目标

稠密注意力输出是softmax(QKᵀ/√d)V。朴素实现往往把T×T分数和概率写入大显存；FlashAttention把Q/K/V按块搬到更快的片上存储，在块间维护softmax统计，减少中间矩阵的全量物化与读写。它仍计算精确的稠密注意力，浮点归约顺序可能产生微小数值差异。

数学关键是稳定的在线归一化。已有块保存最大值m、指数和l和加权和值a；新块最大值m_b到来后，取m'=max(m,m_b)，把旧统计乘exp(m−m')，再加新块按m'缩放的统计，最终输出a/l。下面对一个查询验证该合并等式，未实现GPU内核、反向或完整FlashAttention。

减少HBM读写与中间内存不代表所有计算变为线性。稠密token配对仍有平方规模；长上下文任务还可能受投影、MLP和KV读取限制。阅读原文时把FLOPs、内存载荷、内存访问与真实时间分别记账，才能理解为什么有时多做少量重计算反而更快。

```python
import torch
torch.manual_seed(19)
scores = torch.randn(9, dtype=torch.float64)*3
values = torch.randn(9, 4, dtype=torch.float64)
reference = scores.softmax(0) @ values
m = torch.tensor(float('-inf'), dtype=torch.float64)
l = torch.zeros((), dtype=torch.float64)
a = torch.zeros(4, dtype=torch.float64)
for start in range(0, 9, 3):
    z, v = scores[start:start+3], values[start:start+3]
    new_m = torch.maximum(m, z.max())
    old_scale = torch.exp(m-new_m)
    e = torch.exp(z-new_m)
    l = old_scale*l + e.sum()
    a = old_scale*a + e @ v
    m = new_m
online = a/l
assert torch.allclose(reference, online, atol=1e-12)
print('online softmax max error:', float((reference-online).abs().max()))
```

## 激活重计算、卸载与缓存的不同取舍

activation checkpointing在前向少存一部分中间激活，反向时重新运行所需前向，拿计算换内存。它和“保存训练检查点到磁盘”名字相近但功能不同；前者控制单步显存，后者支持故障恢复。若重计算中有随机操作，需注意框架的RNG保持与执行一致性。

CPU或磁盘offload把状态放到更便宜的大容量存储，代价是传输与可能的等待。它可以帮助容量不足的任务运行，却不自动提高速度。冻结大部分参数能减少梯度与优化器状态，但中间激活仍可能需要用于计算适配器梯度，因此LoRA也不是训练显存只剩适配器大小。

推理时KV cache避免重复计算历史键和值，但增加长请求的常驻内存。训练的teacher forcing通常并行处理已知序列，不能把自回归生成的缓存开关直接当作节省训练显存的通用办法。将每个优化与它减少的账目对应，才有可检验的决策。

## FLOPs、时间与利用率：写清近似

对稠密Transformer，一种常用训练量级近似是C≈6NM，N为参数量，M为训练token数。常数包含前向与反向的主要矩阵计算，但忽略或粗略处理注意力随长度的额外项、嵌入、重计算与系统开销；长上下文或MoE不能不加辨别地套用总参数N。

若总设备理论算力为P FLOP/s，有效利用比例为u，时间粗估C/(Pu)。P×u应尽可能用相同配置的实测有效吞吐校准；厂商峰值不是训练任务持续吞吐。下面的数字只是情境算术，并不报告本项目运行过百万亿级计算。

固定算力预算下，增加参数会减少能消费的token数。比较候选模型时还要把数据质量、唯一文档数量与重复轮数纳入记录。把同一小语料重复一千遍不等价于获得一千倍独立信息，可能只是让模型更充分地记忆已有偏差。

```text
C ≈ 6 N M；time_seconds ≈ C/(P×u)
```

```python
C = 6e18  # illustrative FLOP budget, not a measured run
candidates = []
for N in [100_000_000, 300_000_000, 1_000_000_000]:
    tokens = C/(6*N)
    candidates.append((N, int(tokens)))
P, utilization = 100e12, 0.4  # hypothetical aggregate rate and utilization
seconds = C/(P*utilization)
assert candidates[0][1] == 10_000_000_000
print('parameter/token choices:', candidates)
print('illustrative hours:', seconds/3600)
```

## Scaling laws是实验规律，不是万能比例

算力最优研究把验证损失与参数量、训练token量联系起来，例如拟合L≈E+A/N^α+B/M^β，再在C≈6NM约束下寻找较好分配。它提醒我们：固定预算时，盲目放大模型会让数据训练不足；只增加数据而保持过小容量也可能错过收益。

这些系数来自特定模型族、数据混合与训练配方，外推必须谨慎。所谓“每参数固定若干token”不能替代自己任务的验证曲线。训练最优和全生命周期最优也不同：如果未来推理次数很多，可能愿意多训练一个较小模型，换取长期服务成本下降。

CurateMicrobiota早期更缺独立研究的可靠数据与外部验证，而不是参数数量。先用三档小容量和受控token预算观察训练/验证差距，判断是容量不足、噪声上限还是分布偏移；只有证据支持时才扩大预算。不要用通用文本的拟合规律直接推导疾病预测准确率。

## 量化、剪枝与蒸馏在链条中的位置

量化降低权重或激活的表示精度，可发生在训练后校准、量化感知训练或冻结低比特底座的适配训练中。量化载荷小不保证所有设备更快：需要对应算子、布局和反量化策略，并观察任务误差、峰值内存与延迟。D20将把QLoRA放回后训练流程。

剪枝删除权重或结构。非结构化权重置零若仍保存在稠密张量并由稠密内核执行，文件和乘法次数未必下降；删除头、通道或层的结构化剪枝更容易改变实际形状，但需要重新评价与可能的修复训练。不能只报告“稀疏率90%”就声称速度提升十倍。

蒸馏训练学生匹配教师输出分布、表示或生成样例，可与原始标签组合。经典软目标思路来自https://arxiv.org/abs/1503.02531；学生也可能继承教师的错误与偏差。三个方向都需在固定外部测试上同时比较性能与资源，才能决定压缩是否适合科学任务。

## 论文导读

### ZeRO: Memory Optimizations Toward Training Trillion Parameter Models (2020)

https://arxiv.org/abs/1910.02054

沿状态冗余理解分片，而不是把多个stage当作神秘配置编号。

- 读第3节，分别列出模型状态与剩余内存。
- 读第5节三个分片阶段，画出某个参数及其优化器状态分别由哪个rank持有。

**阅读问题：** 参数完全分片后，为何峰值不一定等于总状态除设备数？

**参考思路：** 执行层计算时需要聚合参数，另外还有激活、通信与预取缓冲以及分配器开销。理想常驻分片量只是其中一项。

### FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness (2022)

https://arxiv.org/abs/2205.14135

学习在不改变注意力目标的条件下减少内存访问。

- 读第3.1节与Algorithm 1，对照本课单查询在线softmax的m、l、a统计。
- 读Theorem 1和图2，分别记录FLOPs、额外内存、HBM访问与耗时的区别。

**阅读问题：** 为什么仍有平方数量的token配对，却可以降低内存并加速？

**参考思路：** 不把完整分数和概率矩阵反复写回大显存，并用分块和重计算调整数据流。速度来自实现与内存访问改进，不要求把所有配对删除。

### Training Compute-Optimal Large Language Models (2022)

https://arxiv.org/abs/2203.15556

把模型容量与训练数据作为同一预算下的两个变量。

- 读第3节三种估计方法，特别是固定FLOPs的比较。
- 读第3.3节损失拟合与附录FLOPs估算，对照C≈6NM的近似条件。

**阅读问题：** 为何不能把论文的参数/token比例直接用于所有微生物数据？

**参考思路：** 数据分布、目标、架构、可获得独立样本和训练配方都不同；拟合规律只在相关实验范围内提供证据，需要本地验证曲线校准。

## 练习与完整参考解答

### 练习 1. 32层、16个KV头、每头128维、总长度4096、batch为2、每元素2字节，KV载荷多少GiB？若查询头为32是否影响这项计算？

提示：两份缓存分别为K和V。

参考解答：2×32×2×4096×16×128×2=2147483648字节，即2GiB。查询头数不直接出现在KV载荷公式中；GQA共享键值，而打分计算仍与查询头数有关。

### 练习 2. 7B模型按16字节/参数账本使用八路完全分片，理想每rank常驻状态是多少？为什么不能据此保证能运行？

提示：分别计算总量和峰值额外部分。

参考解答：理想常驻为16×7e9/8=14e9字节，约13.04GiB。还要容纳计算时聚合的权重、激活、logits、通信缓冲、工作区及碎片。具体分组与预取可能同时保留多个模块，所以需要实测峰值与余量。

### 练习 3. 两个rank分别有2和8个有效目标，局部平均loss为1和3。DDP直接平均局部均值会得到什么？应怎样加权？

提示：全局目标有10个有效位置，R=2。

参考解答：直接平均得到2，正确全局平均为(2×1+8×3)/10=2.6。若DDP平均梯度，可让每个rank使用R×S_r/10；对局部均值而言权重分别为2×2/10与2×8/10，随后rank平均便恢复正确全局目标。

### 练习 4. 某优化把权重90%置零，但延迟没有改善。给出两个合理解释和下一项验证。

提示：区分数值零与存储/算子的结构变化。

参考解答：第一，稠密张量仍分配原大小并调用稠密乘法，零值没有减少工作。第二，瓶颈可能在KV读取或其他未剪枝模块。应检查真实张量形状、稀疏存储和内核路径，并用分阶段profile测量瓶颈；不要只比较非零元素数。

## 验收自测

### 1. DDP主要怎样分摊训练？

A. 把每个权重自动切成所有rank份
B. 各rank处理不同数据并同步梯度
C. 只分片KV不训练
D. 每rank使用完全无关的优化器目标

参考答案：B。标准数据并行复制模型，分摊样本；输入分片仍需要合适的数据管道。

### 2. FlashAttention的关键机制是什么？

A. 删除所有远距离注意力
B. 只保留top-1 token
C. 改变CE标签
D. 分块计算与在线归一化减少内存读写

参考答案：D。它保持稠密注意力计算对象，优化IO与中间存储。

### 3. 理想4bit权重载荷是否等于最终峰值显存？

A. 不是，还要计元数据、缓存与工作区等
B. 是，所有框架都精确相同
C. 只有训练时相同
D. 只需再加一个字节

参考答案：A。载荷是最基础的一项，实际模型运行需要额外状态和临时空间。

### 4. 固定C≈6NM时把参数N翻倍，会怎样影响允许的训练token M？

A. 必然翻四倍
B. 必然不变
C. 近似减半
D. 变为零

参考答案：C。在该简化预算内N与M乘积固定；实际配置还要校正其他计算项。

### 5. 蒸馏最恰当的描述是？

A. 随机删除教师一半参数
B. 训练学生匹配教师信号并评价效果
C. 保证学生没有教师错误
D. 等同于把float32改成int4

参考答案：B。蒸馏是训练过程，教师信号可为概率、表示或样例；它不自动消除偏差。
