## 证据检索要解决的具体问题

当你问“这个微生物模型是否经过跨研究验证”时，答案需要一个当前可查的来源，而不只是语言模型参数中的模糊记忆。检索模块先寻找有关材料，回答模块再根据这些材料组织输出。检索增强生成的重点在于为回答提供可更新、可追溯的外部条件。它能够帮助研究者找到依据，但不能保证检索结果完整，也不能保证生成器忠实阅读。每个环节都需要单独检验。

今天的 CurateMicrobiota 提供本地证据检索与来源展示基线，能够在没有外部模型服务的条件下练习问题、来源和证据之间的关系。课程整理的来源卡片是教学摘要，不是自动下载的论文全文。若尚未接入生成器，应将结果称作检索证据或模板式摘要，不能把它包装成已经运行的生成式大模型。未来接入本地或远程生成器后，仍保留相同的证据接口与评价集合，这样可以判断改进究竟发生在检索还是生成。

## 先定义一个可追溯的证据单元

每个证据单元至少包含稳定ID、标题、来源URL、发表或更新时间、材料类型、内容以及内容在来源中的位置。材料类型可以是原始研究、官方方法文档、综述或课程整理卡片。相同内容的不同版本要记录关联，防止同一研究被当作多项独立证据。微生物研究还应保留样本类型、物种或功能层级、数据处理版本、研究设计和结局定义，方便判断一个结论的适用范围。

对卡片进行核验时，把每一句事实归回具体来源。官方软件文档能证明某个参数怎样工作，不能自动证明该软件对疾病具有预测效力；论文能报告作者的数据结果，也不等于结果已经在你的队列复制。一个关于属水平模型的段落，不能不经转换就用于证明物种级模型具有同样性能。今天手工整理三张卡片：数据资源、方法研究、评价方法。每张卡片写出能支持的命题与明确不能支持的命题，训练证据边界意识。

## 分块：保证事实和限定条件留在一起

文档分块是为检索建立粒度，不是机械地按固定字符数剪开。过短的片段可能只剩一个结果而丢掉样本、否定词、统计条件或研究限制；过长的片段又会引入大量无关内容，降低匹配精度并占用上下文。起步可以按标题和自然段拆分，再限制每块长度，并保留适度重叠。长度阈值需要在开发问题集上比较，而不能先看最终测试答案再挑选。

微生物论文中的表格、图注和方法信息尤其容易被切散。若结论写在结果段，样本范围写在图注，你需要把关联信息作为元数据或相邻块一起返回。数值不能离开单位与分母，例如“准确率90%”至少要知道对应多少样本、什么划分、怎样定义类别。PDF解析也会把列顺序、上标和特殊符号弄错，所以索引前应抽查原文。下面短代码只是分块边界练习，不是通用PDF解析器；请尝试不同块长，观察限定条件是否完整。

```python
def chunks(text, size=80, overlap=20):
    if not 0 <= overlap < size:
        raise ValueError("overlap must be smaller than size")
    step = size - overlap
    return [{"start": i, "end": min(i + size, len(text)), "text": text[i:i+size]}
            for i in range(0, len(text), step)]
text = "研究仅纳入成年粪便样本。模型在同一研究内交叉验证；尚未在独立研究验证。" * 3
for row in chunks(text):
    print(row)
assert all(row["text"] == text[row["start"]:row["end"]] for row in chunks(text))
```

## 先做词项检索，再理解向量检索

词项检索把问题与文本中的词或字符联系起来，适合精确术语、物种名、DOI和软件参数。向量检索将问题和片段编码成稠密表示，按相似性寻找语义接近的内容，但相似不意味着事实支持。同义表达可能改善召回，物种名拼写、近缘分类单元和数字条件也可能被混淆。一个可用系统往往需要比较词项、向量和混合策略，而不是假设向量方法必然更好。

对当前小型课程证据库，先观察本地实现实际使用的匹配规则。用三个版本提问：中文描述、英文术语、带资源名的精确问题。记录返回ID和顺序，解释为什么某种写法没有找到内容。新增向量检索时，应记录嵌入模型及版本、归一化方法、相似度函数与索引配置。若更换嵌入模型，需要重新建立相应索引；把不同模型的向量直接混在一起比较通常没有明确意义。检索器训练也不能使用最终测试问题的答案作为反馈。

## 重排与上下文：更多材料未必更好

召回阶段追求尽量找到相关候选，重排阶段再综合问题与片段判断优先级。一个简单策略先取较多候选，再去除重复、保留方法或原始结果来源，并筛选与问题条件匹配的材料。不要把同一篇论文的相似片段堆成看似丰富的多来源支持。对于冲突证据，应保留差异而不是仅选与预期结论一致的一方；疾病、样本类型、处理流程不同，可能正是冲突的原因。

语言模型能够接收很长上下文，并不等于对每个位置都利用得同样充分。加入生成器后，可以把同一证据分别放在上下文开头、中间和末尾，比较回答是否保留限定条件。还应固定总长度，防止将位置实验与长度实验混在一起。课程的检索基线不宣称完成重排大模型或长上下文实验；本节给出的是下一步应怎样设计比较。当前先实现人工去重和证据排序表，练习在有限阅读预算中保留最关键、最独立的证据。

## 引用核验要检查四层关系

第一层是来源存在：URL或DOI能否指向真实材料。第二层是定位正确：所引段落是否真的出现在该来源。第三层是命题支持：段落是否支持答案附近的具体说法，而不是只与主题相关。第四层是覆盖完整：答案中需要依据的关键断言是否都有证据。引用数量越多不一定越可靠，同一个来源支持多个命题时需要逐项确认，不能用一串链接替代核验。

为研究助手设计一张逐句表：答案断言、证据ID、对应原文、适用范围、核验结论。只写“相关”不足以判通过。例如来源报告某模型在特定外部队列取得结果，答案扩成“能泛化到所有精神疾病”，即使链接真实也不成立。若来源只是一张课程摘要卡，进一步研究时应打开原始论文或官方文档确认。生成器不得创造不存在的证据ID；输出中出现库外ID时，系统应标为错误而不是自动生成一个看起来合理的链接。

## 把检索质量与回答质量分开计分

检索层可以用Recall@k、Precision@k和MRR等指标。Recall@k关注人工相关证据中有多少进入前k；本课Precision@k固定用k作为分母，少返回的槽位也不记命中。单题的倒数排名RR关注第一条相关结果的位置，多题RR平均才得到MRR；代码报告的是截断到k的RR。计算前必须定义相关性：询问参数行为时，直接官方说明通常比泛泛介绍更相关。不存在答案的问题不应强行安排相关文档，应另外评价错误召回与缺证处理。

回答层另外评估事实正确、引用支持、引用覆盖、结构格式和是否适当说明缺证。不能拿检索召回率当作问答准确率，也不能用模型自评替代所有人工核验。下面用一个小列表演示检索指标的分母，其中相关集合由人事先确定，返回列表没有重复ID。正式实验要在多个问题上计算并报告分布，保留零相关或无答案问题的处理规则。如果两个人对相关证据不一致，先讨论准则，再固定标签。

```python
def retrieval_scores(ranked, relevant, k):
    if k < 1:
        raise ValueError("k must be positive")
    if len(set(ranked)) != len(ranked):
        raise ValueError("duplicate evidence IDs")
    relevant = set(relevant)
    top = ranked[:k]
    hits = [x in relevant for x in top]
    precision = sum(hits) / k
    recall = sum(hits) / len(relevant) if relevant else None
    rr = next((1.0/(i+1) for i, x in enumerate(top) if x in relevant), 0.0)
    return {"precision_at_k": precision, "recall_at_k": recall, "reciprocal_rank_at_k": rr}
print(retrieval_scores(["A", "C", "B"], {"B", "C", "D"}, 3))
assert retrieval_scores(["A"], {"A"}, 3)["precision_at_k"] == 1/3
# 完整列表示例：precision=2/3，recall=2/3，RR@3=1/2；跨题平均RR得到MRR。
```

## 结构化输出与工具调用的边界

研究助手的结构化输出应有明确模式，例如问题、结论、证据列表、缺失信息和下一步核验。语法校验检查字段类型与必填项，语义校验检查证据ID属于检索结果、数值和单位一致、结论强度与研究设计匹配。不要把“模型输出JSON”理解为“结果可以直接写入正式数据库”。写入前需要独立的核验状态，遇到冲突时保留来源而不是覆盖掉另一份记录。

工具调用只是把明确参数传给一个受限功能，例如检索证据、读取评估报告或计算指标。工具返回的内容仍是数据，不是可以改写系统任务的命令。文献中若出现“忽略原规则”或任意脚本指令，应按普通文本处理。课程的本地证据查询不需要外部账户或秘密凭证；未来接入远程模型时，密钥不能放到网页前端、公开代码或训练样本中。工具执行与模型生成分离，有助于把可验证计算留给确定性代码。

**参考思路：** 不一定。外部证据可以独立更新，但索引和版本需要同步管理。

https://arxiv.org/abs/2305.14627

- 为自己的来源卡片设计命题支持与引用覆盖标注。

**参考思路：** 不能。尤其是科学范围、否定条件和研究设计，需要抽样人工核验。

## 练习与完整参考解答

### 练习 1. 相关证据为{A,B,C,D}，返回前3项为[B,E,A]，Precision@3、Recall@3和MRR@3是多少？

提示：分别使用返回数量、相关证据总数和第一条相关位置。

参考解答：Precision@3=2/3；Recall@3=2/4=1/2；第一条结果B相关，所以MRR@3=1。高MRR只说明首条相关出现得早，不说明所有相关材料都被找齐。

### 练习 2. 一段材料写“在同一队列内交叉验证表现良好，但缺少独立队列验证”。答案写“已证实跨队列泛化”。错误在哪里？

提示：检查限定条件与结论方向。

参考解答：答案删除了关键限制，并把尚未完成的验证改成已完成。即使引用该段真实存在，也属于命题不被支持。应改为同队列结果，并明确外部验证缺失。

### 练习 3. 向量检索总把Bacteroides和Bifidobacterium的文献混排，如何设计修复实验？

提示：保留固定问题集，增加精确实体约束。

参考解答：先记录实体混淆的基线，再比较精确名称词项加权、实体过滤或混合检索。用固定开发集选择策略，在未用于调整的问题集评价，检查提升是否以漏检同义名称为代价。

### 练习 4. 网页展示了一段优美解释，但Python模块只返回证据列表。应该怎样说明产品功能？

提示：区分展示内容、模板和运行时生成。

参考解答：明确网页解释是固定课程文本或模板，运行模块负责检索来源。只有真正接入并执行生成器的部分才称生成式回答，其评价也需要单独报告。

## 验收自测

### 1. RAG中检索结果与答案的关系应是？

A. 只要有检索就不会出错
B. 检索排序就是因果证据强度
C. 可省略来源版本
D. 为生成提供可追溯条件，仍需核验

参考答案：D。外部材料改善可追溯性，但不自动保证相关、完整或被正确使用。

### 2. Recall@k的分母通常是？

A. 答案字数
B. 被返回的所有网页字数
C. 预先标注的相关证据总数
D. 模型参数量

参考答案：C。召回率衡量相关证据被找回的比例，相关集合需要事先定义。

### 3. 同一研究的五个重复片段应怎样处理？

A. 全部作为外部验证
B. 识别同源并去重，不当成五项独立证据
C. 自动增加结论可信度五倍
D. 随机改成五个DOI

参考答案：B。独立证据数量不能由重复切片制造。

### 4. 结构化输出通过JSON解析后，还需要什么？

A. 检查字段语义、证据支持和引用ID
B. 无需任何检查
C. 自动写入正式数据库
D. 删除所有缺失值

参考答案：A。语法合法只是第一层，科学内容必须另外验证。

### 5. 问题在证据库中没有答案时，正确做法是？

A. 生成最可能的事实并编链接
B. 把主题相近段落视作直接证明
C. 重复检索直到出现想要的答案
D. 说明缺少支持，保留待核验信息

参考答案：D。缺证处理是研究助手的重要能力，不能用表面完整替代真实性。
