## 项目名称与真实数据资源分开记录

本课程使用 CurateMicrobiota 作为贯穿项目名称，真实数据接口连接 curatedMetagenomicData。后者是可核验的官方资源，提供经过统一处理的宏基因组丰度与功能数据，以及人工整理的样本元数据；它不是本课程新建的数据库，也不是一套已训练好的语言模型。课程的演示数据则由代码生成，用于验证输入格式、训练流程和研究划分。三者在网页、文件名和结果报告中都要保持清楚。

真实资源中的物种相对丰度和功能潜力来自特定版本的分析流程。不同版本的物种名称、数据库与功能注释可能变化，因此不能只写“使用公开微生物数据”就认为可复现。今天先理解数据代表什么、样本怎样对应、研究怎样划分，再进入模型。一个结构优美的网络若读取了错位的样本标签，或者把百分数当成比例，其训练曲线仍可能看似正常；数据契约就是让这种错误尽早暴露。

## 四份文件建立最小数据契约

课程工程读取 abundance.csv、metadata.csv、split.json，并用来源说明记录数据出处。丰度表一行一个样本，第一列为sample_id，后续列是唯一且非空的物种标识。元数据至少包含sample_id、study、subject_id与label。label在本工程中使用0、1或空值：空值可用于未标注预训练样本，不能悄悄解释为健康。split.json把每个研究完整分配到train、val或test，不能重复，也不能遗漏。

输入丰度采用比例而不是百分数或测序计数，单行总和应为正并处于合理范围。保留部分物种后总和可能小于一，这并不自动构成错误，但必须知道保留了多少组成质量。特征名称缺失与测量为零不同：前者可能意味着检测面板或版本不匹配，不能默认补零。元数据读入后按样本ID精确对齐，不能依赖文件排序。任何重复样本ID、重复物种列、负数、非有限值或缺失研究标识都应明确报错。

| 文件 | 最小字段 | 必须核验的关系 |
| --- | --- | --- |
| abundance.csv | sample_id + taxa | 唯一ID、非负有限比例、物种列唯一 |
| metadata.csv | sample_id, study, subject_id, label | 与丰度表样本集合完全相等 |
| split.json | train, val, test | 每个研究恰好属于一组 |
| data_provenance.json | 来源、单位、版本、校验值 | 结果能够追溯到本次输入 |

## 通过官方接口选择与导出真实样本

先安装与本机R版本对应的Bioconductor环境，再安装curatedMetagenomicData。包内sampleMetadata可用于检查study_name、sample_id、body_site等字段。先查看研究与条件分布，再选择任务；不要假定某个标签值在所有版本中含义相同。官方returnSamples函数接受筛选后的元数据和数据类型，返回带样本信息的实验对象。对于起步项目，先选粪便相对丰度与少量研究，避免直接合并体量更大的基因家族矩阵。

下面是独立的接口查看示例。它列出可用研究，不代表这些研究已经被本课程下载或训练。实际导出使用工程中的scripts/export_cmd.R，按文件说明核对研究、标签映射和输出位置。官方counts=TRUE会把相对丰度乘读深并取整，因此本课程坚持counts=FALSE，不能将换算值称为原始计数。还应知道，选择少量样本仍可能下载整个对应研究资源；这会影响网络和磁盘预算，下载清单要随实验保存。

对接真实资源时还要检查两个接口细节。官方returnSamples通常将sample_id转为colData行名，不能假设它仍是普通列；按丰度矩阵列名对齐，并核对没有遗漏或新增样本。counts=FALSE也不等于数值必为0–1：已核验的cMD 3源码与维护者分析使用百分数，示例配置因此设为percent并显式除以100。请阅读工程REAL_DATA.md中的固定源码与分析链接，按实际资源核验单位，不凭矩阵大小自动猜测。

## 标签必须来自预先写下的任务定义

如果任务是区分某一疾病与健康对照，应明确疾病定义、排除条件和健康标签的原始取值。把“不是该疾病”的所有样本都设为健康，会把其他疾病、未知状态和治疗后样本混进对照组。标签还可能受到采样时期、部位、年龄、用药和纳入标准影响。今天建立一张映射表，包含原字段、原值、目标标签、纳入或排除理由；映射表在看模型结果之前固定。

跨研究的同名标签也可能代表不同诊断或严重程度。遇到这种情况，先检查原论文和元数据说明，再决定是否合并。缺失标签可用于允许的无标签预训练部分，但下游评价只使用标签明确的样本，并报告数量。临床变量可以构成单独的基线或用于混杂分析，不能不加说明地混入微生物模型输入。选择一个简单、明确、多个研究都能支持的任务，比一开始堆砌很多含义不清的疾病类别更有助于学习可靠模型开发。

## 研究划分与受试者划分是两层约束

样本ID识别一行记录，受试者ID识别可能重复采样的人，研究ID识别采集和处理环境。随机按行划分时，同一个人的不同时间点可能同时出现在训练和测试中，模型因识别人而得到过于乐观的分数。研究外测进一步要求某个研究的全部样本留在外部；这有助于检验对不同研究环境的转移，但也可能同时改变人群、检测和标签分布，所以必须描述这些变化。

对公开数据可使用study_name与本地sample_id组合成稳定样本键，用study_name与subject_id避免不同研究重复编号造成的碰撞。不过，命名空间不能替代真实重复调查：若同一受试者被不同论文或资源重复使用，还需通过可用的原始项目与样本信息建立统一映射。subject_id缺失时应报告，不能直接把每行当作一个已证实独立的人。课程工程会检查研究分配和受试者交集，真正资料仍需在导出前完成这层数据审查。

## 组合性：相对增加不等于绝对增加

相对丰度受到总和约束。假设某样本只有两个物种，一个从10个单位增加到20个，另一个保持10个，后者的绝对数量没有变化，相对丰度却从二分之一变成三分之一。因此，模型看到相对丰度下降，不能直接解释为该物种绝对减少。CLR等对数比变换帮助表达组成中的相对关系，但需要处理零值，并且结果受所选成分集合影响。任何变换都不自动恢复没有测量的绝对微生物负荷。

本工程的微生物预训练使用逐物种log1p与训练集统计量，作为易检查的教学实现；它并不声称解决所有组合性问题。后面会把CLR加逻辑回归作为候选基线讨论，并用组合数据实验检查不同处理的敏感性；当前五模型基准使用log1p加训练内标准化。特别注意：在掩码任务中，完整样本的CLR中心包含将要遮蔽的目标，先CLR再遮蔽可能泄漏目标信息。今天先把输入单位、是否闭合、是否截取物种与保留质量写清楚，明天才能理解为什么损失函数与预处理必须共同设计。

## 零值、未测量与稀有特征分别处理

一个零可能代表真实缺失，也可能是低于检测能力；一个空白列可能表示该特征根本未测量或无法映射。它们不应该全部被同一常数替代。训练前需要区分数值零、缺失值、未知物种和低质量样本。对数变换不能直接接受零，伪计数或log1p是可用的处理选择，但其数值会影响小丰度成分。应在训练域内比较合理设置并记录，不应在测试集上挑出最有利的伪计数。

prevalence过滤的阈值、最多保留物种数和特征排序都在训练样本上拟合。验证与测试仅应用已经确定的词表和缩放量；即使过滤过程不使用疾病标签，借助测试分布选择特征仍改变了严格外测的设置。若新数据缺少训练词表中的物种列，默认应该停止并检查映射。只有明确知道它是同一检测体系中的未检出，才可讨论补零，并同时报告该假设和保留丰度质量。

## 版本、资源和许可进入实验清单

可复现的数据清单不仅写下载日期，还包括资源名称、包版本、分析流程、原研究出处、筛选条件、标签映射、导出代码版本与输出文件校验值。curatedMetagenomicData可返回不同运行日期对应的资源，默认选择行为不应被当作永久固定。第一次真实下载后，将本次资源名与实验清单一同保存，避免未来更新包后悄悄改变输入。合并资源时出现的物种丢弃或树映射警告，也应进入日志。

软件许可证与来源研究数据使用条件不是同一个问题。包的软件许可证不能被直接解释为所有样本都允许任意再次分发。课程提供导出接口，学习者从官方渠道获取资料并保留引用；如果将来发布真实子集，需要核查来源的使用条件。演示数据则有独立、明确的合成说明，不带真实个人信息。今天的目标是形成能让别人检查输入来历的最小清单，而不是为了界面漂亮省略这些关键事实。

## 用断言替代“看起来对齐了”

进入训练前执行几项有明确意义的检查：样本集合完全相同；ID不重复；研究在三组之间不相交；受试者在三组之间不相交；训练集含足够物种；分类评价中每个目标集合具有所需类别；所有比例非负有限。工程已经对基本契约设置检查，下面额外用标准库查看演示数据中的受试者交集。不要为了让程序跑通而删除报错逻辑，应先解释是哪项科学假设被违反。

最后完成一张数据去向图或表：原始研究进入哪组，哪些样本用于无标签预训练，哪些样本有下游标签，哪些变换只在训练组拟合，最终测试在什么时候打开。真实数据未下载时，这张表仍可在合成队列上练习，但报告必须保留“合成”标记。只有当你可以逐列解释输入、逐组解释样本独立性，才进入第11天的掩码模型；这会让模型失败时的排错更快，也让成功时的结论更可信。

```python
import csv, json
from pathlib import Path
p = Path("data/demo")
meta = list(csv.DictReader((p/"metadata.csv").open(encoding="utf-8")))
split = json.loads((p/"split.json").read_text(encoding="utf-8"))
subjects = {part: {r["subject_id"] for r in meta if r["study"] in studies}
            for part, studies in split.items()}
for a,b in [("train","val"),("train","test"),("val","test")]:
    assert not subjects[a] & subjects[b], (a,b)
print({part: len(ids) for part,ids in subjects.items()})
assert len(meta) == 240
assert len({r["subject_id"] for r in meta}) == 120
```

## 练习与完整参考解答

### 练习 1. 样本A有物种X=10、Y=10；样本B有X=20、Y=10。Y的相对变化能否说明它绝对减少？

提示：分别计算总量和Y的比例。

参考解答：A中Y占1/2，B中Y占1/3，但Y的绝对量都为10。相对下降不能直接解释为绝对减少，需要额外的绝对定量或明确的相对关系表述。

### 练习 2. 两个文件都是240行，但行顺序不同。为什么不能直接把第二个文件的label向量接到第一个文件后？

提示：行数相等不代表对象对应。

参考解答：标签可能分配给错误样本。必须用唯一sample_id精确连接并验证集合相同，之后按丰度表顺序重新排列元数据。

### 练习 3. 研究A、B都有subject_id=001，是否一定是同一个人？反过来不同ID是否一定是不同人？

提示：区分命名碰撞与资源重复。

参考解答：两者都不能直接断定。研究内编号可能碰撞，需命名空间；同一人的重复公开资源也可能使用不同ID，需要原始样本或项目映射审查。

### 练习 4. 先用全部数据去掉低prevalence物种，然后划分测试研究，为什么不符合严格外测？

提示：过滤虽然无标签，仍使用了测试分布。

参考解答：特征集合已经根据测试研究的出现情况改变。严格外测应先划分，再仅在训练研究估计prevalence和词表；验证测试只应用已冻结变换。

## 验收自测

### 1. 课程默认data/demo属于？

A. 已经验证的MDD队列
B. 外部临床试验
C. 带人工规律的合成教学队列
D. 真实cMD全部样本

参考答案：C。合成数据用于工程验证，不能产生真实疾病结论。

### 2. label缺失时，最合理的处理是？

A. 删掉来源记录
B. 保留未知并按任务决定是否用于无标签训练
C. 默认设为健康
D. 复制邻近样本标签

参考答案：B。未知不等于阴性或健康，监督评价需要明确标签。

### 3. 工程丰度输入使用什么单位？

A. 非负有限的相对丰度比例
B. 百分数不经转换
C. 任意测序计数
D. 物种名称的字符长度

参考答案：A。单位是数据契约的一部分，百分数或计数必须先明确转换。

### 4. 严格研究外测中，测试研究可以用于什么？

A. 预训练早停
B. 选择prevalence阈值
C. 寻找最优学习率
D. 冻结方法后的最终评价

参考答案：D。测试研究不能反馈到训练与选择过程。

### 5. 软件许可证能够自动说明什么？

A. 所有队列都无伦理限制
B. 数据已经经过临床验证
C. 该软件代码的许可条件
D. 所有原始研究数据可任意再分发

参考答案：C。软件许可与来源数据条件需分别核对。
