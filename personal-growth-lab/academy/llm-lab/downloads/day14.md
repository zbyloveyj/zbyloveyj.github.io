## 项目完成意味着能力可以被检查

到今天，你应能够把一个问题拆成数据、模型、目标、优化、推理和评价，并指出每一步实际运行的证据。CurateMicrobiota包含小型字节语言模型、答案位置监督与低秩更新实验、文献证据卡检索、菌群丰度自监督编码器以及研究和受试者隔离的评价。它们共同构成一个可以继续研究的工程原型，而不是仅靠界面呈现的概念演示。

完成十四个核心单元不意味着任何人已经掌握大模型领域的全部知识，也不意味着四万参数的丰度编码器已经成为经过广泛验证的基础模型。可检查的毕业标准是：你能解释关键公式、修改并运行小实验、发现泄漏、复算指标、诚实界定结论，并独立提出下一项有效比较。今天的交付会把这些能力落实到文件和运行结果，让别人能够从入口重做，而不必依赖你的口头说明。

## 端到端命令覆盖了哪些组件

快速流水线不是所有课程实验的自动合集。TinyGPT全量SFT、LoRA-SFT和DPO公式演示需要按第8天的独立命令执行；证据检索也有独立入口。真实cMD导出、完整留一研究外测、监督Transformer从零训练、全量菌群微调和DNA模型不由这条命令完成。验收表逐项写明完成方式和输出位置，不能用一个“运行成功”状态代表这些拓展研究都已执行。

## 从运行目录建立可复现证据链

同一个文件名不代表同一份数据，同一个模型名称也不代表同一组权重。代码版本、输入文件校验值、研究划分、训练词表、预处理参数、随机种子、检查点和输出报告需要相互对应。当前预训练manifest记录输入与预处理校验值，评价阶段会重新核查，防止训练后悄悄改标签或划分。另行记录代码提交与实际依赖版本，才能让其他人在相同条件下定位差异。

下面的短代码对快速运行的核心文件做一致性检查，并打印模型文件的校验值。它证明的是文件与记录的对应关系，并不证明所有算法正确或模型具有生物学价值。随机种子有助于复现，但不同软件版本、硬件和计算内核可能导致浮点差异。复现实验应先比较配置与数据身份，再检查允许误差内的结果；不要在环境明显不同的情况下要求每个小数都完全一致。

```python
import json
from pathlib import Path
from curatemicrobiota.common import file_sha256
root = Path("runs/demo")
report = json.loads((root / "report.json").read_text(encoding="utf-8"))
manifest = json.loads((root / "microbiome/manifest.json").read_text(encoding="utf-8"))
assert report["source_kind"] == "synthetic_teaching_fixture"
assert report["data"]["samples"] == 240
assert report["data"]["subjects"] == 120
for name, expected in manifest["data_sha256"].items():
    assert file_sha256(root / "data" / name) == expected, name
assert file_sha256(root / "microbiome/preprocessor.json") == manifest["preprocessor_sha256"]
print("Input identity checks passed")
for name in ("language/model.pt", "microbiome/encoder.pt"):
    print(name, file_sha256(root / name))
print(report["environment"])
```

## 原样保留一次已经执行的结果

课程附带的quick_report.json来自固定种子42的实际CPU快速运行，输入是二百四十条合成记录。TinyGPT有136960个参数，四十步训练后验证交叉熵从5.5804下降到3.0533，单位是每字节nats；这说明小模型优化流程能够学习教学文本的统计结构，不代表它能可靠回答科学问题。生成文本仍可能破碎，不能把一段偶然通顺的片段当成领域能力证明。

丰度编码器有40513个参数，六十步后验证掩码MSE从1.4422变成0.97176，训练均值插补为0.97331。单一外部合成研究的二十名受试者上，LR基线、随机编码器探针、预训练探针的AUROC是0.88、0.51、0.48。这是一份应当公开解释的负面迁移案例：重建目标改善并没有在该任务中转化为冻结表示收益。发布时同时记录预算、评价单位和局限，而不是只选下降曲线。

| 实测项目 | 固定quick观察 | 支持的结论 |
| --- | --- | --- |
| TinyGPT验证CE | 5.5804 → 3.0533 nats/byte | 语言训练链路可优化 |
| 丰度验证掩码MSE | 1.4422 → 0.97176；均值0.97331 | 相对均值仅约0.16%改善 |

## 模型卡要让使用者做出正确判断

Model Cards for Model Reporting提出随模型提供用途、训练与评价背景等信息的做法。对本项目，模型卡应写清输入单位、分类层级、词表规则、任务目标、参数量、训练预算、选择标准、评价单位、数据来源和结果。语言模型与丰度编码器各有用途，不能用语言损失为疾病预测背书。建议先读工程中的MODEL_CARD.md，再用自己的运行填写相应记录。

局限应具体到会改变使用判断的事实：输入是合成资料，测试只有一个研究，编码器探针尚未优于简单基线，注意力没有识别因果机制，模型不处理DNA序列，真实cMD接口尚需用户在符合数据条件下实际运行。这里不需要堆通用口号。结果较差也是模型卡内容的一部分，因为它告诉下一位研究者应从哪里开始排查，以及哪些用途还没有得到验证。

```text
模型名称与版本：CurateMicrobiota 教学编码器
输入：样本×固定分类单元的相对丰度比例
训练目标：仅遮蔽位置的标准化对数丰度MSE
选择：验证重建选编码器；验证受试者AUROC选探针C
评价：研究和受试者隔离；受试者均值概率为主
数据来源：合成教学数据；不是实际临床队列
结果：填入本次报告的三种方法，保留未获收益结果
局限：单外测研究、小样本、固定词表、未验证真实疾病效能
复现身份：代码版本、环境、输入哈希、预处理与检查点哈希
```

## 数据说明与软件许可分别记录

数据说明应让他人知道数据来自哪里、如何筛选、由什么程序生成或导出，以及字段怎样解释。当前合成数据可以随课程用于复现；接入真实cMD时需要记录资源版本、研究选择、样本清单、导出方法、物种层级、丰度单位和原始研究来源。某些元数据缺失时，记录缺失和处理规则，不要为了满足统一表格而编造受试者身份或健康标签。

软件包采用什么开源许可证，并不能替代底层研究数据的使用和再分发条件。自己的代码、第三方依赖、合成资料、真实数据和模型权重应分别说明来源与适用许可。发布真实数据前检查各资源的授权与访问条件；如果不适合重新分发，可以提供选择配置、导出脚本和校验值，让具备条件的研究者复现。不要把整个cMD资源都标成你自己的项目许可。

## 演示应展示输入到结论的完整路径

最终演示建议从一个具体问题开始：能否用没有标签的菌群丰度学习表示，并在独立研究评价其预测价值？展示数据契约和划分，再解释一个样本如何成为带身份的丰度词元、哪些位置被遮蔽、损失在哪里计算，最后展示三种方法与不确定性。语言侧另外演示答案损失和证据检索。观众应能看见每个输出来自哪个输入和哪种处理。

一张成绩图配一段漂亮文案不足以完成验收。挑一个预期行为和一个失败行为：预期行为可以是打乱输入列并同步身份后表示保持一致；失败行为可以是预训练重建改善但迁移未受益，或未知物种列导致兼容性检查。解释系统如何发现问题与下一步如何验证。这样的展示既有技术细节，也有科学判断，能够说明你具备继续开发的能力。

## 下一阶段先扩大数据覆盖与验证问题

从原型走向研究，第一阶段应接入少量经过核验的真实研究，固定目标人群、测量层级与一个明确任务。先完成样本与受试者去重、标签映射、来源追踪和质量检查，然后复现强基线。按研究留出的方案需要有足够研究支持训练、验证与外测；若多研究包含重复的人、共享样本或重新分析的同一测序数据，需要额外去重，不能只依靠不同文件名。

当数据接口和基线可靠后，再增加训练研究数量与多样性，并保留真正未参与选择的外部研究。无标签预训练也要检查与外测人群的重叠；如果使用已有基础模型却无法核实其训练来源，就在报告中说明潜在污染，不能直接宣称完全独立外测。目标不是让样本数看上去庞大，而是让额外数据覆盖能检验的新研究、任务和变化情形。

## 用学习曲线决定何时增加模型规模

扩大参数量之前，先在固定验证协议下比较预训练数据量、训练步数与下游表现。若均值插补已经接近掩码模型，而下游表示仍弱，就应该检查任务、汇聚和信息保留，而不是默认加层一定解决。若增加数据在多个研究上持续产生收益，再考虑更大隐藏维度、更长特征集合和更丰富目标。不同配置同时记录准确性、运行时间、内存和计算预算。

标准注意力的分数矩阵随特征数平方增长：特征数从四十八变为四百八十，相关分数元素数量约增加一百倍，但总训练开销还由隐藏维度、前馈层、批量和内核决定。先测量一小段训练的实际资源，再选择混合精度、梯度累积、检查点重计算或更高效结构。它们需要相应实现与数值检查，当前CPU教程没有自动提供分布式大规模训练，也不要求先购买设备才能完成学习。

```text
标准注意力分数张量约为 B × H × T × T；扩大T时需同时评估表示价值与资源成本
```

## 向基础模型发展的证据是什么

一个基础模型通常被期待能从广泛数据学习可迁移表示，并支持多个任务或环境。参数大、名字里有GPT或使用Transformer，都不能单独证明这一点。对微生物研究，可以逐步比较跨研究的表型预测、特征缺失重建、相近任务迁移和其他明确用途，始终保留强基线与对照。每一种新增任务都要说明标签质量、训练信息与外测单位，不能把同一数据上的多个统计图当作独立泛化证据。

MGM的原始研究提供了较大规模微生物预训练路线，可作为下一阶段的阅读与比较对象。阅读时检查它的分类层级、输入表示、数据来源、预训练目标和评估安排，再判断哪些方法适合当前任务。它不是课程集合式掩码编码器的同一个实现。论文报告的表现需要在相应数据与设计范围内理解，不能直接贴到CurateMicrobiota结果页，也不能因为模型名称相近就声称已经复现。

## 把研究路线写成可以失败的问题

一个有效问题必须允许结果不支持你的想法。问题一可以是“在相同监督预算下，增加互不重叠的预训练研究能否改善多数外测研究的冻结表示？”问题二可以是“当前平均汇聚是否丢失任务信息，替代汇聚是否在训练域选择后仍有稳定收益？”问题三可以是“加入真实功能谱后，是否超过单一丰度和简单拼接基线？”每个问题都明确对照、评价单位和何时停止。

下一阶段按依赖推进：先真实数据契约与基线，再完整多折外测与消融，然后在证据支持时扩大数据和模型，最后研究跨模态或序列表示。每阶段保留失败结果与配置，防止不断变更指标使问题失去可检验性。日历可以根据时间和资源调整，但阶段通过条件应事先规定。这里给你的是能逐步形成研究工作的路线，而不是承诺几周内必然获得微生物领域领先模型。

| 阶段 | 主要工作 | 通过条件 |
| --- | --- | --- |
| 真实数据小规模接入 | 来源、受试者、标签、单位与基线 | 数据契约可核查，基线可复算 |
| 稳健评价 | 多折研究外测、种子与预训练消融 | 所有外层折独立训练，报告差异和失败 |
| 有证据的扩大 | 数据量与计算学习曲线 | 更多资源产生可重复的任务收益 |
| 新模态或新任务 | 功能谱、临床变量或序列表征 | 对齐清楚并超过相应单模态强基线 |

## 动手实验 · 完成一次独立复现并形成可审阅发布包

### 1. 记录环境和代码版本

从项目说明确认工作目录、依赖与输入约定，记录代码版本和doctor输出。依赖版本应来自实际环境，不直接复制课程示例的版本数字。

```bash
python -m curatemicrobiota doctor
```

检查什么：解释器、依赖与训练设备可见，缺失依赖先按README安装。

### 2. 运行端到端快速验收

选择独立输出目录执行quick流水线。该模式固定为40步语言、60步菌群与100步LoRA线性演示，不能与之前100步训练结果混写。

```bash
python -m curatemicrobiota pipeline --quick --out runs/demo
```

检查什么：总报告及data、language、microbiome、lora组件输出齐全；完成状态只表示这些实际步骤完成。

### 3. 核查身份与复算结果

执行第3节校验代码，检查输入文件与manifest一致。读取测试受试者预测表复算主要指标，同时记录样本、受试者、研究三个规模。

检查什么：数据身份断言通过；指标与原始预测对应，不要求新模型获胜作为验收条件。

### 4. 补齐独立学习实验

如果已做D8，可复用其报告；否则用quick产生的language/model.pt分别运行全量与LoRA-SFT，再执行DPO公式演示。当前pipeline没有自动调用这些步骤。

```bash
python -m curatemicrobiota finetune --checkpoint runs/demo/language/model.pt --out runs/demo/sft --steps 30
python -m curatemicrobiota finetune --checkpoint runs/demo/language/model.pt --out runs/demo/sft-lora --steps 30 --lora
python -m curatemicrobiota alignment-demo --out runs/demo/alignment
```

检查什么：SFT记录答案掩码与验证损失，LoRA底座未变化；DPO报告明确是固定合成概率上的公式演示。

### 5. 演示证据检索与边界

运行一个与数据单位有关的查询，查看命中卡片及来源；再检查无证据或含糊问题，说明检索覆盖不足时不能补写事实。


## 论文导读

### Model Cards for Model Reporting (2019)

https://arxiv.org/abs/1810.03993

学习如何把模型用途、数据背景、评价过程与局限交付给使用者；该论文预印本始于2018年，会议版本为2019年。

- 先读模型卡为何需要说明用途与评价背景，而不是只有一个总分。
- 对照论文的报告框架与项目MODEL_CARD.md，找出当前结果中最影响使用判断的内容。
- 用自己的运行填写一份卡片，注意实际样本规模、失败结果与没有验证的场景。

**阅读问题：** 模型卡是否只是给性能最好的模型写宣传说明？

**参考思路：** 不是。它应帮助他人理解模型能用于什么、评价如何进行、表现与限制是什么。当前预训练未优于基线也应记录，因为它直接影响下一阶段研究与使用判断。

**阅读问题：** 写了模型卡是否就证明模型适合真实疾病任务？

**参考思路：** 不能。模型卡是透明报告工具，不能替代独立评价或相关领域证据。合成实验只能支持课程范围内的机制与工程结论，真实任务仍需要相应资料和验证。

## 练习与完整参考解答

### 练习 1. 你的模型验证掩码MSE下降了三成，但冻结表示AUROC低于LR。请写一段能放进模型卡的结论。

提示：同时说明参照、评价单位、范围与下一步，不把优化成功等同迁移成功。

参考解答：可写“在指定合成数据和研究划分下，编码器的验证重建误差较初始化下降，但在留出研究的受试者分类任务中，冻结预训练表示未优于直接丰度LR。该结果支持优化流程可运行，尚未显示本任务的迁移收益。由于训练预算、样本规模与外测研究有限，下一步将比较重建均值基线、汇聚策略和更多独立研究，不将该结果解释为预训练普遍有效或无效。”

### 练习 2. 同学复制了你的随机种子，却无法完全复现每个小数。你应该先检查哪些证据？

提示：种子之外还有数据身份、配置与数值环境。

参考解答：依次核对代码版本、输入与split校验值、预处理与词表、检查点选择、训练步数和超参数，再比较Python、数值库、PyTorch版本以及硬件和内核。先判断是否在复现同一个实验，再按合理浮点容差检查结果。不能仅凭种子一致就断定不同输出必然是错误。

### 练习 3. 为了发布真实数据项目，你发现软件包使用开源许可证。能否将全部来源研究数据和模型权重统一改成该许可？

提示：软件、数据与派生权重的授权并不是同一对象。

参考解答：不能。应逐项核查自己的代码、依赖、底层研究数据和权重的来源与适用条件。软件包许可证不自动覆盖所有研究数据或其再分发。必要时发布选择配置、导出脚本、版本与校验值，并让具备相应访问条件的研究者获取资料，而不是自行替换原有授权。

### 练习 4. 提出一项能检验“更大的微生物模型更有用”的实验，而不预设模型一定获胜。

提示：固定问题与外测协议，控制计算和监督预算。

参考解答：先固定任务、训练域内选择与多个外层研究，比较小、中两种容量，在相同预训练数据和明确预算下运行多个种子。每折重新拟合预处理和预训练，比较强LR及随机/预训练表示，报告受试者指标、研究间差异、运行成本与失败。若扩大模型没有稳定收益或成本过高，就不支持当前设置下继续扩大；再检验数据量或目标是否成为限制。

## 验收自测

### 1. 快速流水线运行成功最直接支持什么？

A. 完整多折LOSO和DNA模型都已经训练
B. 预训练探针必须优于所有基线
C. 其中实际实现的步骤可按当前配置端到端执行
D. 模型已经通过真实临床验证

参考答案：C。运行状态只覆盖命令实际执行的组件；科学收益与其他拓展任务需要各自证据。

### 2. 下列哪项最应保留在最终模型卡中？

A. 把合成数据写成公开真实队列
B. 预训练探针未优于LR及对应数据范围
C. 只保留最漂亮的训练曲线
D. 删除所有低于随机的测试结果

参考答案：B。负面结果和适用范围直接影响使用判断，是透明报告的重要组成。

### 3. 当模型规模扩大十倍时，哪种做法最合理？

A. 用固定评价与资源记录检验新增容量是否带来收益
B. 自动把模型名称改成基础模型并发布高效能结论
C. 取消简单基线以免结果不够突出
D. 反复改测试集直到新模型获胜

参考答案：A。模型规模本身不是收益证据，应有同协议对照、数据身份与计算成本记录。

### 4. 模型文件哈希一致能够证明什么？

A. 模型已经学习了正确因果机制
B. 训练数据没有任何偏差
C. 模型适用于所有人群
D. 比较的文件内容身份一致

参考答案：D。哈希用于文件身份核对；算法有效性、数据质量与泛化能力需要其他验证。

### 5. 下一阶段最先需要完成哪项工作？

A. 把已有论文最高分写进结果页
B. 先做跨模态模型再补样本对应关系
C. 定义真实数据任务、来源与划分，并复现适当强基线
D. 先购买最大显存设备再考虑数据

参考答案：C。明确数据、任务和对照是判断新模型是否有用的基础，后续规模和模态扩展应据此推进。
