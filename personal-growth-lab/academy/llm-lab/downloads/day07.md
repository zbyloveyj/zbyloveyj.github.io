## 困惑度是怎样从损失得到的

若交叉熵使用自然对数且按有效token平均，困惑度PPL=exp(loss)。例如loss=ln4时，困惑度为4，可以把它理解为在该评价条件下平均预测不确定性的一个尺度。它不是“每次一定有四个候选”，也不是正确率，不能用1/PPL直接当作模型答题准确率。

PPL的单位依附tokenization。相同文本用字节、字符或子词切分，平均token损失定义不同，数值不能直接横向排名。比较两个模型至少固定语料、清洗、tokenizer、上下文处理和评分方法。跨编码比较可设计按字节等共同单位计算的度量，但必须实际实现一致评分。

评价长文本时，是否重叠窗口、每个token计分几次、窗口边界能看到多少上下文，都会改变结果。工程目前报告固定采样验证窗口的估计，用于教学模型选择。不要把这个估计直接标成完整独立语料上的最终语言建模基准。

```text
PPL=exp(平均负对数概率)，仅在相同token与评价条件下直接比较
```

```python
import math
loss = math.log(4)
assert abs(math.exp(loss) - 4) < 1e-12
print(math.exp(3.053329646587372))  # about 21.18577
```

## 从最后一个位置取得下一token分布

训练输出[B,T,V]包含每个位置的候选分数；生成下一token只需要当前序列最后一个位置的logits，即logits[:,-1,:]。选出下一个token后把它拼到输入尾部，再重复。每次新增内容都会成为下一步上下文，生成可以因此逐渐偏离原提示。

贪心解码每次取最高分候选，过程简单、容易重复，但不保证整段文本概率最大，也不保证自然或正确。逐步最高概率路径不一定是序列整体最优，更不等于语义最优。Beam search等方法维护多个候选路径，但开放式文本生成也可能出现重复与单调。

本课先比较固定模型和固定提示，改变采样策略的效果。若同时改模型权重、提示和随机种子，就难以知道变化来自哪里。生成实验也要像训练实验一样控制条件，保存原始输出，不能只展示最好的一次。

## Temperature 改变分布，不增加知识

对logits除以正温度τ，再softmax。τ小于1时分数差异被放大，分布通常更尖；τ大于1时差异被压小，分布通常更平。温度影响采样的不确定性，不会向模型加入新事实，也不能修复错误训练数据或缺失证据。

τ趋近零时，概率集中到最大分数候选；但直接令τ=0会除零，因此工程要求温度严格为正。若要确定贪心，单独使用argmax更清楚。工程top-k阈值采样在k=1且最大值无并列时等价于选最大项，若并列会保留并列项，仍可能采样。

下面给定同一组三个logits，比较三个温度。你应预测高温时低分候选概率增加，再运行核对。请把“更随机”“更自然”“更正确”分开记录；这些不是同一个评价维度。

```python
import torch
logits = torch.tensor([2.0, 1.0, 0.0])
for temperature in [0.5, 1.0, 2.0]:
    p = torch.softmax(logits / temperature, dim=-1)
    print(temperature, p.tolist(), float(-(p * p.log()).sum()))
```

## Top-k 与 top-p 分别截断什么

Top-k按分数保留最高的一组候选，再在保留集合重新归一化采样。k小会限制选择，k大更接近原分布；不同位置的概率形状不一样，固定k可能在某些位置保留太多低可信尾部，也可能在另一些位置过度限制合理选择。工程使用分数阈值实现，同分边界会一并保留。

Top-p也叫nucleus sampling，按概率从高到低排序，保留累计概率首次达到阈值p所需的最小前缀，再归一化采样。它每个位置保留的token数可以不同。达到阈值的那个候选也要保留，否则累计质量可能不足。这里p是累计概率阈值，不是“保留前p比例的词表”。

当前生成CLI主线提供temperature和top-k；下面的top-p是独立扩展练习，不把不存在的--top-p参数写入命令。将它接入工程前，应与现有采样测试一起检查合法范围、至少保留一个候选和概率归一化。

```python
import torch
def nucleus_probs(logits, p=0.9):
    if not 0 < p <= 1:
        raise ValueError('p must be in (0, 1]')
    sorted_logits, order = logits.sort(descending=True)
    probs = sorted_logits.softmax(dim=-1)
    remove = probs.cumsum(dim=-1) > p
    remove[1:] = remove[:-1].clone()
    remove[0] = False
    kept = sorted_logits.masked_fill(remove, float('-inf')).softmax(dim=-1)
    result = torch.zeros_like(kept).scatter(0, order, kept)
    return result
p = nucleus_probs(torch.tensor([0.4, 0.3, 0.2, 0.1]).log(), 0.65)
assert torch.allclose(p, torch.tensor([4/7, 3/7, 0., 0.]))
print(p)
```

## 上下文裁剪与缓存，影响什么

模型只接受不超过context的位置数。当前生成实现每一步取最近64个token作为输入，重新计算窗口内全部表示；更早内容从输入中退出，因此不能期待模型无限记住开头。若提示中重要限定早已被裁掉，后续生成不再直接看到它，这是一种明确的上下文边界。

KV缓存保存先前位置的键和值，减少自回归推理中重复计算，但它不会自动扩大模型学过的上下文，也不是持久知识库。缓存是否正确还涉及位置编码、窗口策略和批次管理。本工程没有实现KV缓存，代码的重点是让逐步生成完全可见。

长上下文、外部检索和持久记录解决不同问题：长上下文让更多信息同时进入一次前向；检索决定哪些外部材料进入；持久记录保存跨会话的数据。设计微生物助手时可以组合这些能力，但仍要单独检查召回、引用和信息是否超出模型可见范围。

## 字节模型生成的特殊问题

UTF-8字节token保证原始有效文本可以编码和还原，但模型采样的是任意字节序列，未必始终满足UTF-8编码规则。工程decode使用errors='replace'，遇到非法或不完整序列会出现替代字符。这个字符是解码处理结果，不表示词表中有一个掌握了特殊语义的未知词。

英文教学短文以单字节字符为主，早期生成更容易出现单词碎片和无意义拼接。中文或其他多字节文字需要模型学习更长的字节组合，小数据下尤其困难。生成80个byte token并不一定是80个可见字符，报告长度时要区分两者。

不要为了让演示好看，把模型输出偷偷换成预写回答。可以同时展示原始字节、解码文本与失败说明，指出未来改进可来自更合适的tokenizer、更充分语料和训练预算。真实展示局限，比把一个教学模型包装成科学专家更能证明你理解了它。

## 怎样比较采样，不挑最好的一次

固定检查点、提示、最大新增token数，建立三组条件，例如温度0.5/0.8/1.2且top-k固定40；再固定温度0.8，比较k=1/10/40。每组使用事先指定的多个seed，保留全部输出，观察重复、可读性、提示保持和无依据事实。小模型可能三组都不理想，这也是结果。

评价记录应同时有自动统计和人工观察。重复片段比例、非法字节替代字符数量或长度只是局部指标；低重复也可能来自完全随机字符，不能单独代表质量。科学事实问题需要证据标注与正确性评价，不能用文本流畅度替代。

若采用人工评分，提前写清规则：什么算偏离提示、什么算凭空编造来源、无法判断的答案如何处理。即便课程只做个人练习，这种预先定义也能减少挑选偏好。后续检索模块将使用可检查证据，而不是让TinyGPT承担知识正确性。

## 损失下降与任务能力之间，还缺哪些证据

语言损失评价模型预测语料的能力，特定任务还要单独检验。指令遵循需要输入输出任务测试，结构化提取需要字段级指标，检索需要相关证据召回和排序评价，科学回答需要来源支持与事实核对。一个总loss不能替代这些不同层面的测量。

训练资料与评价资料相关时，表现可能受记忆影响。对于文献助手，同一论文不同摘要版本、综述对原研究的重复描述及后续引用都可能让评价变容易；对于菌群模型，同一受试者和研究来源也产生类似问题。形式不同，核心都是独立信息单位与允许数据边界。

第一阶段的合格证据是：代码可运行、目标正确、因果测试通过、训练和验证分开、损失与生成过程能解释。它不包括“已经是微生物基础模型”这一结论。后面的课程会增加微生物数据接口、掩码表征和跨研究验证，让目标逐步变得科学具体。

## 练习与完整参考解答

### 练习 1. 模型A按byte计算PPL=20，模型B按BPE计算PPL=10，可直接说B好一倍吗？

提示：比较token单位。

参考解答：不能。编码单位、评价语料与上下文条件不同，需要统一评分定义。

### 练习 2. 概率[0.5,0.25,0.15,0.1]，top-p=0.8保留几项？

提示：保留首次达到阈值的候选。

参考解答：前三项累计0.9，前两项仅0.75。保留三项后重新归一化。

### 练习 3. 温度变高后文本更流畅，就能说明模型知识增加吗？

提示：分清分布、采样和参数。

参考解答：不能。参数未改变，采样改变可能改善或恶化观感，知识与事实能力仍需任务评价。

### 练习 4. 生成中文出现替代字符可能有什么原因？

提示：考虑字节组合。

参考解答：模型可能生成非法或不完整UTF-8序列，解码用替代字符展示；检查原始字节和tokenizer，不能当成知识回答。

## 验收自测

### 1. 自然对数交叉熵对应PPL怎样算？

A. loss²
B. 1/loss
C. exp(loss)
D. log(loss)

参考答案：C。指数与对数互逆，但必须注明token单位。

### 2. 生成下一token用哪一处logits？

A. 第一batch第一位置
B. 当前序列最后位置
C. 所有位置直接平均
D. 训练目标本身

参考答案：B。取最后位置的候选分布，再追加新token。

### 3. top-p=0.9的意思是？

A. 保留90%词表
B. 概率最高的9个
C. 累计质量达到0.9的候选前缀
D. 温度0.9
