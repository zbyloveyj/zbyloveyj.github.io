## 这 14 个单元，最终让你能解释什么

这门课沿着一个问题推进：怎样把“读懂模型代码”变成“自己能设计并检验一个微生物模型”？前七个单元完成一个小型自回归语言模型，后七个单元把表征学习迁移到菌群丰度表，并加入基线、跨研究验证、参数高效适配与证据检索。你将亲手看到输入如何变成张量、注意力如何混合信息、梯度如何修改参数，以及模型为什么可能记住错误的线索。

这里的“14 天”是十四个连续学习单元。建议每单元先做 150 分钟核心任务，再用 45 分钟完成扩展阅读；时间不足时可拆成 28 天。完成标准是能够解释自己的实现、复现实验并判断结论强弱，不能用日历天数保证掌握全部前沿技术。第一次运行尤其不追求语言流畅或预测高分，先证明数据、目标、梯度和评价流程都正确。

为自己建立一个学习文件夹，每天保留一份代码变化、一张结果或日志，以及一个已经弄懂的错误。最后的成果应能回答三个问题：模型实际学的是什么；现有证据支持它完成什么任务；下一步扩展需要增加哪些数据和验证。

## CurateMicrobiota 的三种对象

本课程把 CurateMicrobiota 用作实战项目名称。对接的公开数据资源 curatedMetagenomicData 提供统一处理的宏基因组物种和功能表及元数据。菌群相对丰度是一行样本、一列物种的非负数值表，它本身不是自然语言，也不是原始 DNA 序列。因此不能因为采用 Transformer，就把三类模型混为同一种任务。

TinyGPT 接收文本 token，学习“给定前文，下一个 token 的概率”。微生物表征模型接收物种身份和丰度，学习从可见组成重建被遮蔽的信息，之后再检验学到的表征能否迁移到标签预测。证据检索模块接收问题，返回可追溯的文献片段或证据卡。三者可以连接成系统，但各自需要不同的数据、损失和评价。

生成“某菌与抑郁相关”不等于完成关联分析；分类器输出较高风险分数不等于找到了致病机制；检索到一篇研究不等于研究结论已被重复验证。项目中的界面、文件名和报告都要把模型输出的性质写清。科学上可信的项目，首先能准确描述自己做了什么。

| 模块 | 输入 | 目标 | 产物 |
| --- | --- | --- | --- |
| TinyGPT | 文本 token | 下一 token 概率 | 日志与生成样本 |
| 菌群 Transformer | 物种身份＋丰度 | 掩码重建与表征 | 样本向量和验证报告 |
| 证据检索 | 问题与资料库 | 证据定位 | 带来源的证据列表 |

## 把训练阶段放回同一张地图

预训练通常先用大量、较少人工标签的数据学习统计结构。自回归语言模型从文本自身得到监督信号；掩码模型从被遮蔽的位置得到监督信号。这叫自监督学习，并不意味着没有目标值，而是目标可以从数据中构造。数据来源、重复程度、覆盖范围和训练目标共同决定模型可能学到什么。

监督微调用任务示例调整模型行为，例如让输入问题对应一个格式明确的回答。偏好优化进一步使用回答之间的相对偏好；它不是把模型的每个知识结论重新证明一遍。推理阶段通常固定参数，根据输入计算输出。检索增强则在推理时提供外部上下文，外部资料变更不必等到重新训练权重。

本地小模型有两个教学价值：可以完整检查计算步骤，也可以低成本制造故障并解释故障。它不会因为结构与大型系统相似，就自动继承大型系统的数据覆盖和语言能力。后续把“理解机制”“跑通原型”“建立研究证据”作为逐级目标，避免用一个漂亮演示替代最后一步。

## VS Code、终端和虚拟环境各负责什么

VS Code 是编辑器，终端负责执行命令，Python 解释器负责运行代码，虚拟环境负责隔离依赖。常见错误是终端把包装进一个 Python，而编辑器使用另一个 Python。遇到找不到模块时，先打印 sys.executable；不要连续尝试多套安装命令，把问题变成无法解释的环境变化。

在解压后的 project 目录创建虚拟环境。Windows PowerShell 可用 py -m venv .venv；macOS 或 Linux 可用 python3 -m venv .venv。可以激活环境，也可以始终使用环境中 Python 的完整路径。Windows 若激活脚本受限，直接调用 .venv\Scripts\python.exe 即可继续，不需要修改系统范围的执行策略。随后按工程 README 安装依赖，在 VS Code 的解释器选择器中选中该环境。

第一张环境卡至少记录操作系统、Python 版本、PyTorch 版本、设备和执行目录。CPU 是课程主线，没有独立显卡不妨碍起步。训练时长取决于设备与配置，示例步数不是对运行分钟数的承诺。安装依赖需要网络，安装后教学数据及主线训练可以本地进行。

## 张量形状，是理解模型最可靠的入口

标量只有一个数，向量是一列数，矩阵有行列，更高阶张量用额外轴组织批次或序列。语言模型常见输入形状是 [B,T]：B 是同一批样本数量，T 是每段上下文的 token 数。经过 embedding 后变成 [B,T,D]，每个 token 对应一个 D 维向量。最后为词表 V 个候选给分，得到 [B,T,V]。

微生物模型也可以用 [B,F,D] 表示 B 个样本、F 个物种 token 及 D 维表示，但 F 没有天然前后文顺序。形状相似不表示科学含义相同。代码再长，都先给每条主要张量写出轴的含义。最后一轴是特征时，Linear(D,H) 才能把它映射为 H 维；交换轴不改变数值数量，却可能改变计算语义。

例子把两个样本的三个特征映射到两个输出。矩阵乘法要求内侧维度相同：[2,3] 乘 [3,2] 得到 [2,2]。用 @ 表示矩阵乘法，* 表示逐元素乘法。广播可让偏置 [2] 加到每一行，也可能把错误形状悄悄扩大，所以频繁使用 assert，不只看程序能不能运行。

```python
import torch
x = torch.tensor([[1., 2., 3.], [4., 5., 6.]])
w = torch.tensor([[1., 0.], [0., 1.], [1., 1.]])
b = torch.tensor([0.5, -0.5])
y = x @ w + b
assert x.shape == (2, 3)
assert y.shape == (2, 2)
print(y)  # [[4.5, 4.5], [10.5, 10.5]]
```

## 从一次手算开始理解自动求导

设一个极小模型 y_hat=w×x+b，目标 y=5，输入 x=2，初始 w=1、b=0。预测值为 2，平方损失 L=(2−5)²=9。链式法则给出 dL/dw=2×(y_hat−y)×x=−12，dL/db=2×(y_hat−y)=−6。梯度指向损失增加最快的局部方向，因此梯度下降要减去学习率乘梯度。

若学习率为 0.01，更新后 w=1.12、b=0.06，预测为 2.30，损失为 7.29。这个例子只证明我们朝正确方向移动了一步，不证明任意学习率都稳定，也不证明复杂网络每一步损失都下降。后面所有 Transformer 参数更新，基本逻辑仍是前向计算、得到损失、反向传播和优化器更新。

PyTorch 记录可求导张量组成的计算图。调用 backward 后，梯度累积在参数的 grad 中；再次反向传播前通常需要清零。不要把训练张量随意转成 Python 数字或 NumPy 数组后再构造新张量，这会切断计算图。记录日志时可对副本使用 detach 或 item，但用于 backward 的损失须保留图关系。

```text
L=(wx+b-y)²；∂L/∂w=2(wx+b-y)x；∂L/∂b=2(wx+b-y)
```

```python
import torch
w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
loss = (w * 2.0 + b - 5.0).square()
loss.backward()
assert w.grad.item() == -12.0
assert b.grad.item() == -6.0
with torch.no_grad():
    w -= 0.01 * w.grad
    b -= 0.01 * b.grad
print(float((w * 2.0 + b - 5.0).square().detach()))
```

## 数据先分组，基线先落地

一个模型既可以学习可迁移规律，也可以利用不该使用的捷径。文本中同一段内容的重复版本若进入训练和测试，低损失可能来自记忆。微生物中，同一受试者不同时间点或同一研究技术特征若跨集合混用，模型可能学到身份与批次。第一天就把这些问题写进任务卡，可以减少“模型做好后才想验证”的返工。

训练集估计参数，验证集选择学习率、步数和配置，测试集留到方案确定后评估。若按不同研究评价迁移，测试研究也不能悄悄参加自监督预训练；否则实验回答的是允许无标签目标域数据的另一种设定，必须明确标注。缺失值处理、特征筛选、标准化和词表构建同样遵守训练边界。

基线是判断复杂性是否值得的参照。语言模型可比较均匀概率或训练集频率预测；菌群任务可比较简单插补和线性预测。深模型优于很弱的基线，不等于优于合理的传统方法。今天写出基线名称、允许使用的数据和评价输出，后续按同一划分实现。

## 一次小实验应该留下什么

实验目录不是随意存放截图的地方。为每次运行保存独立目录，至少区分配置、日志、权重和指标。配置说明当时使用了多少数据、什么随机种子、什么架构和多少训练步；日志记录损失随步骤的变化；权重用于恢复模型；指标文件说明评价样本与算法。文件可以简单，但四类信息不能彼此替代。只有一个模型文件，往往不足以解释它怎么得到。

调试时还应保留失败的证据。例如把学习率调得过大后出现非有限损失，记录修改前后唯一不同的配置、第一次异常所在步骤及输入范围。不要删除异常点，再把平滑后的曲线作为训练表现。学习的目标不是让每次运行都好看，而是知道失败发生在哪个环节，并用最小改动验证判断。

今天用课程提供的小配置建立第一份基线运行。后续改动需要另建目录，比较相同数据划分下的变化，保留原始基线。这样的习惯会让最后的模型卡有据可写，也能帮助你分辨“代码改进”“随机波动”和“评价条件改变”三种完全不同的现象。

## 练习与完整参考解答

### 练习 1. 手算例子中若学习率为 0.1，更新后 w、b、预测和损失是什么？

提示：使用同一初始梯度。
