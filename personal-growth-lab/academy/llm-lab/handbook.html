CurateMicrobiota 的三种对象

本课程把 CurateMicrobiota 用作实战项目名称。对接的公开数据资源 curatedMetagenomicData 提供统一处理的宏基因组物种和功能表及元数据。菌群相对丰度是一行样本、一列物种的非负数值表，它本身不是自然语言，也不是原始 DNA 序列。因此不能因为采用 Transformer，就把三类模型混为同一种任务。

TinyGPT 接收文本 token，学习“给定前文，下一个 token 的概率”。微生物表征模型接收物种身份和丰度，学习从可见组成重建被遮蔽的信息，之后再检验学到的表征能否迁移到标签预测。证据检索模块接收问题，返回可追溯的文献片段或证据卡。三者可以连接成系统，但各自需要不同的数据、损失和评价。

生成“某菌与抑郁相关”不等于完成关联分析；分类器输出较高风险分数不等于找到了致病机制；检索到一篇研究不等于研究结论已被重复验证。项目中的界面、文件名和报告都要把模型输出的性质写清。科学上可信的项目，首先能准确描述自己做了什么。

把训练阶段放回同一张地图

预训练通常先用大量、较少人工标签的数据学习统计结构。自回归语言模型从文本自身得到监督信号；掩码模型从被遮蔽的位置得到监督信号。这叫自监督学习，并不意味着没有目标值，而是目标可以从数据中构造。数据来源、重复程度、覆盖范围和训练目标共同决定模型可能学到什么。

监督微调用任务示例调整模型行为，例如让输入问题对应一个格式明确的回答。偏好优化进一步使用回答之间的相对偏好；它不是把模型的每个知识结论重新证明一遍。推理阶段通常固定参数，根据输入计算输出。检索增强则在推理时提供外部上下文，外部资料变更不必等到重新训练权重。

本地小模型有两个教学价值：可以完整检查计算步骤，也可以低成本制造故障并解释故障。它不会因为结构与大型系统相似，就自动继承大型系统的数据覆盖和语言能力。后续把“理解机制”“跑通原型”“建立研究证据”作为逐级目标，避免用一个漂亮演示替代最后一步。

VS Code、终端和虚拟环境各负责什么

VS Code 是编辑器，终端负责执行命令，Python 解释器负责运行代码，虚拟环境负责隔离依赖。常见错误是终端把包装进一个 Python，而编辑器使用另一个 Python。遇到找不到模块时，先打印 sys.executable；不要连续尝试多套安装命令，把问题变成无法解释的环境变化。

在解压后的 project 目录创建虚拟环境。Windows PowerShell 可用 py -m venv .venv；macOS 或 Linux 可用 python3 -m venv .venv。可以激活环境，也可以始终使用环境中 Python 的完整路径。Windows 若激活脚本受限，直接调用 .venv\Scripts\python.exe 即可继续，不需要修改系统范围的执行策略。随后按工程 README 安装依赖，在 VS Code 的解释器选择器中选中该环境。

第一张环境卡至少记录操作系统、Python 版本、PyTorch 版本、设备和执行目录。CPU 是课程主线，没有独立显卡不妨碍起步。训练时长取决于设备与配置，示例步数不是对运行分钟数的承诺。安装依赖需要网络，安装后教学数据及主线训练可以本地进行。

张量形状，是理解模型最可靠的入口

标量只有一个数，向量是一列数，矩阵有行列，更高阶张量用额外轴组织批次或序列。语言模型常见输入形状是 [B,T]：B 是同一批样本数量，T 是每段上下文的 token 数。经过 embedding 后变成 [B,T,D]，每个 token 对应一个 D 维向量。最后为词表 V 个候选给分，得到 [B,T,V]。

微生物模型也可以用 [B,F,D] 表示 B 个样本、F 个物种 token 及 D 维表示，但 F 没有天然前后文顺序。形状相似不表示科学含义相同。代码再长，都先给每条主要张量写出轴的含义。最后一轴是特征时，Linear(D,H) 才能把它映射为 H 维；交换轴不改变数值数量，却可能改变计算语义。

例子把两个样本的三个特征映射到两个输出。矩阵乘法要求内侧维度相同：[2,3] 乘 [3,2] 得到 [2,2]。用 @ 表示矩阵乘法，* 表示逐元素乘法。广播可让偏置 [2] 加到每一行，也可能把错误形状悄悄扩大，所以频繁使用 assert，不只看程序能不能运行。

python
import torch
x = torch.tensor([[1., 2., 3.], [4., 5., 6.]])
w = torch.tensor([[1., 0.], [0., 1.], [1., 1.]])
b = torch.tensor([0.5, -0.5])
y = x @ w + b
assert x.shape == (2, 3)
assert y.shape == (2, 2)
print(y)  # [[4.5, 4.5], [10.5, 10.5]]

从一次手算开始理解自动求导

设一个极小模型 y_hat=w×x+b，目标 y=5，输入 x=2，初始 w=1、b=0。预测值为 2，平方损失 L=(2−5)²=9。链式法则给出 dL/dw=2×(y_hat−y)×x=−12，dL/db=2×(y_hat−y)=−6。梯度指向损失增加最快的局部方向，因此梯度下降要减去学习率乘梯度。

若学习率为 0.01，更新后 w=1.12、b=0.06，预测为 2.30，损失为 7.29。这个例子只证明我们朝正确方向移动了一步，不证明任意学习率都稳定，也不证明复杂网络每一步损失都下降。后面所有 Transformer 参数更新，基本逻辑仍是前向计算、得到损失、反向传播和优化器更新。

PyTorch 记录可求导张量组成的计算图。调用 backward 后，梯度累积在参数的 grad 中；再次反向传播前通常需要清零。不要把训练张量随意转成 Python 数字或 NumPy 数组后再构造新张量，这会切断计算图。记录日志时可对副本使用 detach 或 item，但用于 backward 的损失须保留图关系。

L=(wx+b-y)²；∂L/∂w=2(wx+b-y)x；∂L/∂b=2(wx+b-y)
python
import torch
w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
loss = (w * 2.0 + b - 5.0).square()
loss.backward()
assert w.grad.item() == -12.0
assert b.grad.item() == -6.0
with torch.no_grad():
    w -= 0.01 * w.grad
    b -= 0.01 * b.grad
print(float((w * 2.0 + b - 5.0).square().detach()))

数据先分组，基线先落地

一个模型既可以学习可迁移规律，也可以利用不该使用的捷径。文本中同一段内容的重复版本若进入训练和测试，低损失可能来自记忆。微生物中，同一受试者不同时间点或同一研究技术特征若跨集合混用，模型可能学到身份与批次。第一天就把这些问题写进任务卡，可以减少“模型做好后才想验证”的返工。

训练集估计参数，验证集选择学习率、步数和配置，测试集留到方案确定后评估。若按不同研究评价迁移，测试研究也不能悄悄参加自监督预训练；否则实验回答的是允许无标签目标域数据的另一种设定，必须明确标注。缺失值处理、特征筛选、标准化和词表构建同样遵守训练边界。

基线是判断复杂性是否值得的参照。语言模型可比较均匀概率或训练集频率预测；菌群任务可比较简单插补和线性预测。深模型优于很弱的基线，不等于优于合理的传统方法。今天写出基线名称、允许使用的数据和评价输出，后续按同一划分实现。

一次小实验应该留下什么

实验目录不是随意存放截图的地方。为每次运行保存独立目录，至少区分配置、日志、权重和指标。配置说明当时使用了多少数据、什么随机种子、什么架构和多少训练步；日志记录损失随步骤的变化；权重用于恢复模型；指标文件说明评价样本与算法。文件可以简单，但四类信息不能彼此替代。只有一个模型文件，往往不足以解释它怎么得到。

调试时还应保留失败的证据。例如把学习率调得过大后出现非有限损失，记录修改前后唯一不同的配置、第一次异常所在步骤及输入范围。不要删除异常点，再把平滑后的曲线作为训练表现。学习的目标不是让每次运行都好看，而是知道失败发生在哪个环节，并用最小改动验证判断。

今天用课程提供的小配置建立第一份基线运行。后续改动需要另建目录，比较相同数据划分下的变化，保留原始基线。这样的习惯会让最后的模型卡有据可写，也能帮助你分辨“代码改进”“随机波动”和“评价条件改变”三种完全不同的现象。

计算机看到的文本，比“一个字”复杂

人读文本时倾向于把一个字、单词或词组当作单位，但它们在计算机里不总对应一个数字。Unicode 为字符定义码点，UTF-8 将码点编码为一个或多个字节；显示出来的一个符号也可能由多个码点组合。最稳妥的检查是同时看字符串长度、编码后的字节长度以及实际整数序列。

“菌A”有两个 Python 字符，UTF-8 编码得到四个字节：中文“菌”占三个，英文字母 A 占一个。字节词表可以覆盖所有 UTF-8 文本，无须为每个新汉字增加条目，代价是相同文本的 token 序列通常更长。字符词表更直观，但只根据训练语料建立时，必须给未见字符设计处理规则。

不要把“一个 token 大约几个英文字符”当作所有语言和 tokenizer 的恒定换算。物种名、拉丁文、下划线和 accession 都可能拆成不同长度的片段。工程实际编码以保存的 tokenizer 配置为准；下面的字节实验是理解可逆性，不要求悄悄更换工程的默认编码。

python
text = "菌A"
raw = text.encode("utf-8")
print(len(text), len(raw), list(raw))
assert len(text) == 2 and len(raw) == 4
assert bytes(list(raw)).decode("utf-8") == text

词表大小和序列长度，是一组预算

按单词编码时，常见单词可以很紧凑，但长尾物种名和新词容易落入未知词；按字符或字节编码时，覆盖更自然，却要更长序列表达同一句话。子词方法处于两者之间，把常共同出现的片段合并为 token，同时保留组合新词的能力。词表 V 和上下文 T 会分别影响 embedding 与注意力开销。

词表扩大时，embedding 参数按 V×D 增长，输出层要给更多候选评分；序列增长时，普通全注意力需要处理 T×T 的位置关系。更大的词表若显著缩短序列，可能值得；如果语料很小而词表巨大，大量条目很少更新，反而浪费参数。不存在脱离数据的最佳词表大小。

本课程优先用简单编码，让每个 token 与目标都可检查。后面的丰度模型中，物种标识相当于离散 token，丰度是额外连续数值。不能把丰度小数逐字拆开，就宣称得到科学上等价的输入。先选择表达对象，再选择编码方法。

手工做一次 BPE

简化 BPE 训练从较小符号开始，统计相邻符号对频率，每一步合并频率较高的一对，再重复到目标词表大小。它利用序列出现规律，不需要理解词义。用“a b a b a”和“a b a”两个序列，先数相邻对：a b 共三次，b a 也共三次。并列时要规定确定规则，否则相同数据可能产生不同词表。

若并列时选 a b，把它合为 X，序列变成“X X a”和“X a”。下一步必须在新序列重新计数，不能继续用旧频率。真实 tokenizer 还涉及预切分、字节映射、特殊 token 和高效实现，但“学习规则”与“应用已固定规则”要分清。

评价用的 tokenizer 一旦确定，应与模型一起冻结。不能把验证或测试文本加入当前实验 tokenizer 训练，又将评估描述为完全未见测试分布。使用外部预训练 tokenizer 是允许的设定，但需要写清来源；它与从本实验训练集现学词表并非同一条件。

python
from collections import Counter
seqs = [list("ababa"), list("aba")]
pairs = Counter(pair for s in seqs for pair in zip(s, s[1:]))
print(pairs)
def merge_once(seq, pair, new):
    out, i = [], 0
    while i < len(seq):
        if i + 1 < len(seq) and tuple(seq[i:i+2]) == pair:
            out.append(new); i += 2
        else:
            out.append(seq[i]); i += 1
    return out
assert merge_once(seqs[0], ("a", "b"), "X") == ["X", "X", "a"]

token ID 只是索引

假设“菌”“群”“。”的 ID 是 4、19、2。ID 19 不表示“群”比“菌”强 4.75 倍，也不表示二者语义距离为 15。整数只是稳定指向词表条目。进入模型后，通过 embedding 查表才变成可学习的连续向量；因此输入 ID 使用整型，模型权重与激活通常使用浮点型。

特殊 token 可表示文档边界、填充、未知字符或控制信息。意义由数据组织和训练建立，不由名称自动赋予。插入 EOS 却从不要求模型在结束处预测它，生成器不一定知道何时停。使用 padding 时，必须明确哪些位置不进入损失、哪些位置不被注意力看到。

词表文件与权重一样重要。训练时 ID 7 是 a，加载时 ID 7 却是 b，形状可以完全匹配，但输出语义已错位。检查点要保留 tokenizer 配置、词表或字符列表、模型参数和数据版本。调试先做 encode—decode 往返，再检查网络，不要反过来。

输入和目标只差一格

对 token 序列 [5,8,2,9,4]，上下文 T=4 时输入是 [5,8,2,9]，目标是 [8,2,9,4]。第一个位置用已见的 5 预测 8；第二个用 5、8 预测 2；最后用整个输入前缀预测 4。一次前向可以同时计算四个位置的损失，但因果注意力必须限制各位置可用信息。

常见错误有两种：直接把目标设为输入自身，模型就能复制当前位置；目标虽然右移，却让位置 t 看见输入 t+1，仍能偷看待预测 token。数据窗口正确与因果遮罩正确必须同时满足，不能只验证其中之一。

例子显式要求 T+1 个 token，再切出等长 x 与 y，批量堆叠得到 [B,T]。文件末尾不足 T+1 时，可舍弃窗口或按明确规则补齐；不能随意补一个真实词表 ID，又让这些补齐位置进入损失。主线先使用等长窗口，把其他复杂性暂时分离。

x=(z₀,…,zT₋₁)，y=(z₁,…,zT)；L=−平均 log pθ(y_t | x₀,…,x_t)
python
import torch
z = torch.tensor([5, 8, 2, 9, 4], dtype=torch.long)
T = 4
x, y = z[:T], z[1:T+1]
assert x.tolist() == [5, 8, 2, 9]
assert y.tolist() == [8, 2, 9, 4]
assert torch.equal(x[1:], y[:-1])
print(list(zip(x.tolist(), y.tolist())))

滑动窗口为什么制造假泛化

从长文每隔一个 token 取窗口，会产生很多高度重叠的训练样本。如果先生成全部窗口，再随机分出测试集，测试窗口可能与训练窗口只差一个 token。低损失此时不代表能处理新文档，统计出来的“样本数”也远大于独立信息数量。

正确顺序取决于目标。想评价新文档，先按文档或来源分组、去重，再分别编码与切窗口；想评价同一本连续文本后续部分，可以顺序切分并禁止窗口跨边界，但要承认评价范围较窄。同一文章的版本、翻译或摘录也应作为关联来源处理，不能只比较文件名。

训练集内部使用重叠窗口可以是数据利用方式，评价集近重复却会改变结论。记录文档数、总 token、窗口长度、步长、去重和划分单位。比起“有一百万训练样本”，这些信息更能帮助别人理解实际利用了多少内容。

让任何窗口都能回溯来源

下面按不同 document ID 演示先分文档再切窗口。函数只读一篇文档，不跨文档串接。若真实训练要串联文档，应显式插入边界 token，并检查跨文档注意力是否符合目标。初学阶段选择容易解释的规则，把效率技巧建立在可验证的数据定义上。

代码的列表划分只是示例。正式实验可按来源、时间或研究分组，固定种子与清单，保留 ID。若 tokenizer 要学习，先仅用训练文档拟合，再编码其他文档；未见字符采用明确 unknown 或 byte fallback。不能默默丢弃测试集难编码片段，那会选择性地使评价变容易。

执行后，应能追踪任意窗口来自哪篇文档、什么起点，以及目标属于哪个划分。后面处理研究名、受试者名和菌群列时会再次使用这个习惯：模型之前，先有一层可审计的数据索引。

def windows(ids, length=4, stride=2):
    return [(i, ids[i:i+length], ids[i+1:i+length+1])
            for i in range(0, len(ids)-length, stride)]

文本预处理不能丢掉科学含义

至少检查空文件、异常编码、重复段落、过长连续字符和模板噪声。清洗围绕任务制定：保留物种学名大小写和符号可能有价值，删除数字可能损坏 PMID、年份与 accession。清洗改变学习对象，必须写进数据卡，不能只留一份无法解释来源的最终文本。

语料事实可能过时或互相矛盾。下一 token 损失奖励的是对语料的预测，并不逐句核实结论。收集文献时，应区分正文、参考文献、导航内容及使用条件。课程短文本只用于检查流程，不能包装成覆盖微生物知识的基础语料库。

例如把同一论文的题名、摘要和数据库描述当成三条独立资料，可能重复强化一个结论。把撤回文章或评论中的反例句子无标识地拼入训练文本，也可能制造误导。今天不需要解决完整知识审计，但应记录来源 ID 与文本类型，让后面的证据模块能解释资料从哪里来。

填充、边界和损失掩码不能混用

当同一批文本长度不同，常见做法是把较短序列补到相同长度。假设两个有效长度分别为三和五，补齐后都长五。较短样本后两个位置不是真实文本，如果把它们当作普通训练目标，模型会花精力学习人工填充频率。可以给这些目标设置忽略索引，计算平均损失时只统计真实目标位置。

注意力掩码解决“能看谁”，损失掩码解决“哪些预测计分”，二者不是同一个对象。padding key 不应该被当成有效上下文；被忽略的输出位置即便不计分，也不能成为其他有效位置的信息来源。因果遮罩则处理未来位置，与 padding 遮罩具有不同原因，组合时必须检查布尔约定和形状。

一个极端情况是整行位置都被遮蔽。如果给这一行分数全部写入负无穷，再计算 softmax，可能得到非有限数值。设计数据加载时避免空有效样本，并为边界情况写出断言。主线的固定等长窗口暂时绕开 padding，但你仍应知道这些掩码存在的理由，以便后面读懂指令微调的回答区间损失。

计算 token 预算，并给数据写一张卡

设 B=4、T=32，一次训练微批次包括 128 个预测位置。若优化器更新前累积四个同样大小的微批次，有效 token 数是 512；它不表示模型获得了 512 个独立文档。相邻窗口重叠、语料重复和连续抽样都会降低独立信息量。写清统计单位，有助于后面比较训练预算。

数据卡至少含：原始来源与获取时间、许可或使用条件、清洗规则、去重单位、划分清单、tokenizer 类型与版本、词表大小、特殊 token、窗口长度、步长和目标构造。若是一份合成教学文本，直接写清合成性质与用途。不能只把文件命名为 final.txt，就以为数据版本已经管理好。

Embedding 是一张可学习的表

设词表大小 V=6，向量维度 D=3，embedding 就是一张 [6,3] 的参数表。输入 ID 2 时取第 2 行；输入 [2,1,2] 时依次取三行，其中第一个与第三个初始向量相同。查表本身没有读到相邻 token，也没有执行语义搜索。它只是把离散身份变成后续网络能处理的连续坐标。

为什么这些坐标会有用？因为训练损失沿计算图传回 embedding，使被用于预测的表示逐步改变。向量关系来自任务和数据，并不是随机初始化时已经藏着知识。一个未训练 embedding 中两个物种名余弦相似度高，没有生物学意义；即便训练之后，也要问相似性反映了共现、语法、来源偏好还是实际功能。

Embedding 可以理解为可学习的特征设计。在传统建模里，你人工决定一个对象用哪些特征；这里先给对象一组可优化坐标，再让任务决定如何利用它。维度 D 是容量选择，不是“模型理解了 D 种独立科学属性”。解释每个维度前需要额外证据。

查表与 one-hot 乘法为何等价

如果 ID 为 2，可写成长度六的 one-hot 向量 [0,0,1,0,0,0]。它乘 embedding 表只保留第 2 行，所以与查表结果相同。对批量序列，可以把每个 ID 变成 one-hot 后一起乘矩阵，但当词表很大时，这会建立大量零值，查表在表达和存储上更直接。

下面给参数表一个固定的人工数值，避免随机结果妨碍手算。输入的第二轴是位置，输出最后一轴是向量坐标。代码中的 assert 不只是确认 API 能运行，而是在检验我们对计算含义的理解。先手写期望的三维数组，再运行，才算完成这个练习。

注意数学表达中的行向量约定可能与代码权重布局不同。PyTorch 的 Linear 权重通常存成 [输出维,输入维]，前向等价于 x 乘权重转置；Embedding 存成 [词表,向量维]，直接按行索引。看到 W 与 W 转置时，先核对维度，不用死记某一种论文记号。

同一个 token，为何在不同位置需要不同表示

不考虑上下文时，相同 token ID 查到同一行。“菌群影响药物”和“药物影响菌群”包含相近词汇，却表达不同方向。序列模型需要某种方法表示顺序，否则仅仅把词向量放成一堆，很难区分这些关系。位置编码为模型提供“在哪里”的信息，token embedding 提供“是什么”的信息。

最直观的方案是可学习绝对位置表 P，形状为 [Tmax,D]。序列第 t 个位置取 P[t]，与对应 token 向量相加。位置表在所有 batch 样本共享，所以 [T,D] 可以广播到 [B,T,D]。相加要求最后一维相同；把二者拼接也可设计，但后续投影维度和参数量都要相应改变。

绝对位置表只为定义范围内的位置存了参数。若训练与实现只支持长度 32，不能在推理时随意输入长度 64 并期待正确外推。裁剪历史、重新设计位置机制和扩大训练上下文是不同方案。课程先明确上限并检查边界，后面再认识 RoPE 等方法。

位置编码没有“越先进越适合一切”的顺序

正弦位置编码用不同频率的正弦、余弦构造确定向量，无需学习位置表；可学习位置表由训练调整；旋转位置编码在注意力的查询与键上施加与位置有关的旋转。它们把顺序信息放入计算的方式不同，不能把换一个名字当作必然提升性能。

语言具有自然先后顺序，因果遮罩也会提供“能看到多少前缀”的结构，但顺序信号不等于单独一个位置向量，实际效果由完整架构决定。本课用显式位置编码，便于直接检查位置如何影响表示。实验中若去掉位置项，应把它当作一个有定义的消融，并在相同训练预算下比较。

菌群丰度表没有“排在第三列的物种在时间上早于第四列”的含义。后面的模型使用物种身份与丰度，避免把任意 CSV 列序当作语言位置。若引入系统发育信息，应作为有生物学依据的额外关系，而不是把表格排序伪装成进化距离。输入设计服务于科学对象。

从输入到输出，逐轴核对

以 B=2、T=4、D=8、V=10 为例，输入 ID 是 [2,4]，查词表得到 [2,4,8]，位置项为 [4,8]，相加仍是 [2,4,8]。之后 Transformer 保持这个主干形状，最后输出投影把每个位置的 8 维表示映射为 10 个候选分数，得到 [2,4,10]。

最后一层产生的数值叫 logits，可以为正或负，也不要求和为一。softmax 沿词表轴把它们转为概率；沿错误轴做归一化也可能得到看起来合理的数组，但那不再是每个位置的候选 token 分布。交叉熵实现通常直接接收 logits，在内部进行稳定计算，不需要你先手工 softmax。

在调试表中，为每个节点写四件事：形状、dtype、device 和语义。输入 ID 常为 long，embedding 输出为浮点，两者要在同一设备。把模型放到某设备而忘记移动位置索引，是实际编码里很常见的错误。对小模型而言，先统一在 CPU 使用 float32 最便于理解。

写出最小预测器，并准确说明它的限制

下面的模块只有 token embedding、位置 embedding 和输出投影。它足以演示数据接口及损失形状，却没有把不同位置的信息混合起来。位置 t 的预测只能使用当前 token 向量和位置向量，无法依据更早上下文区分同一个 token 的不同用法。这是后面加入注意力的直接动机。

运行时只检查输出形状与数值有限，不检查它能否写出自然语言。随机初始化的模型没有接受训练，输出概率接近某种无知识的初始分布才正常。如果一个复杂系统在初始化后就能输出完整科学回答，那通常说明你调用了已有模型或外部内容，而不是刚刚训练出知识。

读完整工程时，找到同样的三个接口，再定位它们之间新增的 Transformer blocks。这样即便代码变长，你仍能知道每部分承担什么。不要把 embedding 之后的所有内容一概叫“黑箱”，每天只增加一种能解释的变换。

python
import torch
from torch import nn
class TokenPositionHead(nn.Module):
    def __init__(self, vocab=10, dim=8, context=4):
        super().__init__()
        self.token = nn.Embedding(vocab, dim)
        self.position = nn.Embedding(context, dim)
        self.head = nn.Linear(dim, vocab, bias=False)
    def forward(self, ids):
        B, T = ids.shape
        pos = torch.arange(T, device=ids.device)
        h = self.token(ids) + self.position(pos)
        return self.head(h)
model = TokenPositionHead()
ids = torch.tensor([[1, 2, 3, 4], [4, 3, 2, 1]])
logits = model(ids)
assert logits.shape == (2, 4, 10)
assert torch.isfinite(logits).all()
print(sum(p.numel() for p in model.parameters()))  # 192

参数量与内存，先算后改

上面的小模块有词表参数 10×8=80、位置参数 4×8=32、无偏置输出参数 8×10=80，总计 192。参数量可以手算，也可以用 numel 汇总，两者对不上时要查是否包含 bias、归一化参数或共享权重。模型名称中“多少参数”应来自实际实现，不照抄别人的结构估计。

如果 V=256、D=64、Tmax=64，词表参数是 16384，位置表是 4096，独立输出表又增加 16384。输入与输出权重共享时，两处使用同一组参数，总量会降低；这是建模选择，不能仅把数值复制一遍就叫共享。真正共享还意味着来自两条路径的梯度会共同更新同一参数对象。

参数内存只是训练内存的一部分。float32 参数每个通常占四字节，还要考虑梯度、优化器状态、中间激活、注意力矩阵和缓存。小模型可用手算建立量级感觉，大模型要实际测量峰值。把训练失败简单归因于“参数太多”，可能忽略了上下文长度带来的更大开销。

Embedding 的梯度会更新哪些行

在纯查表后求和的例子中，只有被索引的行收到梯度，重复出现的 ID 会让梯度累加。输入 [1,1,3] 时，第一行出现两次，第三行一次，其余行没有参与这条计算路径。这是一个适合手算的局部事实，也能帮助理解罕见 token 在小语料中为什么可能学得不足。

不要把这个结论直接推广成“语言模型每步只更新出现过的词表行”。若输出投影与输入 embedding 共享权重，softmax 预测的输出路径会对候选行贡献梯度；不同的优化器设置也会影响参数变化。区分“这条局部路径的梯度”和“整个模型参数的总梯度”，是读懂共享权重的重要一步。

下面只验证纯查表路径。运行后检查 grad 数值，再把 loss 从 sum 改为 mean，观察梯度按参与元素数缩放。梯度大小与损失的归一化规则直接相关，这个结论到第六课的梯度累积时会再次出现。

python
import torch
from torch import nn
emb = nn.Embedding(5, 2)
ids = torch.tensor([1, 1, 3])
emb(ids).sum().backward()
expected = torch.tensor([[0.,0.],[2.,2.],[0.,0.],[1.,1.],[0.,0.]])
assert torch.equal(emb.weight.grad, expected)
print(emb.weight.grad)

静态向量、上下文向量与样本向量

静态 embedding 对同一 token 返回固定初始向量，经过注意力与非线性层后，同一 token 的表示会因上下文改变。最后可以选择某个位置、做有效位置平均或使用特定汇聚方式，把一段文本压成一个向量。汇聚方式定义了保留与丢失的信息，应根据任务验证。

在菌群模型中，每个物种先有身份向量，再结合该样本丰度，经双向信息混合后得到样本内物种表示，最后汇聚为样本向量。这个向量可以用于线性探针或其他下游任务，但聚类图上分得开不等于疾病信号可泛化；它也可能按研究、测序流程或人群结构分开。

比较向量时，余弦相似度关注方向，欧氏距离同时受尺度影响。归一化、汇聚和训练目标都会改变距离含义。今天可计算相似度熟悉操作，但不要给随机向量贴“产丁酸功能”“炎症轴”等标签。科学解释必须由独立分析支持。

为什么仅有 embedding 还不够

上一课的最小预测器只根据当前位置 token 和位置给下一 token 打分，不能读取更早内容。设文本出现“研究 A”“研究 B”，之后都接“发现”，当前位置相同，应该引用哪项结果却依赖前文。注意力提供一种按当前需求汇集其他位置信息的方法，而不是把所有前缀简单平均。

每个位置先从当前表示产生三个向量：查询 Q 表示这次要匹配的特征，键 K 表示可被匹配的特征，值 V 表示匹配后实际传递的内容。这些是便于理解的角色描述，真实含义由训练决定，不能把每个头预先命名为“语法头”或“疾病头”。Q、K、V 都是可学习线性变换的输出。

一个位置将自身 Q 与允许范围内各位置 K 比较，得到分数；softmax 把分数变成权重；用这些权重对 V 求加权和。查询者决定读什么，键参与决定读谁，值提供被读取内容。三者可以来自同一序列，也可以来自不同序列；本课实现自注意力，全部由同一输入产生。

先写形状，再写公式

设单头输入 X 为 [B,T,D]，查询与键维度为 d，值维度为 dv。三个权重分别把 D 映射到 d、d 和 dv，得到 Q=[B,T,d]、K=[B,T,d]、V=[B,T,dv]。Q 乘 K 在最后两轴的转置，得到 [B,T,T] 的分数矩阵。

分数矩阵的行表示“哪个位置正在查询”，列表示“哪个位置作为候选被读取”。因此 softmax 沿最后一轴，也就是候选键的位置轴进行。每一行在有效候选上形成分布，再乘 V，得到 [B,T,dv]。如果沿查询轴归一化，代码仍能运行，却回答了不同的问题。

这里的 QK 转置只交换最后两个维度，不能把 batch 一起转走。使用 transpose(-2,-1) 可以明确表达这个意图。后面增加多头时会多出一个头轴，主要矩阵关系仍然不变。每遇到一个新维度，都先给它起科学或计算含义明确的名字。

Q=XWQ，K=XWK，V=XWV；A=softmax(QKᵀ/√d+M)；O=AV
对象形状最后两轴含义
Q、K[B,T,d]位置×查询/键特征
V[B,T,dv]位置×值特征
分数与权重[B,T,T]查询位置×候选位置
输出[B,T,dv]位置×汇聚特征

两位置例子：把一次注意力算完

取查询 q=[1,0]，两个键 k1=[1,0]、k2=[0,1]，两个值 v1=[2,0]、v2=[0,4]。原始点积为 [1,0]，键维度 d=2，缩放后分数为 [1/√2,0]。softmax 给出约 [0.670,0.330]，输出为 0.670×[2,0]+0.330×[0,4]，约 [1.34,1.32]。

这个输出通常不是某个原始值向量的直接拷贝，而是按上下文需要得到的混合。改变 K 会改变权重，改变 V 会改变被传递的内容；如果只看最终输出，无法唯一判断变化发生在哪条路径。这也提醒我们，注意力图只能观察计算的一部分。

现在把第二个键改为 [2,0]，预测第二个权重会增大，再运行核对。然后保持 Q、K 不变，只把 v2 改为 [0,8]，权重应该不变，输出第二维增加。两步实验分别隔离“选信息”和“传信息”，比一次同时修改所有矩阵更能建立理解。

python
import math
import torch
q = torch.tensor([[1., 0.]])
k = torch.tensor([[1., 0.], [0., 1.]])
v = torch.tensor([[2., 0.], [0., 4.]])
a = torch.softmax(q @ k.T / math.sqrt(2), dim=-1)
out = a @ v
assert torch.allclose(a.sum(-1), torch.ones(1))
print(a, out)

为什么除以维度平方根

点积把 d 个乘积项相加。若为了直观分析，假设各维查询与键近似独立、均值为零且方差为一，那么点积方差会随 d 增长，尺度约随 √d 增长。维度较大时，分数容易过大，softmax 变得非常尖锐，一些梯度可能变得不利于学习。除以 √d 是控制初始分数尺度的办法。

这些独立和方差假设是解释缩放动机的近似，不是训练后网络必须满足的事实。实际数值还受初始化、归一化和数据分布影响，因此仍应检查分数范围与注意力熵。缩放不是保证训练稳定的唯一条件，也不能修复错误目标或数据泄漏。

做一个小实验：分别生成 d=8、32、128 的随机查询键，比较未缩放点积的标准差与缩放后的标准差。使用足够多重复样本观察趋势，不要求每一次抽样完全相同。实验目标是理解量级，而不是把随机结果拟合成新的科学规律。

额外核对时，分清键维度与整个模型维度。多头结构中每个头只拥有一部分查询和键特征，缩放通常使用该头的键维度。若误用总维度，分数会被额外压小，注意力分布可能更平；程序不一定报错，但已经改变了模型。把缩放分母也列入你的形状检查表。

稳定 softmax 与负无穷遮罩

softmax 的分子是指数，直接对很大的分数取 exp 可能溢出。对一行分数统一减去该行最大值不会改变归一化结果，因为分子分母都乘了同一个常数。实际训练通常使用框架提供的稳定实现，但你应知道它为什么可以平移分数。

遮罩可以把禁止位置的分数设置为负无穷，再进行 softmax，这些位置的概率就为零。把禁止位置简单乘零是不对的：如果其他有效分数为负，零反而可能得到更大权重。也不要把已经归一化的概率直接删掉后不重新归一化，除非你明确定义的是另一种操作。

一行必须至少有一个有效候选，否则全为负无穷时可能出现非有限结果。因果自注意力通常保留当前位置自身，所以第一行仍有对角线位置可用。若后来组合 padding 遮罩，需再次检查是否制造了空有效行。注意力 dropout 之后行和不一定为一，归一化断言应作用在 dropout 之前。

python
import torch
scores = torch.tensor([[1000., 1001., 999.]])
shifted = scores - scores.max(dim=-1, keepdim=True).values
manual = shifted.exp() / shifted.exp().sum(dim=-1, keepdim=True)
assert torch.allclose(manual, torch.softmax(scores, dim=-1))
forbidden = torch.tensor([[False, True, False]])
a = torch.softmax(scores.masked_fill(forbidden, float('-inf')), dim=-1)
assert a[0, 1].item() == 0.0
assert torch.isfinite(a).all()

因果遮罩：允许看到自身，禁止偷看未来

下一 token 目标在位置 t 使用输入 0 到 t 预测原序列 t+1，因此允许看当前位置输入，禁止看输入 t+1 以及之后。遮罩应去掉严格上三角，保留下三角与对角线。若误把对角线也去掉，第一行没有有效候选；若方向写反，则模型能看未来却看不到前文。

不要混淆训练时并行与信息泄漏。虽然所有位置一起计算，但每一行独立遵守自己的可见前缀，因果目标仍成立。生成时当前序列末端没有真实未来 token，所以模型依次追加预测。训练可以并行计算位置损失，生成的新增 token 通常有顺序依赖。

不同框架 API 对布尔 mask 的含义可能相反：有的 True 表示禁止，有的表示允许。课程手写实现明确规定 forbidden=True 表示禁止，再使用 masked_fill。换成高效内核前应阅读对应 API 并跑同样因果测试，而不是照搬布尔张量。

实现单头注意力

下面的函数直接接收 Q、K、V，便于独立验证，使用固定的因果遮罩。广播让 [T,T] 的禁止矩阵作用到每个 batch。结果先计算注意力权重，再混合值向量，整个过程不读取训练目标。函数中把长度、键维度和输出形状写清，未来增加多头时才不会盲目 reshape。

运行随机示例后检查三个性质：输出形状符合预期；每一行概率和为一；严格上三角概率全为零。第一行只有自身可用，注意力应为 [1,0,…]。这些检查证明矩阵操作的局部规则正确，但还不能保证完整模型不存在其他未来信息通路。

因此下一节还要直接扰动未来输入，检查更早输出是否改变。测试应与风险对应：形状测试捕捉接口错误，概率测试捕捉归一化错误，扰动测试捕捉信息流错误。只写“模型可以前向”远远不够。

python
import math
import torch
def attention(q, k, v):
    T, d = q.shape[-2:]
    scores = q @ k.transpose(-2, -1) / math.sqrt(d)
    forbidden = torch.triu(torch.ones(T, T, dtype=torch.bool, device=q.device), diagonal=1)
    a = torch.softmax(scores.masked_fill(forbidden, float('-inf')), dim=-1)
    return a @ v, a
torch.manual_seed(7)
q = torch.randn(2, 4, 6); k = torch.randn(2, 4, 6); v = torch.randn(2, 4, 5)
out, a = attention(q, k, v)
assert out.shape == (2, 4, 5)
assert torch.allclose(a.sum(-1), torch.ones(2, 4))
assert torch.count_nonzero(torch.triu(a, diagonal=1)) == 0

用未来扰动，检验真正的因果性

创建一份输入 X，再复制为 X2，只修改后两个位置。用相同权重计算两个输出，比较前两个位置。只要信息流严格因果，前缀输出应该保持不变；后面输出可以改变，因为它们有权看到被修改的位置。这个测试比肉眼看遮罩图更直接。

完整模型也应该做类似测试，处于 eval 模式、关闭 dropout，固定输入与参数。不要因为训练模式中的随机 dropout 导致输出不同，就误判为泄漏。先排除随机干扰，再做有控制的扰动；必要时使用容差比较，考虑浮点计算的误差。

若测试失败，检查是否有跨全部时间位置的归一化、在前向中使用完整序列汇总、目标被拼到输入或 mask 广播错误。逐层记录第一个出现前缀差异的位置，可以定位非法信息通路。科学建模里检验“模型是否用了不该知道的信息”，也是同样的思路。

python
torch.manual_seed(11)
x = torch.randn(1, 4, 6)
x2 = x.clone(); x2[:, 2:] += 100
Wq, Wk, Wv = [torch.randn(6, 6) for _ in range(3)]
def forward(z):
    return attention(z @ Wq, z @ Wk, z @ Wv)[0]
y1, y2 = forward(x), forward(x2)
assert torch.allclose(y1[:, :2], y2[:, :2], atol=1e-6)
print('future perturbation passed')

注意力图显示了什么，没有显示什么

某个位置给某个词较高权重，表示这条计算路径在当前参数和输入下更多混合了它的值向量。它不直接等于该词对最终回答的总贡献，更不等于生物因果作用。残差路径、其他头、其他层和后续非线性都可能改变最终输出。

微生物模型中也一样：两个物种 token 之间注意力大，不足以证明共生、代谢互作或水平基因转移。丰度共变、组成约束、测序批次和共同环境都可能影响表示。若要研究模型利用什么信息，可以结合扰动、消融、稳定性分析和独立生物知识，但每种方法也有自己的假设。

本课可把注意力矩阵画成热图帮助检查遮罩，标题应写“模型注意力权重示例”，不能写“发现微生物相互作用网络”。把计算机制与科学解释分清，反而让最终项目更有研究价值，因为用户知道哪些图能用于调试、哪些结论还需要验证。

序列长度为什么很贵，优化内核解决什么

单头注意力矩阵有 B×T×T 个元素，多头后还乘头数 H。T 从 32 变成 64，矩阵元素变为四倍；从 64 变为 256，则变为十六倍。值投影和前馈层也有开销，但序列增加带来的平方项尤其需要预算。微生物 token 数上千时，同样应先估计规模。

FlashAttention 等方法通过分块与减少内存读写，避免以朴素方式物化完整注意力中间结果，并保持标准注意力计算的数学目标；它不是把所有两两关系神奇地变成线性复杂度。实际速度还取决于设备、形状、精度和内核支持，不能照搬某论文的加速倍率。

本课先保留可读手写实现，之后若替换高效算子，要求相同输入输出在容差内一致，并再次通过因果扰动测试。优化应保持已确认的语义。先把事情做对，再通过证据判断哪里最值得加速。

多头不是把同一个结果复制几遍

单头在一个投影空间中决定信息混合，多头把表示划分为多个子空间，分别计算权重与值汇聚，再拼回整体表示。假设总宽度 D=64、头数 H=4，每头维度 d=16。每个头有不同的投影参数，但不是预先安排一个看语法、一个看疾病；各头的功能由数据和训练共同形成。

工程先用一个 Linear(D,3D) 同时得到 Q、K、V，再沿最后一轴 chunk 成三份。这样和分别建立三个投影在表达上对应，但存储及计算组织更紧凑。每份 [B,T,D] 先变为 [B,T,H,d]，再交换位置与头轴，成为 [B,H,T,d]，便可对每个头独立执行上一课矩阵关系。

头数不是免费增加能力。在总 D 固定时，更多头意味着每头维度更小；改变头数也影响注意力中间矩阵大小和实现效率。首先要求 D 能被 H 整除，其次才讨论效果。不要只因更大的模型使用更多头，就在小数据上无限增加。

拆头、转置与合头，最容易悄悄出错

多头权重形状是 [B,H,T,T]，每个 batch、每个头的每一查询位置都在可见候选上归一化。权重乘值后是 [B,H,T,d]；交换回 [B,T,H,d]，再把 H 与 d 合并，得到 [B,T,D]。最后的输出投影允许不同头的信息再次混合。

PyTorch 的 transpose 常返回共享存储但非连续布局的视图，直接 view 可能失败；工程在合头时显式 contiguous 后 view。使用 reshape 有时会自动复制，但不应该靠它掩盖轴语义错误。最有效的调试是在人工填入连续整数的张量上拆头和合头，确认最终能恢复原始排列。

把本课示例的 B、T、H、d 逐一改变，注意不要恰好让多个轴长度相同，否则交换错轴也可能在形状上蒙混过关。选择如 B=2、T=5、H=4、d=3 的不对称尺寸，通常更容易暴露代码的真实含义。

python
import torch
B, T, H, d = 2, 5, 4, 3
x = torch.arange(B*T*H*d).reshape(B, T, H*d)
heads = x.reshape(B, T, H, d).transpose(1, 2)
assert heads.shape == (B, H, T, d)
restored = heads.transpose(1, 2).contiguous().view(B, T, H*d)
assert torch.equal(x, restored)

残差连接为信息和梯度保留一条路

残差模块写成 x+f(x)，要求输入与分支输出形状相同。它允许模块在原有表示基础上学习一个变化，而不必每层都从头重建全部信息。若 f(x) 很小，主干仍接近原输入；反向传播时，导数中也包含直接经过恒等路径的部分。这提供了理解深网络训练的一条线索。

残差并不意味着每层只做微小改动，也不保证所有深度都稳定。分支尺度、初始化、归一化和优化器仍然重要。把残差删掉是有意义的消融，但不能同时改变学习率、层数和训练步数后把差异全部归给残差。比较条件必须可解释。

工程的 block 先执行注意力残差，再执行 MLP 残差，两次均保持 [B,T,D]。自回归约束要求残差分支也不能偷看未来；逐位置 LayerNorm 和 MLP 不跨时间混合，因果注意力负责允许的信息汇聚。完整 block 的因果性来自所有路径共同满足约束。

LayerNorm 沿哪一轴计算

对每个 token 的 D 维向量，LayerNorm 计算该向量内部的均值与方差，再用学习到的缩放和偏移调整结果。它通常不把不同样本混在一起，也不把完整序列所有位置一起归一化。这里区分得很重要：如果归一化统计跨未来位置，就可能破坏语言模型的因果性。

Pre-LN 把归一化放在注意力或 MLP 分支之前，然后加回未经过该次归一化的残差主干。Post-LN 则在残差相加后归一化。二者都叫 Transformer，但初始化梯度和训练行为可能不同。课程工程采用 Pre-LN，并在全部 blocks 后还有一次最终 LayerNorm。

归一化并不是数据集标准化。它作用于当前 token 的隐藏维度，参数随网络训练；菌群数据的训练集均值、零值处理和列筛选是另一层预处理。不要因为网络内部有 LayerNorm，就认为所有数据尺度与批次问题都已解决。研究中仍要分别检查输入处理和模型结构。

手算归一化时还要留意 epsilon：它加在方差相关的分母里，防止向量几乎常数时除以零。可学习的缩放与偏移分别有 D 个参数，因此一个普通 LayerNorm(D) 通常有 2D 个参数。不同实现可以关闭偏置或采用其他参数化，所以预算仍以实际代码为准。训练时的 LayerNorm 和 BatchNorm 行为也不同，不要因为名字相似就假设 eval 会改用一套跨样本统计。

MLP 对每个位置做什么

标准前馈分支通常把 D 维映射到较宽的中间空间，再经非线性映射回 D 维。工程使用 D→4D→D 和 GELU。它对各位置共享同一组权重，但每个位置独立计算，不像注意力那样直接混合不同 token。注意力负责跨位置组合，MLP 在每个位置上进一步变换组合后的特征。

若只有线性层堆叠而没有非线性，它们可以合并为一个线性变换，表达能力不会按层数自然增长。GELU 等非线性让输入依赖的特征变换更丰富。你不必第一天背下所有激活函数，但应知道它们放在哪里、是否改变形状，以及梯度如何通过。

小模型里 MLP 往往占据相当多参数。以 D=64、隐藏维256为例，两层权重共32768个，偏置共320个。只盯注意力头数而忽略前馈宽度，会误判模型预算。后续做压缩或消融时应先读参数表，针对实际占比决定实验。

三类 Transformer 架构回答不同问题

编码器常允许输入位置双向读取，用于分类、检索或掩码表征学习。解码器的自回归形式使用因果遮罩，逐步生成后续 token。编码器—解码器则先表示输入，再让输出序列通过自注意力和跨注意力读取输入。三种形式共享若干模块，却不共享全部信息流规则。

本课 TinyGPT 是 decoder-only。后面的菌群模型采用双向 encoder，因为同一样本的不同物种不是等待逐词生成的句子，重建被遮蔽物种可以利用所有可见物种。但它仍必须在输入端隐藏目标，不能因为用了双向注意力就把完整丰度直接交给模型。

讨论“微生物大模型”时，先明确是原始序列模型、丰度表基础模型，还是微生物文献语言模型，再选择结构和目标。三个方向都可能有价值，训练数据与评价标准却不同。CurateMicrobiota 主线从丰度表出发，语言模型部分负责让你理解机制与生成系统。

现代架构扩展：知道改了哪里

RoPE 将位置信息放入查询与键的旋转，上一课已给出原论文入口。RMSNorm 用均方根尺度归一化隐藏向量，不像 LayerNorm 那样进行相同的均值中心化。GQA 则让多组查询头共享较少的键值头，主要关联推理阶段键值缓存和计算预算。这些是可定位的结构变化，不是一个笼统的“升级按钮”。

当前 TinyGPT 主线使用可学习位置表、LayerNorm 和普通多头注意力，便于逐步检查。扩展练习一次只替换一个机制，先保持输入输出接口、参数记录和因果测试，再考虑训练对比。把多个前沿组件一次装进去却无法解释结果，会破坏课程建立的可诊断性。

读新模型论文时，给每项改动标记四件事：改变表示、改变训练目标、改变计算执行，还是改变数据与预算。它们的贡献不能互相替代。一个推理缓存优化可以让部署更快，却不会自动证明微生物预测更准确；较长上下文也不等于更可靠的科学证据。

给架构实验建立最小验收门槛

先在 eval 模式测试：构造两份只在后半段不同的输入，比较前缀 logits，应该在容差内一致。再检查不同输入长度不超过 context，超过时明确报错，而不是悄悄截断训练目标。读取 checkpoint 时，词表和结构应与保存配置一致；不能仅因张量数量相近就强行加载。

做一项有理由的消融，例如保持训练数据、步数、宽度和种子不变，比较一层与两层。记录参数量、训练耗时、验证损失和生成样本，并承认这只是小规模实验。只看训练损失更低无法判断增加层数是否值得；较小模型可能在有限数据和算力下更合适。

交叉熵到底在奖励什么

对某个位置，模型给真实下一个 token 的概率为 p，负对数损失就是 −log(p)。如果概率从0.1提高到0.5，损失从约2.303降到0.693；提高到0.9，损失约0.105。损失奖励把更多概率放到观察到的目标上，而不是直接衡量句子是否具有科学真理或证据充分。

整批损失通常对有效 token 的负对数概率求平均。不同长度样本若含padding，应只统计真实目标；否则大量简单填充会影响均值。对自然对数计算的交叉熵，单位是nats/token。本项目token是UTF-8字节，所以报告明确为nats/byte，不能只写一个没有单位的“loss”。

框架的cross_entropy通常直接接受logits，内部执行稳定的log-softmax。若先softmax再传进去，就把概率当作新分数又归一化一次，目标已不正确。手工例子用log概率作为logits可核对公式，因为这些分数经过softmax恰好恢复原概率。

L=−(1/N)Σ log pθ(yᵢ|允许的上下文)，N为有效目标token数
python
import torch
import torch.nn.functional as F
p = torch.tensor([[0.7, 0.2, 0.1], [0.2, 0.4, 0.4]])
y = torch.tensor([0, 1])

Teacher forcing 与并行训练

训练时每个位置读到真实前缀，称为teacher forcing。整段正确序列已知，所以可以一次前向为所有位置生成logits，同时用因果遮罩保证每个位置只读允许的前缀。生成时则把自己刚采样的token加入后文，错误可能逐步累积；训练和生成的上下文分布并不完全相同。

目标右移应该只做一次。工程sample_batch已经产生x=tokens[i:i+T]和y=tokens[i+1:i+T+1]，TinyGPT.forward直接将logits与targets展平计算损失，不能在模型里再移一次。重复移位会让模型预测隔一个token的内容，可能仍下降，却训练了错误任务。

Teacher forcing不是“把答案直接给当前预测位置”。输入包含后续真实token，但遮罩阻止当前位置读取它们。理解这个区别后，你才能判断哪种信息构成合法监督、哪种构成泄漏。数据、遮罩和损失三者必须一起审查。

一个优化步的顺序

先切换训练模式，读取一批输入与目标，前向得到损失；清理上一步梯度；反向传播；必要时裁剪梯度；最后调用优化器更新。清梯度也可放在前向之前，只要保证本步backward前没有无意保留旧梯度。记录日志时使用detach或item，不能把用于训练的loss替换为失去计算图的普通数字。

下面的例子使用工程真实模块，只完成一个教学更新。人工重复短句用于让数据长度足够，不用于验证语言泛化。clip_grad_norm_按整体梯度范数进行缩放，返回裁剪前范数；它不能修复目标错位或泄漏，也不是让所有参数梯度都相同。

训练后检查参数是否有变化只是最低要求。更有价值的是在同一小批次上尝试拟合、确认损失能明显下降，再换到独立验证数据。如果连极小样本都无法拟合，优先检查实现、学习率和数据接口；如果小样本拟合很好但验证恶化，问题可能转向过拟合或分布差异。

import torch

tokens = torch.tensor(ByteTokenizer.encode('Microbes form diverse communities. ' * 100))
x, y = sample_batch(tokens, batch_size=2, context=32)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)

AdamW、学习率与权重衰减

梯度下降用学习率控制每次更新幅度。Adam类方法保存梯度的一阶与二阶移动统计，对不同参数做自适应调整。AdamW将权重衰减与自适应梯度更新分离；它不是简单地把一个L2项加进目标，再假设与所有优化器里的衰减完全等价。

学习率过小可能使损失几乎不动，过大可能导致震荡或非有限值。权重衰减是一种约束参数规模的选择，不是防止过拟合的万能开关。数据量、架构、训练长度和验证方式仍然决定泛化。当前工程采用固定学习率0.001和权重衰减0.01，这是一组可跑通的教学配置，不是微生物任务的通用最优值。

实际大模型常按参数组决定是否对归一化、偏置等应用衰减。阅读代码时要确认真正传给optimizer的参数组，而不只看文章中的一个lambda。想改变策略，先保留原运行，记录新配置，在相同验证标准下比较，不能根据最终测试集反复选择。

学习率调度、warmup与稳定性

Warmup让学习率从较小值逐步达到计划峰值，随后可以保持不变或按余弦等规律衰减。它帮助控制训练初期更新，但不是所有小模型都必须使用。选择调度时，要明确横轴是优化器更新步、微批次还是已处理token，否则累积步数改变后实际学习率时间表可能错位。

工程主线先使用固定学习率，便于解释。下面只给一个独立可执行的调度函数，作为扩展练习，不声称CLI已经启用它。若接入训练循环，通常在恰当的优化器步之后更新下一步学习率，并保存调度状态。不同scheduler API的调用约定要按具体版本核对。

比较调度方法时保持总优化步和数据访问预算一致。看到更平滑曲线不必然意味着更好验证表现；也不要为了让曲线漂亮而删掉warmup阶段或异常点。报告完整训练区间，使别人能判断收益来自什么。

python
import math
def lr_at(step, total=100, warmup=10, peak=1e-3):
    if step < warmup:
        return peak * (step + 1) / warmup
    progress = (step - warmup) / max(1, total - warmup - 1)
    return peak * 0.5 * (1 + math.cos(math.pi * min(progress, 1)))
print([lr_at(s) for s in [0, 9, 10, 50, 99]])

梯度累积与有效批次

显存或内存限制微批次大小时，可以连续做多次前向反向，再执行一次优化器更新。若每个微批次含相同数量有效token，累积K次时将每次平均loss除以K，累积后的梯度对应这些微批次总体平均。清梯度要在一组累积开始前做，step和裁剪在累积完成后做。

如果各微批次的有效token数不同，简单除以K会给短批次和长批次相同权重，不等价于所有token平均。应按有效token总数加权，或累积总损失后按总token规范化。涉及padding与回答区间损失时，这一点尤其重要。分布式训练还要考虑跨设备的归约方式。

例如微批次B=2、T=32、累积K=4，在固定等长窗口下每次优化更新使用256个token。它不是每次前向处理8个样本，也不会完全复制所有随机层行为；dropout等使逐次计算与单大批次未必逐位一致。梯度累积改变预算单位，应在日志中同时记录微批次和优化步。

验证、模式切换与模型选择

model.eval改变dropout等模块行为，torch.no_grad或inference_mode停止记录梯度图，两者作用不同。只写no_grad而不eval，验证可能仍带dropout随机性；只写eval而不关闭梯度，通常会建立不必要的计算图。验证完成回到训练时，也要记得重新model.train。

工程在固定随机种子下从独立验证文本采样若干窗口估计损失，用验证损失选择检查点。这个结果是固定采样窗口的估计，不等同对整个文档逐token无重叠计算的精确负对数似然，也不是最终独立测试性能。保持相同评价窗口有助于比较，但不能把它解释得更宽。

选最优检查点本身使用了验证信息，因此报告中必须称其为验证结果。小语料可以用于学习流程，正式研究还需要更充足且独立的评价设计。调试阶段先把验证流程稳定下来，再考虑提高模型规模，避免把评价噪声当成训练改进。

训练曲线的四种常见信号

训练和验证都不下降时，检查输入目标是否错位、参数是否在optimizer里、loss图是否被切断、梯度是否为有限值，以及学习率是否过小。训练损失下降而验证升高，可能是过拟合，也可能是训练与验证分布或处理规则不同，应先确认数据一致性再调正则化。

若损失突然变为NaN或无穷，检查首次异常发生在哪一步，追踪输入、logits、loss和梯度。空有效目标、全遮蔽注意力行、过大学习率及数值范围都可能造成问题。不要把NaN替换成零继续跑，那会隐藏错误并改变训练目标。

如果训练与验证异常地同时接近零，尤其是在很少步数内，应检查泄漏和目标是否被直接复制。曲线太好也值得调查。每种现象写出两个候选原因，再设计能区分它们的小实验，形成诊断证据，而不是凭一条曲线下结论。

困惑度是怎样从损失得到的

若交叉熵使用自然对数且按有效token平均，困惑度PPL=exp(loss)。例如loss=ln4时，困惑度为4，可以把它理解为在该评价条件下平均预测不确定性的一个尺度。它不是“每次一定有四个候选”，也不是正确率，不能用1/PPL直接当作模型答题准确率。

PPL的单位依附tokenization。相同文本用字节、字符或子词切分，平均token损失定义不同，数值不能直接横向排名。比较两个模型至少固定语料、清洗、tokenizer、上下文处理和评分方法。跨编码比较可设计按字节等共同单位计算的度量，但必须实际实现一致评分。

评价长文本时，是否重叠窗口、每个token计分几次、窗口边界能看到多少上下文，都会改变结果。工程目前报告固定采样验证窗口的估计，用于教学模型选择。不要把这个估计直接标成完整独立语料上的最终语言建模基准。

PPL=exp(平均负对数概率)，仅在相同token与评价条件下直接比较

从最后一个位置取得下一token分布

训练输出[B,T,V]包含每个位置的候选分数；生成下一token只需要当前序列最后一个位置的logits，即logits[:,-1,:]。选出下一个token后把它拼到输入尾部，再重复。每次新增内容都会成为下一步上下文，生成可以因此逐渐偏离原提示。

贪心解码每次取最高分候选，过程简单、容易重复，但不保证整段文本概率最大，也不保证自然或正确。逐步最高概率路径不一定是序列整体最优，更不等于语义最优。Beam search等方法维护多个候选路径，但开放式文本生成也可能出现重复与单调。

本课先比较固定模型和固定提示，改变采样策略的效果。若同时改模型权重、提示和随机种子，就难以知道变化来自哪里。生成实验也要像训练实验一样控制条件，保存原始输出，不能只展示最好的一次。

Temperature 改变分布，不增加知识

对logits除以正温度τ，再softmax。τ小于1时分数差异被放大，分布通常更尖；τ大于1时差异被压小，分布通常更平。温度影响采样的不确定性，不会向模型加入新事实，也不能修复错误训练数据或缺失证据。

τ趋近零时，概率集中到最大分数候选；但直接令τ=0会除零，因此工程要求温度严格为正。若要确定贪心，单独使用argmax更清楚。工程top-k阈值采样在k=1且最大值无并列时等价于选最大项，若并列会保留并列项，仍可能采样。

下面给定同一组三个logits，比较三个温度。你应预测高温时低分候选概率增加，再运行核对。请把“更随机”“更自然”“更正确”分开记录；这些不是同一个评价维度。

import torch
logits = torch.tensor([2.0, 1.0, 0.0])
for temperature in [0.5, 1.0, 2.0]:
    p = torch.softmax(logits / temperature, dim=-1)

Top-k 与 top-p 分别截断什么

Top-k按分数保留最高的一组候选，再在保留集合重新归一化采样。k小会限制选择，k大更接近原分布；不同位置的概率形状不一样，固定k可能在某些位置保留太多低可信尾部，也可能在另一些位置过度限制合理选择。工程使用分数阈值实现，同分边界会一并保留。

Top-p也叫nucleus sampling，按概率从高到低排序，保留累计概率首次达到阈值p所需的最小前缀，再归一化采样。它每个位置保留的token数可以不同。达到阈值的那个候选也要保留，否则累计质量可能不足。这里p是累计概率阈值，不是“保留前p比例的词表”。

当前生成CLI主线提供temperature和top-k；下面的top-p是独立扩展练习，不把不存在的--top-p参数写入命令。将它接入工程前，应与现有采样测试一起检查合法范围、至少保留一个候选和概率归一化。

python
import torch
def nucleus_probs(logits, p=0.9):
    if not 0 < p <= 1:
        raise ValueError('p must be in (0, 1]')
    sorted_logits, order = logits.sort(descending=True)
    probs = sorted_logits.softmax(dim=-1)
    remove = probs.cumsum(dim=-1) > p
    remove[1:] = remove[:-1].clone()
    remove[0] = False
    kept = sorted_logits.masked_fill(remove, float('-inf')).softmax(dim=-1)
    result = torch.zeros_like(kept).scatter(0, order, kept)
    return result
p = nucleus_probs(torch.tensor([0.4, 0.3, 0.2, 0.1]).log(), 0.65)
assert torch.allclose(p, torch.tensor([4/7, 3/7, 0., 0.]))
print(p)

上下文裁剪与缓存，影响什么

模型只接受不超过context的位置数。当前生成实现每一步取最近64个token作为输入，重新计算窗口内全部表示；更早内容从输入中退出，因此不能期待模型无限记住开头。若提示中重要限定早已被裁掉，后续生成不再直接看到它，这是一种明确的上下文边界。

KV缓存保存先前位置的键和值，减少自回归推理中重复计算，但它不会自动扩大模型学过的上下文，也不是持久知识库。缓存是否正确还涉及位置编码、窗口策略和批次管理。本工程没有实现KV缓存，代码的重点是让逐步生成完全可见。

长上下文、外部检索和持久记录解决不同问题：长上下文让更多信息同时进入一次前向；检索决定哪些外部材料进入；持久记录保存跨会话的数据。设计微生物助手时可以组合这些能力，但仍要单独检查召回、引用和信息是否超出模型可见范围。

字节模型生成的特殊问题

UTF-8字节token保证原始有效文本可以编码和还原，但模型采样的是任意字节序列，未必始终满足UTF-8编码规则。工程decode使用errors='replace'，遇到非法或不完整序列会出现替代字符。这个字符是解码处理结果，不表示词表中有一个掌握了特殊语义的未知词。

英文教学短文以单字节字符为主，早期生成更容易出现单词碎片和无意义拼接。中文或其他多字节文字需要模型学习更长的字节组合，小数据下尤其困难。生成80个byte token并不一定是80个可见字符，报告长度时要区分两者。

不要为了让演示好看，把模型输出偷偷换成预写回答。可以同时展示原始字节、解码文本与失败说明，指出未来改进可来自更合适的tokenizer、更充分语料和训练预算。真实展示局限，比把一个教学模型包装成科学专家更能证明你理解了它。

怎样比较采样，不挑最好的一次

固定检查点、提示、最大新增token数，建立三组条件，例如温度0.5/0.8/1.2且top-k固定40；再固定温度0.8，比较k=1/10/40。每组使用事先指定的多个seed，保留全部输出，观察重复、可读性、提示保持和无依据事实。小模型可能三组都不理想，这也是结果。

评价记录应同时有自动统计和人工观察。重复片段比例、非法字节替代字符数量或长度只是局部指标；低重复也可能来自完全随机字符，不能单独代表质量。科学事实问题需要证据标注与正确性评价，不能用文本流畅度替代。

昨天的小型语言模型学会了根据前文预测后文。今天要解决的问题变成：给定一项任务，它能否按要求输出合适的答案？预训练、领域继续预训练、监督指令微调和偏好优化改变模型的方式不同。预训练从大量文本学习统计结构；领域继续预训练仍可使用下一词预测目标，只是语料转向某一领域；监督微调给出任务与示范答案；偏好优化利用同一问题下回答优劣的比较。把微生物论文放入语料，并不自动获得可靠的研究助手。

在CurateMicrobiota中，语言侧用于练习文本建模、答案监督与证据整理，微生物编码器用于丰度表表示学习。本课先运行低秩线性映射实验，再可选地对已经训练的TinyGPT执行全量SFT和LoRA-SFT，真实检查哪些参数改变。它们仍是小型教学任务，不等同于经过独立评价的微生物研究助手。你需要判断一个需求是在补知识来源、纠正输出格式，还是改变样本表示；这个判断决定使用检索、微调或新的预测模型。

把指令样本写成可以核验的数据

一个指令样本至少包括任务、输入材料、示范回答和来源。任务应具体，例如“从给定摘要提取研究设计、受试者、微生物检测方式和关联方向”。输入材料是模型作答的证据范围，示范回答遵守统一字段规范。缺失字段使用明确的空值与缺失原因，不能凭领域常识补齐。原文只报告横断面相关时，答案不能写成因果效应；只有体外实验时，不能提升为人群治疗结论。这些约束需要落实到样本，而不仅写在提示词中。

整理数据时先按论文或独立研究划分训练、验证和测试，再对各自文档切片。来自同一论文的摘要、方法片段、问答改写不能分散到不同集合。逐条记录 DOI、样本来源、文档版本、整理者与核验状态。合成指令可以用来验证格式流程，但它的正确性和多样性需要人工检查，也不能充当独立测试的事实依据。今天先手工做五条高质量样本：两条完整提取、两条字段缺失、一条证据不足；每条保留一段能支撑答案的原始材料。

只在答案位置计算损失

指令微调通常把提示和回答连接成同一条序列。模型仍进行因果预测，但优化目标可以只覆盖回答部分：提示词参与注意力计算，作为回答的条件；提示位置的标签设为忽略标记，使它们不贡献目标损失。需要仔细区分“预测发生的位置”和“被预测 token 的位置”。预测第一枚答案 token 的 logits 来自前一个位置，若掩码没有与右移标签同步，就可能把第一枚答案漏掉，或者错误训练提示末尾。

下面的独立短实验不依赖项目内部类，可以在 VS Code 新建 Python 文件运行。前两枚 token 表示提示，后两枚表示回答。右移后的目标中，仍属于提示的标签设为 -100。验收时逐个打印目标 token、位置和是否计分。多轮对话还需要精确标识每个 assistant 片段；截断、padding、打包多条样本都可能改变边界。某个批次没有有效答案 token 时应跳过或报错，不能让除以零产生的异常悄悄进入训练。

python
import torch
import torch.nn.functional as F
torch.manual_seed(8)
ids = torch.tensor([[2, 3, 4, 5]])
answer = torch.tensor([[False, False, True, True]])
logits = torch.randn(1, 4, 8, requires_grad=True)
target = ids[:, 1:].clone()
target[~answer[:, 1:]] = -100
loss = F.cross_entropy(logits[:, :-1].reshape(-1, 8), target.reshape(-1), ignore_index=-100)
loss.backward()
print("shifted labels:", target.tolist())
print("scored answer tokens:", int((target != -100).sum()))
print("loss:", float(loss.detach()))
assert target.tolist() == [[-100, 4, 5]]
assert logits.grad[:, 0].abs().sum().item() == 0
assert logits.grad[:, 1:3].abs().sum().item() > 0

LoRA：学习权重改变量的低秩分解

设一层线性变换的权重 W 有 d_out 行、d_in 列。全量微调直接修改这 d_out×d_in 个元素。LoRA 冻结 W，另外学习 A 与 B，使权重改变量写成缩放后的 BA。A 把输入投影到较低的 r 维，B 再映射回输出维度。这样新增的可训练参数为 r×(d_in+d_out)，当 r 远小于输入和输出维度时，可以大幅减少优化器需要维护的状态。低秩约束是对改变量的结构假设，并不是声称原权重本身只有很低的秩。

以输入输出均为 64、秩为 4 的线性层为例，不含偏置的全量权重有 4096 个参数，LoRA 两个矩阵合计 512 个。实际显存还包含底座、梯度、优化器状态和中间激活，不能把可训练参数缩小八倍直接解释为总显存缩小八倍。常见初始化让一个矩阵随机、另一个为零，使初始增量为零。若 A 和 B 同时设为零，两者的梯度可能同时为零而无法启动学习；这个细节非常适合作为本课的故障实验。

W_eff = W_0 + (alpha / r) B A；A ∈ R^(r×d_in)，B ∈ R^(d_out×r)

看懂本地 LoRA 实验到底证明了什么

运行项目提供的 lora-demo，记录冻结参数量、可训练参数量、初始损失、最终损失和输出位置。先确认优化器只接收需要更新的参数，再比较运行前后的底座权重。正确实验应同时满足：底座没有改变，至少一部分低秩参数改变，损失计算和反向传播能够完成。损失下降只是说明该实验目标可以被拟合，不代表模型已经获得微生物研究知识，更不能据此给出问答准确率。

选择全量微调、冻结探针还是低秩微调

当数据很少时，先冻结已有编码器，只训练一个简单的预测头，是识别表示价值的便宜办法。若冻结表示无法适应目标分布，可尝试逐层解冻、全量微调或低秩更新。它们的比较必须使用同一训练和验证划分、同一评价任务以及清楚的预算。模型参数更少不必然泛化更好，更新参数更多也不必然带来收益。小样本下训练损失持续改善而验证性能下降，往往意味着需要更早停止或更强的约束。

微生物丰度编码器和语言模型可以使用相同的参数高效思想，但输入、任务头与损失不同。不要把语言模型常用的目标层名称直接复制到另一个网络而不检查模块结构。当前语言模型已经提供SFT与LoRA-SFT；后续丰度工程实现的是直接数值基线和冻结编码器探针。从零监督、全量菌群微调和菌群LoRA仍是研究拓展，需使用严格外测比较，才能区分表示本身有用与重新训练后有用。

QLoRA 与量化：存储精度不等于计算精度

量化用较少比特表示权重，通常还需要缩放因子或码本。QLoRA 将量化后冻结的底座与可训练低秩适配器结合；参与矩阵乘法时的计算精度、适配器精度和权重存储精度可以不同。理解这三个层面，才能避免“所有参数与梯度都在四比特里训练”这样的错误表述。低比特表示节省的主要是部分存储开销，激活和优化器仍会占用内存，长上下文也可能成为显存瓶颈。

这一节是进阶阅读，不作为普通 CPU 环境的安装必选项。真正运行量化微调之前，需要核对硬件、软件支持、底座许可证、目标模块和训练精度；然后与未量化的小规模参考运行比较输出和任务指标。当前课程的 LoRA 演示不依赖下载大权重，也不包含已经验证的 QLoRA 训练结果。你应在学习记录中画出“量化底座—高精度低秩分支—任务损失”的关系，并说明哪部分冻结、哪部分更新、哪部分在推理时保存。

RLHF 与 DPO：偏好数据如何改变回答

监督微调告诉模型怎样回答，偏好优化比较同一问题下哪份回答更符合评价标准。典型 RLHF 路线会先学习偏好相关的奖励模型，再优化语言模型的策略，同时限制它偏离参考策略过远。DPO 使用成对偏好和参考模型概率构造直接优化目标，通常不需要另行执行同一套在线强化学习采样与奖励模型训练流程。二者都依赖偏好数据的质量；标注者喜欢一个答案，不代表其中每个科学事实都正确。

为CurateMicrobiota写一对偏好示例：好答案准确指出样本、设计和证据局限；差答案把横断面关联写成治疗效果。比较时尽量避免把更长或术语更多当成好答案的代理标准。alignment-demo在固定合成序列对数概率上真实计算DPO损失和梯度，使用回答词元对数概率之和而非默认按长度平均，参考项冻结；它没有更新真实语言模型、训练奖励模型或执行完整RLHF。

附带公式实验初始损失约0.6664，提高chosen相对rejected的优势后变为0.64715。chosen对数概率的梯度为负、rejected为正，因此梯度下降会朝相应偏好方向推动这组变量。理解这一计算有助于检查实际DPO实现，但把两个标量方向改对，不等于模型已经学会正确科研回答。真正偏好训练还需要独立数据、参考模型与任务评价。

L_DPO = -log sigmoid(beta × [(log πθ(y+|x) - log πθ(y−|x)) - (log πref(y+|x) - log πref(y−|x))])

怎样证明微调真的改善了任务

建立三组独立测试：结构化提取是否匹配人工核验字段、来源证据是否支持答案、材料缺失时是否能够保持空值或说明未知。模型输出是否符合 JSON 格式，只覆盖了语法层面的正确性；字段内容是否准确、是否引用正确研究，是另外两层。报告每层的分母，列出失败案例，并按文档、研究类型或任务类别分组。一个平均分不能说明模型在所有子任务上都可靠。

必须保留微调前的底座输出作为对照，并控制提示词、检索材料与生成参数。若同时更换底座、增加文献库和微调，性能变化不能归因于单一因素。测试材料不得出现在监督样本、生成指令的示例库或人工调参循环中。对于非常小的测试集，结论写成“在该批任务上的观察”，并同时报告原始正确数。当天至少检查一条模型变好的例子和一条变差的例子，练习分析遗忘、格式过拟合与不适当自信。

证据检索要解决的具体问题

当你问“这个微生物模型是否经过跨研究验证”时，答案需要一个当前可查的来源，而不只是语言模型参数中的模糊记忆。检索模块先寻找有关材料，回答模块再根据这些材料组织输出。检索增强生成的重点在于为回答提供可更新、可追溯的外部条件。它能够帮助研究者找到依据，但不能保证检索结果完整，也不能保证生成器忠实阅读。每个环节都需要单独检验。

今天的 CurateMicrobiota 提供本地证据检索与来源展示基线，能够在没有外部模型服务的条件下练习问题、来源和证据之间的关系。课程整理的来源卡片是教学摘要，不是自动下载的论文全文。若尚未接入生成器，应将结果称作检索证据或模板式摘要，不能把它包装成已经运行的生成式大模型。未来接入本地或远程生成器后，仍保留相同的证据接口与评价集合，这样可以判断改进究竟发生在检索还是生成。

先定义一个可追溯的证据单元

每个证据单元至少包含稳定ID、标题、来源URL、发表或更新时间、材料类型、内容以及内容在来源中的位置。材料类型可以是原始研究、官方方法文档、综述或课程整理卡片。相同内容的不同版本要记录关联，防止同一研究被当作多项独立证据。微生物研究还应保留样本类型、物种或功能层级、数据处理版本、研究设计和结局定义，方便判断一个结论的适用范围。

对卡片进行核验时，把每一句事实归回具体来源。官方软件文档能证明某个参数怎样工作，不能自动证明该软件对疾病具有预测效力；论文能报告作者的数据结果，也不等于结果已经在你的队列复制。一个关于属水平模型的段落，不能不经转换就用于证明物种级模型具有同样性能。今天手工整理三张卡片：数据资源、方法研究、评价方法。每张卡片写出能支持的命题与明确不能支持的命题，训练证据边界意识。

分块：保证事实和限定条件留在一起

文档分块是为检索建立粒度，不是机械地按固定字符数剪开。过短的片段可能只剩一个结果而丢掉样本、否定词、统计条件或研究限制；过长的片段又会引入大量无关内容，降低匹配精度并占用上下文。起步可以按标题和自然段拆分，再限制每块长度，并保留适度重叠。长度阈值需要在开发问题集上比较，而不能先看最终测试答案再挑选。

微生物论文中的表格、图注和方法信息尤其容易被切散。若结论写在结果段，样本范围写在图注，你需要把关联信息作为元数据或相邻块一起返回。数值不能离开单位与分母，例如“准确率90%”至少要知道对应多少样本、什么划分、怎样定义类别。PDF解析也会把列顺序、上标和特殊符号弄错，所以索引前应抽查原文。下面短代码只是分块边界练习，不是通用PDF解析器；请尝试不同块长，观察限定条件是否完整。

python
def chunks(text, size=80, overlap=20):
    if not 0 <= overlap < size:
        raise ValueError("overlap must be smaller than size")
    step = size - overlap
    return [{"start": i, "end": min(i + size, len(text)), "text": text[i:i+size]}
            for i in range(0, len(text), step)]
text = "研究仅纳入成年粪便样本。模型在同一研究内交叉验证；尚未在独立研究验证。" * 3
for row in chunks(text):
    print(row)
assert all(row["text"] == text[row["start"]:row["end"]] for row in chunks(text))

先做词项检索，再理解向量检索

词项检索把问题与文本中的词或字符联系起来，适合精确术语、物种名、DOI和软件参数。向量检索将问题和片段编码成稠密表示，按相似性寻找语义接近的内容，但相似不意味着事实支持。同义表达可能改善召回，物种名拼写、近缘分类单元和数字条件也可能被混淆。一个可用系统往往需要比较词项、向量和混合策略，而不是假设向量方法必然更好。

对当前小型课程证据库，先观察本地实现实际使用的匹配规则。用三个版本提问：中文描述、英文术语、带资源名的精确问题。记录返回ID和顺序，解释为什么某种写法没有找到内容。新增向量检索时，应记录嵌入模型及版本、归一化方法、相似度函数与索引配置。若更换嵌入模型，需要重新建立相应索引；把不同模型的向量直接混在一起比较通常没有明确意义。检索器训练也不能使用最终测试问题的答案作为反馈。

重排与上下文：更多材料未必更好

召回阶段追求尽量找到相关候选，重排阶段再综合问题与片段判断优先级。一个简单策略先取较多候选，再去除重复、保留方法或原始结果来源，并筛选与问题条件匹配的材料。不要把同一篇论文的相似片段堆成看似丰富的多来源支持。对于冲突证据，应保留差异而不是仅选与预期结论一致的一方；疾病、样本类型、处理流程不同，可能正是冲突的原因。

语言模型能够接收很长上下文，并不等于对每个位置都利用得同样充分。加入生成器后，可以把同一证据分别放在上下文开头、中间和末尾，比较回答是否保留限定条件。还应固定总长度，防止将位置实验与长度实验混在一起。课程的检索基线不宣称完成重排大模型或长上下文实验；本节给出的是下一步应怎样设计比较。当前先实现人工去重和证据排序表，练习在有限阅读预算中保留最关键、最独立的证据。

引用核验要检查四层关系

第一层是来源存在：URL或DOI能否指向真实材料。第二层是定位正确：所引段落是否真的出现在该来源。第三层是命题支持：段落是否支持答案附近的具体说法，而不是只与主题相关。第四层是覆盖完整：答案中需要依据的关键断言是否都有证据。引用数量越多不一定越可靠，同一个来源支持多个命题时需要逐项确认，不能用一串链接替代核验。

为研究助手设计一张逐句表：答案断言、证据ID、对应原文、适用范围、核验结论。只写“相关”不足以判通过。例如来源报告某模型在特定外部队列取得结果，答案扩成“能泛化到所有精神疾病”，即使链接真实也不成立。若来源只是一张课程摘要卡，进一步研究时应打开原始论文或官方文档确认。生成器不得创造不存在的证据ID；输出中出现库外ID时，系统应标为错误而不是自动生成一个看起来合理的链接。

把检索质量与回答质量分开计分

检索层可以用Recall@k、Precision@k和MRR等指标。Recall@k关注人工相关证据中有多少进入前k；本课Precision@k固定用k作为分母，少返回的槽位也不记命中。单题的倒数排名RR关注第一条相关结果的位置，多题RR平均才得到MRR；代码报告的是截断到k的RR。计算前必须定义相关性：询问参数行为时，直接官方说明通常比泛泛介绍更相关。不存在答案的问题不应强行安排相关文档，应另外评价错误召回与缺证处理。

回答层另外评估事实正确、引用支持、引用覆盖、结构格式和是否适当说明缺证。不能拿检索召回率当作问答准确率，也不能用模型自评替代所有人工核验。下面用一个小列表演示检索指标的分母，其中相关集合由人事先确定，返回列表没有重复ID。正式实验要在多个问题上计算并报告分布，保留零相关或无答案问题的处理规则。如果两个人对相关证据不一致，先讨论准则，再固定标签。

python
def retrieval_scores(ranked, relevant, k):
    if k < 1:
        raise ValueError("k must be positive")
    if len(set(ranked)) != len(ranked):
        raise ValueError("duplicate evidence IDs")
    relevant = set(relevant)
    top = ranked[:k]
    hits = [x in relevant for x in top]
    precision = sum(hits) / k
    recall = sum(hits) / len(relevant) if relevant else None
    rr = next((1.0/(i+1) for i, x in enumerate(top) if x in relevant), 0.0)
    return {"precision_at_k": precision, "recall_at_k": recall, "reciprocal_rank_at_k": rr}
print(retrieval_scores(["A", "C", "B"], {"B", "C", "D"}, 3))
assert retrieval_scores(["A"], {"A"}, 3)["precision_at_k"] == 1/3
# 完整列表示例：precision=2/3，recall=2/3，RR@3=1/2；跨题平均RR得到MRR。

结构化输出与工具调用的边界

研究助手的结构化输出应有明确模式，例如问题、结论、证据列表、缺失信息和下一步核验。语法校验检查字段类型与必填项，语义校验检查证据ID属于检索结果、数值和单位一致、结论强度与研究设计匹配。不要把“模型输出JSON”理解为“结果可以直接写入正式数据库”。写入前需要独立的核验状态，遇到冲突时保留来源而不是覆盖掉另一份记录。

工具调用只是把明确参数传给一个受限功能，例如检索证据、读取评估报告或计算指标。工具返回的内容仍是数据，不是可以改写系统任务的命令。文献中若出现“忽略原规则”或任意脚本指令，应按普通文本处理。课程的本地证据查询不需要外部账户或秘密凭证；未来接入远程模型时，密钥不能放到网页前端、公开代码或训练样本中。工具执行与模型生成分离，有助于把可验证计算留给确定性代码。

四份文件建立最小数据契约

课程工程读取 abundance.csv、metadata.csv、split.json，并用来源说明记录数据出处。丰度表一行一个样本，第一列为sample_id，后续列是唯一且非空的物种标识。元数据至少包含sample_id、study、subject_id与label。label在本工程中使用0、1或空值：空值可用于未标注预训练样本，不能悄悄解释为健康。split.json把每个研究完整分配到train、val或test，不能重复，也不能遗漏。

输入丰度采用比例而不是百分数或测序计数，单行总和应为正并处于合理范围。保留部分物种后总和可能小于一，这并不自动构成错误，但必须知道保留了多少组成质量。特征名称缺失与测量为零不同：前者可能意味着检测面板或版本不匹配，不能默认补零。元数据读入后按样本ID精确对齐，不能依赖文件排序。任何重复样本ID、重复物种列、负数、非有限值或缺失研究标识都应明确报错。

标签必须来自预先写下的任务定义

如果任务是区分某一疾病与健康对照，应明确疾病定义、排除条件和健康标签的原始取值。把“不是该疾病”的所有样本都设为健康，会把其他疾病、未知状态和治疗后样本混进对照组。标签还可能受到采样时期、部位、年龄、用药和纳入标准影响。今天建立一张映射表，包含原字段、原值、目标标签、纳入或排除理由；映射表在看模型结果之前固定。

研究划分与受试者划分是两层约束

样本ID识别一行记录，受试者ID识别可能重复采样的人，研究ID识别采集和处理环境。随机按行划分时，同一个人的不同时间点可能同时出现在训练和测试中，模型因识别人而得到过于乐观的分数。研究外测进一步要求某个研究的全部样本留在外部；这有助于检验对不同研究环境的转移，但也可能同时改变人群、检测和标签分布，所以必须描述这些变化。

对公开数据可使用study_name与本地sample_id组合成稳定样本键，用study_name与subject_id避免不同研究重复编号造成的碰撞。不过，命名空间不能替代真实重复调查：若同一受试者被不同论文或资源重复使用，还需通过可用的原始项目与样本信息建立统一映射。subject_id缺失时应报告，不能直接把每行当作一个已证实独立的人。课程工程会检查研究分配和受试者交集，真正资料仍需在导出前完成这层数据审查。

组合性：相对增加不等于绝对增加

相对丰度受到总和约束。假设某样本只有两个物种，一个从10个单位增加到20个，另一个保持10个，后者的绝对数量没有变化，相对丰度却从二分之一变成三分之一。因此，模型看到相对丰度下降，不能直接解释为该物种绝对减少。CLR等对数比变换帮助表达组成中的相对关系，但需要处理零值，并且结果受所选成分集合影响。任何变换都不自动恢复没有测量的绝对微生物负荷。

本工程的微生物预训练使用逐物种log1p与训练集统计量，作为易检查的教学实现；它并不声称解决所有组合性问题。后面会把CLR加逻辑回归作为独立基线，并讨论不同处理的敏感性。特别注意：在掩码任务中，完整样本的CLR中心包含将要遮蔽的目标，先CLR再遮蔽可能泄漏目标信息。今天先把输入单位、是否闭合、是否截取物种与保留质量写清楚，明天才能理解为什么损失函数与预处理必须共同设计。

零值、未测量与稀有特征分别处理

一个零可能代表真实缺失，也可能是低于检测能力；一个空白列可能表示该特征根本未测量或无法映射。它们不应该全部被同一常数替代。训练前需要区分数值零、缺失值、未知物种和低质量样本。对数变换不能直接接受零，伪计数或log1p是可用的处理选择，但其数值会影响小丰度成分。应在训练域内比较合理设置并记录，不应在测试集上挑出最有利的伪计数。

prevalence过滤的阈值、最多保留物种数和特征排序都在训练样本上拟合。验证与测试仅应用已经确定的词表和缩放量；即使过滤过程不使用疾病标签，借助测试分布选择特征仍改变了严格外测的设置。若新数据缺少训练词表中的物种列，默认应该停止并检查映射。只有明确知道它是同一检测体系中的未检出，才可讨论补零，并同时报告该假设和保留丰度质量。

版本、资源和许可进入实验清单

可复现的数据清单不仅写下载日期，还包括资源名称、包版本、分析流程、原研究出处、筛选条件、标签映射、导出代码版本与输出文件校验值。curatedMetagenomicData可返回不同运行日期对应的资源，默认选择行为不应被当作永久固定。第一次真实下载后，将本次资源名与实验清单一同保存，避免未来更新包后悄悄改变输入。合并资源时出现的物种丢弃或树映射警告，也应进入日志。

软件许可证与来源研究数据使用条件不是同一个问题。包的软件许可证不能被直接解释为所有样本都允许任意再次分发。课程提供导出接口，学习者从官方渠道获取资料并保留引用；如果将来发布真实子集，需要核查来源的使用条件。演示数据则有独立、明确的合成说明，不带真实个人信息。今天的目标是形成能让别人检查输入来历的最小清单，而不是为了界面漂亮省略这些关键事实。

把语言模型思想迁移到微生物组成

一个样本的物种丰度不是一句自然语言，但也具有上下文：同一物种在不同群落里可能代表不同生态背景。自监督表示学习尝试在不依赖疾病标签的条件下，从训练样本中学习这种共同变化结构。本课选择随机隐藏部分丰度，让模型根据可见成分重建隐藏的数值。训练得到的样本表示，下一课再交给简单分类器或微调任务，检验它是否比直接丰度更有用。

这里的“微生物模型”输入是样本×物种的数值表，输出是隐藏丰度预测与样本向量。它不直接阅读DNA序列，不自动生成可培养菌群，也不能从注意力权重断定物种相互作用。迁移的是注意力、表示和预训练思想，而不是把所有生物数据强行改成句子。你需要同时回答三个问题：输入表示是否符合数据性质，任务是否能避免明显捷径，学到的表示是否在独立研究有实际价值。

物种身份、丰度与人为遮蔽分别编码

每个物种token由身份和数值两部分组成。身份嵌入回答“这是哪个物种”，数值映射回答“它在这个样本中处于什么丰度水平”。对被遮蔽的位置，工程用专门的mask向量替换整个数值表示，同时保留物种身份，这样模型知道自己正在重建哪个成分。若只把被遮蔽数值设为零而没有额外标识，模型就会把人为隐藏与真实未检出混淆；如果替换不完整，还可能残留目标信息。

代码中的taxon_embedding、value_embedding与mask_embedding分别对应这三件事。原始零经过逐物种变换和训练集标准化后，不一定仍是数值零；标准化后的零通常表示训练均值附近。因此，本课的mask标志必须独立于数值。词表与其顺序保存在预处理文件里，推理时按身份对齐，不能把同样长度的另一张矩阵直接塞进去。这个设计也说明：某个真实物种从未进入训练词表时，需要明确的未知特征策略，不能假装它已有学好的身份嵌入。

没有任意序列位置的双向注意力

在句子里，词序会改变含义，所以TinyGPT需要位置机制和因果遮罩。在丰度表中，CSV的第一列物种通常没有天然先于第二列物种的生态含义。本课因此不加入任意列位置编码，允许可见成分之间双向交流。把物种ID、丰度和掩码一起重新排序时，每个物种对应的输出应随之重新排序，而平均汇聚的样本表示应保持不变。这叫对物种排列的等变性与样本表示的不变性。

这种性质并不表示物种身份不重要。若只调换丰度却不调换ID，就是把一个物种的数值错配给另一个物种，预测当然可以改变。测试排列不变性时必须同时移动这几部分，并切换到eval关闭dropout的随机性。课程实现使用标准双向自注意力与平均汇聚，不等于完整复现Set Transformer论文中的所有结构。你应学习它对集合数据的思路，同时精确描述自己代码实际实现的部分。

逐元素变换与目标信息泄漏

工程先把比例按固定公式log1p变换，再用训练研究估计的每物种均值与尺度标准化。这种变换逐元素进行，不使用当前样本其他物种的值来构造某个输入，因此在随后完全替换被遮蔽物种的数值表示时，不额外通过样本中心传播目标。它与“先对完整样本做CLR再遮蔽”不同：CLR中心包含所有成分，隐藏目标可能已经进入可见成分的变换结果。判断泄漏要跟踪每个输入到底依赖哪些原始量。

这个选择仍然不能消除原始相对丰度自身的组合约束。只遮一个成分时，总和接近一可能让任务几乎变成减法。工程每个样本至少遮两个，并保留一部分可见成分；这是降低明显捷径的措施，不是对所有捷径的证明。更严格的研究可比较先遮蔽后重构可见组成、不同目标表示及组成约束插补基线。当前结果必须说明损失是在标准化对数比例空间里计算，并且仍受到零值、组合依赖与研究差异的影响。

z_ij = [log(1 + 10^6 p_ij) - μ_j(train)] / σ_j(train)；被遮蔽位置的数值表示完全替换为mask向量

从张量形状理解前向传播

假设批次有B个样本、词表有T个物种、隐藏维度为D，输入数值形状为B×T，编码后为B×T×D。注意力将其映射成Q、K和V，再按头拆分；每个头计算T×T的关系权重并聚合上下文。残差连接让原信息可以直接传递，归一化稳定层间数值，前馈网络在每个物种位置进一步变换。最后的重建头把每个位置压回一个标量，平均汇聚则输出B×D的样本表示。

默认工程使用小尺寸配置，目的是在CPU上读懂并运行完整路径。读实现时不要只看类名，逐行记录view、transpose和mean到底作用于哪个维度。头数必须整除隐藏维度，词表数变化也会改变身份嵌入的尺寸。物种数变大后注意力矩阵按平方增长：增加样本量与增加每个样本的物种数，计算代价并不相同。扩展到数千物种之前，应先测量内存与时间，而不是只增加一个配置数字。

损失只在隐藏目标上计算

若让所有物种都贡献重建损失，大部分可见位置可能通过复制输入获得很低误差，掩盖模型没有学会预测隐藏成分的问题。本课只选择mask为真的目标计算均方误差。目标保留原始的变换后数值，输入路径则隐藏这些值。每个批次必须至少存在一个有效目标，掩码形状、dtype和预测形状应一致；这些检查能防止广播或空掩码造成的静默错误。

均方误差会受到目标尺度和零值比例影响。训练均值插补在标准化空间中对应预测零，是必须提供的简单对照；模型低于它的误差说明学到了一些超出平均水平的条件信息，但仍不代表获得了疾病判别能力。报告可以同时给出模型误差、均值插补误差、遮蔽数和相对误差降低。真实研究还应按原丰度区间、出现频率和研究分别分层，检查总体改善是否只来自大量容易预测的零或常见物种。

L_mask = Σ_(i,j: M_ij=1) (z_hat_ij - z_ij)^2 / Σ_(i,j) M_ij

训练、验证与模型选择各有职责

预训练只从train研究抽取批次和随机掩码。验证研究使用预先固定的掩码比较候选训练步，避免每次评价目标不同造成曲线难以解释。工程保存验证表现最佳的权重，也允许最佳步仍为初始状态：若训练没有带来改善，应如实保留这一结果，而不是强迫选择一个看起来更像“训练成功”的checkpoint。测试研究不用于优化、选词表或选择训练步。

固定验证掩码便于教学复现，但长期反复尝试可能对这组掩码形成间接过拟合。正式研究可预先设置多个固定掩码种子，并在训练域内完成选择。训练日志至少记录步数、训练批次损失、验证重建、均值基线和用时，保存配置、词表、数据校验值与随机种子。损失出现NaN时先检查输入和梯度，损失完全不变时检查参数是否在优化器中，验证恶化时再讨论学习率、容量与过拟合。

受试者层面的评价与重复测量

演示数据每名受试者有两次记录，若将四十条测试记录全部视为四十个独立人，就会错误放大有效样本量。当前工程的主评价先对同一受试者两次预测概率取平均，再得到二十名受试者的指标；样本层面结果作为补充。监督训练还让每个受试者的总权重相同，避免拥有更多访视的人自动占据更大影响。聚合方式是任务定义的一部分，需要事先固定。

这个规则只适合标签在受试者内稳定且目标就是受试者分类的场景。如果你要预测每次访视的状态变化，或者同一人的标签随时间改变，就不能机械平均并沿用同一个分数。应该定义时间窗口、预测时点和纵向模型，并在受试者或未来时间上划分。课程程序遇到同一人标签变化会报错，提醒你任务不满足现有假设。真实研究中，患者数量、记录数量和研究数量应该同时出现在结果说明里。

AUROC与精确率召回指标描述不同问题

AUROC评估正例相对于负例的排序能力，不依赖某一个概率阈值，但不直接告诉你预测概率是否准确，也不直接反映实际筛查中的阳性预测值。精确率和召回率分别关注预测阳性中有多少是真阳性、所有阳性中找回多少。阳性比例不同会显著改变精确率相关指标，因此跨队列比较时必须报告患病比例或样本构成，不能只展示一个汇总AUC。

工程使用average precision，简称AP，作为精确率召回曲线的汇总；它与用梯形法计算的PR曲线面积不是同一个实现，报告中应写清楚。无信息预测的参考水平与阳性比例有关。类别只有一种时，AUROC没有定义，应返回缺失并说明原因，而不是补成零或一。固定阈值0.5下的F1、平衡准确率和混淆矩阵是另一层信息；若要选择其他阈值，只能在训练或验证域按明确目标选择。

校准：排序好不等于概率可信

一个模型可能总能把阳性排在阴性前面，AUROC很高，却把大多数人的风险都估得过高。校准关注预测概率与观察频率是否匹配。Brier分数计算概率与标签平方误差的平均，越低通常越好；校准分箱把相近预测概率放在一起，比较平均概率与实际阳性比例。ECE把各箱的偏差按样本量汇总，但它依赖分箱方式，也会在小样本下很不稳定。

本工程报告五个等宽分箱，只有二十名测试受试者时，某些箱可能只有一人甚至没有人，因此图形只用于教学检查，不应形成精细校准结论。正式应用可以在独立验证材料上拟合概率校准，再冻结后测试；不能用测试标签校准并在同一批数据报告“改善”。如果训练使用人为平衡的病例对照采样，输出概率也不能自动解释为实际人群风险，因为目标人群的阳性比例与选择机制可能不同。

Brier = (1/n) Σ_i (p_i - y_i)^2；AUROC主要描述排序，校准描述概率与观察频率的一致程度

置信区间必须对应正确的独立单位

bootstrap通过重复抽样观察指标在样本扰动下的变化。存在重复访视时应以受试者为抽样单位，而不是把每条记录独立重采样。当前程序对已经聚合的测试受试者进行四百次教学性重采样，并跳过只含一个类别、无法计算AUC的重采样结果。报告给出有效次数和区间，帮助你看见小样本估计的不确定性；它不是在证明性能精确到小数点后两位。

只有一个外部研究时，这个区间描述该研究内部受试者抽样变化，不能代表研究之间的泛化不确定性。多个研究的分析需要考虑研究层级，例如逐研究报告、按研究汇总或采用事先规定的层级抽样。训练随机种子、超参数选择和数据处理选择带来的变化也不一定包含在一次固定模型的bootstrap中。两个模型在同一批受试者上比较，应考虑配对结构；不能仅凭两个置信区间是否重叠判断显著差异。

留一研究外测需要每折重新训练

真正的留一研究外测依次把每个研究作为外层测试，剩余研究中再安排训练与验证。每一折都重新拟合prevalence、词表、缩放、预训练编码器和下游模型；否则你可能把某个外层测试研究的信息带入其他折训练好的共享模型。无标签预训练同样受这个要求约束。若研究较少，验证研究的选择方式对结果影响可能很大，需要透明呈现。

下面代码只生成六个研究的外测计划，不执行多折模型训练。要实现研究扩展，需要为每折建立独立数据清单和输出目录，再运行全部训练与评价步骤，最后按研究汇总。不要只把原来的test名称换成另一个研究，却继续使用已经见过该研究的编码器。某些研究只有单一类别时，还应在计划阶段说明哪些指标不可计算，并避免只保留容易得到高分的研究。

先区分三个不同层次的解释

“模型使用了某个特征”“这个特征与结局相关”“改变这个特征会改变结局”是三个不同命题。归因方法描述当前模型如何利用输入；统计关联描述观察到的共同变化；因果结论涉及干预和反事实，还依赖研究设计与识别假设。即使三者都出现同一个物种名称，也不能从第一层直接跳到第三层。解释图应该说明它解释的是哪个模型、哪个输出、哪一批数据。

在CurateMicrobiota中，demo_taxon_001等名称是合成特征编号，并不对应真实生物。你可以检查模型是否捕捉模拟器设定的人工变化，却不能据此编写疾病机制或给出菌种干预建议。真实队列还会受到用药、饮食、地理、技术流程和样本选择影响。今天的目标是让模型输出更容易检查，同时清楚标注哪些结论仍需要独立数据或更强研究设计。

注意力是一种计算权重，不是因果证据

注意力权重说明某一层某个头如何混合当前表示，但最终预测还经过值向量、残差、前馈网络、其他层和分类器。同一个较大权重可能对应很小的实际贡献；不同头之间也没有天然统一的“重要物种”刻度。因此展示热图时要注明层、头、输入条件和聚合规则，并与预测变化的检查相互参照。不能只挑最符合已有故事的一张热图。

Jain与Wallace的研究在其自然语言实验设置中检验了注意力作为解释的局限。它为我们提供了应当验证解释的理由，并不直接证明所有微生物注意力图都无用。本项目当前编码器没有提供成套注意力解释报告；若要加入可视化，需要实际暴露权重、检查对应样本，并设计对照。即使热图在不同种子下稳定，也只能支持一种稳定的模型行为，不能单凭它建立微生物之间的生态作用方向。

把“该头在该输入上分配较高权重”写成观察；把“该菌导致疾病”视为尚未被这项模型分析识别的命题。

归因应说明背景分布与扰动方式

逻辑回归系数看起来直接，但它对应的是经过特征转换、标准化和正则化的条件关系；相关特征可能互相分担系数，符号也不能自动解释为单独增加某个菌的效果。梯度描述局部输入变化对输出的敏感度，置换重要性描述按某种打乱规则破坏特征后性能的变化。不同方法回答不同问题，结果不一致时应检查问题定义，而不是选择最漂亮的一种作为唯一解释。

相对丰度具有总量约束。把一个分量单独增加而保持其他分量不变，可能形成不在原始数据支持范围内的向量；重新归一化又同时改变了所有分量。跨人独立打乱某个菌也会破坏菌群相关结构。研究扩展可以比较相关特征成组置换、对数比对照或条件扰动，但每个方案都有额外假设。必须记录扰动单位、是否保持组成约束、使用哪个数据域，以及是否重新训练模型。

两类置换实验不能混为一谈

标签置换用于检查整个学习流程是否能在没有原有标签关系的条件下产生过好的结果。存在重复访视时，应先以受试者为单位置换标签，再把同一标签映射回该人的所有记录；通常还要在研究内保留合适的交换结构。若要进行完整的流程检验，每次置换都应重新执行相关的监督拟合和验证选择，而不是只打乱最终测试标签后继续使用原来的显著性解释。

特征置换则用于测量已拟合模型对某类输入信息的依赖，通常不重新训练，两者目的不同。研究与结局严重混杂、某研究仅有一个类别或纵向标签变化时，简单的研究内标签置换未必提供有效的检验，需要先明确可交换性假设。课程当前CLI没有执行置换显著性检验；今天交付的是明确实验单位与重跑范围的设计，不能把计划中的置换次数写成已经获得的统计证据。

先检查输入兼容，再讨论分布外检测

新的输入可能与训练数据根本不兼容：物种层级不同、数据库版本变更、百分比被误当比例、训练词表中某列完全缺失，或体位与测量平台不同。此时先检查数据契约和来源，再计算模型分数。当前预处理器对缺失的训练列默认报错，未知输入列会排除并记录保留丰度质量。缺失整列不等于每个样本中这个物种都为生物学零。

分布外输入是相对于训练分布和预期任务而言的，不是一个永远固定的标签。新的研究可能在丰度、测量缺失、患病比例或输入与标签关系上发生变化。距离检查只覆盖其中一部分；输入看起来相似也可能出现结局关系改变。工程报告里的词表匹配率、保留质量和来源检查应与数值诊断一起查看。不要把通过格式校验或低重建误差解释为已经证明模型能跨人群使用。

一个可运行的训练参考距离诊断

下面代码使用已经冻结的预处理器，将每个样本表示为训练均值和尺度下的对数丰度，再计算各维平方平均的平方根。它是容易解释的描述性距离，忽略特征间协方差，也没有提供可靠的疾病风险或分布外概率。阈值取训练样本距离的百分之九十五分位，仅用于教学观察；因为阈值来自训练样本，在验证数据上的标记比例不保证恰好为百分之五。

代码只报告训练与验证域，让你在最终测试前确定检查规则。正式扩展可比较独立校准集、稳健协方差距离或表示距离，但要限制调参并检查不同研究的误报。如果根据最后的测试诊断继续修改模型，这批测试数据已经参与开发，后续正式评价需要新的外测安排。距离变大说明应当调查来源与输入差异，不直接说明样本异常、更不说明患者患病。

python
import numpy as np
from curatemicrobiota.data import load_cohort, Preprocessor
cohort = load_cohort("data/demo")
split = cohort.indices()
prep = Preprocessor.load("runs/microbiome/preprocessor.json")
z, alignment = prep.transform(cohort.values, cohort.taxa)
score = np.sqrt(np.mean(z.astype(float) ** 2, axis=1))
threshold = float(np.quantile(score[split["train"]], 0.95))
print({"teaching_threshold": threshold, "alignment": alignment})
for name in ("train", "val"):
    distance = score[split[name]]
    print(name, {"n": len(distance), "mean_distance": float(distance.mean()),
                 "flag_fraction": float(np.mean(distance > threshold))})
# 描述性诊断，不是经过校准的OOD概率；没有使用测试数据调阈值。

不确定性需要对应你想知道的对象

预测概率接近零或一，表示模型给出的输出集中，并不保证预测正确。第12天的校准讨论检验概率与观察频率；受试者bootstrap描述固定模型在当前测试队列抽样下的指标变化；不同训练种子或模型集成反映部分训练不稳定性。它们不是同一种不确定性，不能把其中一种图统一命名为“模型可信度”。当前程序只实现部分评价统计，没有完整的逐样本不确定性系统。

研究扩展可以在验证域规定拒绝预测的规则，并同时报告保留样本比例和保留样本上的错误，防止只挑容易样本造成表面改善。保形预测等方法也依赖交换性或相应修正条件，在跨研究偏移下不能自动照搬覆盖保证。任何需要标定的阈值都应在测试前固定。若目标是解释真实人群中的疾病风险，还需要代表目标人群的校准与评价数据，合成平衡样本不能提供这种保证。

数据增强要写出保留了什么假设

自然语言中替换词语不一定保留含义，微生物数据增强同样如此。对丰度加噪声、丢弃部分特征、混合两个样本或重新抽样，都可能改变标签相关信息。下面的乘性扰动在非负和总和约束下生成一个附近组成，并保持原来的零位置；它只演示数学约束，不证明得到的样本是生物学合理的，也不证明疾病标签不变。增强只应作用于训练数据，验证和测试用于评价原任务。

如果有真实计数和测序深度，可以在明确测量模型后研究下采样，但相对丰度乘一个任意深度并不等于恢复原始测序读段。对比学习还需要慎选正负配对：同一个受试者的两次访视可能有真实状态变化，不同受试者也可能很相似。先规定增强强度、目标不变性与失效情形，再做有无增强的同预算比较；不要只根据测试分数不断选择扰动幅度。

python
import numpy as np
rng = np.random.default_rng(13)
p = np.array([0.2, 0.3, 0.5, 0.0])
q = p * np.exp(rng.normal(0.0, 0.05, size=p.shape))
q = q / q.sum()
assert np.all(q >= 0) and np.isclose(q.sum(), 1.0)
assert np.array_equal(p == 0, q == 0)
print({"original": p.tolist(), "augmented": q.tolist()})
# 这是训练增强候选；保持组成约束并不证明标签保持或生物真实性。

跨模态学习首先是样本对齐问题

宏基因组功能谱、代谢组、临床信息和文献可以提供互补信息，但必须先明确它们是否来自同一受试者、相近时间和匹配的样本处理过程。把一个研究的平均功能谱与每个患者复制配对，可能只让模型学习研究身份；把结局之后得到的信息放进预测时点之前，也会产生时间泄漏。多模态项目的第一张表应该是样本、时间、模态、缺失原因与许可的对应关系。

实现上可以先做各模态单独的强基线，再比较简单拼接或后期融合，最后考虑跨模态注意力与对比目标。缺失模态需要显式策略，并评价现实缺失模式，而不只是所有模态齐全的便利子集。训练与测试继续以受试者和研究隔离；同一个人的不同模态不能分到不同集合。当前CurateMicrobiota只训练丰度表示，证据检索独立提供文献来源，没有执行跨模态联合预训练。

丰度模型与DNA模型的任务边界

丰度表的一行描述某个样本中不同分类单元的相对构成，DNA序列描述按碱基位置排列的遗传信息，文本描述研究者写下的概念和观察。三者的词元、顺序、长度、噪声和监督目标不同。给物种名称加入身份嵌入，不会自动让模型学会这个物种的完整基因组；检索到论文也不会自动为样本提供分子层面的功能验证。你必须先选定输入与目标，才能讨论适合的大模型路线。

Evo的原始研究展示了以基因组序列为核心的建模路线，采用的架构也不应简单写成课程小型Transformer的放大版。本课阅读它，是为了比较序列模型与队列丰度表示的研究对象。若下一阶段研究DNA表示，可先采用公开且适用的预训练表示做明确的预测基准，并按序列同源性、物种或群体关系设计划分。它属于另一个数据工程与验证问题，当前项目没有训练DNA模型。

用稳定性与替代解释收束今天的分析

提交解释报告时，至少记录模型检查点、预处理版本、数据域、输出定义、归因或扰动方法与随机种子。先说明观察，再提出可能解释，最后给出能区分解释的实验。例如某些特征的重要性跨研究变化，可能来自测量差异、群体构成或模型不稳定；下一步可以在训练域比较研究分层结果和特征质量，而不是立刻写成不同地区存在相反的生物机制。

今天不要求你把所有高级方法都实现，而是完成一个可运行的偏移诊断，并为一个解释问题制定可检验方案。课程快速结果中，预训练探针尚未优于简单基线，进一步解释这个探针时尤其应该保留它的性能背景。解释一个表现不佳的模型可以帮助调试，但无法替代有效预测证据。把尚未支持的结论明确列出，明天模型卡就能准确交代项目现阶段的能力与下一步研究重点。

练习与完整参考解答

1. 某个注意力头经常关注A菌，同时A菌的LR系数为正。能否写“A菌促进疾病”？请改写结论并设计下一步。

提示：分别写计算权重、条件关联与干预命题，考虑混杂。

参考解答：不能直接这样写。可写“在指定模型和数据处理下，该头对A特征分配较高权重，LR中A的标准化对数丰度系数为正”。这仍可能受共线性、药物或研究偏移影响。下一步在训练域检查分研究稳定性、相关特征成组扰动及协变量对照；若要讨论机制，需要相应的独立生物证据或因果研究设计。

2. 一名受试者有三次访视。为了做标签置换，你随机打乱全部记录的标签，产生三种不同标签。问题在哪里？

提示：比较独立单位与程序的受试者聚合假设。

参考解答：原任务假设受试者标签固定，记录并非独立。逐行打乱破坏受试者内结构，也不符合现有聚合接口。应以受试者为单位在适当交换组内置换，再映射回所有访视，并按预设流程重新拟合监督模型和验证选择。若真实标签随时间变化，则先重新定义纵向任务，不能套用固定标签方案。

3. 外部数据少了一列训练物种，你填零后模型仍输出0.99；你能据此认为输入可靠且结论确定吗？

提示：区分测量缺失、兼容性、校准与输入分布。

参考解答：不能。缺失列可能来自数据库或测量流程差异，填零引入了未经验证的生物零假设。极端概率不代表输入兼容、校准良好或跨域可靠。先核查层级、版本与单位，保留缺失报告并按冻结规则处理；再用适当独立资料评价偏移与校准。当前接口默认报错正是为防止悄悄混淆这些情况。

4. 把丰度向量乘上小幅随机噪声并重新归一化后总和仍为一。为什么这不足以证明增强有效？

提示：数学约束与任务不变性是两个条件。

参考解答：非负与总和约束只保证得到一个组成向量，不保证它符合测量过程、真实生态联合分布或保持原标签。归一化还同时改变多个分量。应明确噪声假设，在训练域限定强度，并用同预算有无增强对照和独立验证检验收益；不能将增强样本当作新增独立受试者。

  2. 把剩余列重新命名顶替缺失列

用学习曲线决定何时增加模型规模

扩大参数量之前，先在固定验证协议下比较预训练数据量、训练步数与下游表现。若均值插补已经接近掩码模型，而下游表示仍弱，就应该检查任务、汇聚和信息保留，而不是默认加层一定解决。若增加数据在多个研究上持续产生收益，再考虑更大隐藏维度、更长特征集合和更丰富目标。不同配置同时记录准确性、运行时间、内存和计算预算。

标准注意力的分数矩阵随特征数平方增长：特征数从四十八变为四百八十，相关分数元素数量约增加一百倍，但总训练开销还由隐藏维度、前馈层、批量和内核决定。先测量一小段训练的实际资源，再选择混合精度、梯度累积、检查点重计算或更高效结构。它们需要相应实现与数值检查，当前CPU教程没有自动提供分布式大规模训练，也不要求先购买设备才能完成学习。

标准注意力分数张量约为 B × H × T × T；扩大T时需同时评估表示价值与资源成本

向基础模型发展的证据是什么

一个基础模型通常被期待能从广泛数据学习可迁移表示，并支持多个任务或环境。参数大、名字里有GPT或使用Transformer，都不能单独证明这一点。对微生物研究，可以逐步比较跨研究的表型预测、特征缺失重建、相近任务迁移和其他明确用途，始终保留强基线与对照。每一种新增任务都要说明标签质量、训练信息与外测单位，不能把同一数据上的多个统计图当作独立泛化证据。

MGM的原始研究提供了较大规模微生物预训练路线，可作为下一阶段的阅读与比较对象。阅读时检查它的分类层级、输入表示、数据来源、预训练目标和评估安排，再判断哪些方法适合当前任务。它不是课程集合式掩码编码器的同一个实现。论文报告的表现需要在相应数据与设计范围内理解，不能直接贴到CurateMicrobiota结果页，也不能因为模型名称相近就声称已经复现。

把研究路线写成可以失败的问题

一个有效问题必须允许结果不支持你的想法。问题一可以是“在相同监督预算下，增加互不重叠的预训练研究能否改善多数外测研究的冻结表示？”问题二可以是“当前平均汇聚是否丢失任务信息，替代汇聚是否在训练域选择后仍有稳定收益？”问题三可以是“加入真实功能谱后，是否超过单一丰度和简单拼接基线？”每个问题都明确对照、评价单位和何时停止。

练习与完整参考解答

1. 你的模型验证掩码MSE下降了三成，但冻结表示AUROC低于LR。请写一段能放进模型卡的结论。

提示：同时说明参照、评价单位、范围与下一步，不把优化成功等同迁移成功。

参考解答：可写“在指定合成数据和研究划分下，编码器的验证重建误差较初始化下降，但在留出研究的受试者分类任务中，冻结预训练表示未优于直接丰度LR。该结果支持优化流程可运行，尚未显示本任务的迁移收益。由于训练预算、样本规模与外测研究有限，下一步将比较重建均值基线、汇聚策略和更多独立研究，不将该结果解释为预训练普遍有效或无效。”

2. 同学复制了你的随机种子，却无法完全复现每个小数。你应该先检查哪些证据？

提示：种子之外还有数据身份、配置与数值环境。

参考解答：依次核对代码版本、输入与split校验值、预处理与词表、检查点选择、训练步数和超参数，再比较Python、数值库、PyTorch版本以及硬件和内核。先判断是否在复现同一个实验，再按合理浮点容差检查结果。不能仅凭种子一致就断定不同输出必然是错误。

3. 为了发布真实数据项目，你发现软件包使用开源许可证。能否将全部来源研究数据和模型权重统一改成该许可？

提示：软件、数据与派生权重的授权并不是同一对象。

参考解答：不能。应逐项核查自己的代码、依赖、底层研究数据和权重的来源与适用条件。软件包许可证不自动覆盖所有研究数据或其再分发。必要时发布选择配置、导出脚本、版本与校验值，并让具备相应访问条件的研究者获取资料，而不是自行替换原有授权。

4. 提出一项能检验“更大的微生物模型更有用”的实验，而不预设模型一定获胜。

提示：固定问题与外测协议，控制计算和监督预算。

参考解答：先固定任务、训练域内选择与多个外层研究，比较小、中两种容量，在相同预训练数据和明确预算下运行多个种子。每折重新拟合预处理和预训练，比较强LR及随机/预训练表示，报告受试者指标、研究间差异、运行成本与失败。若扩大模型没有稳定收益或成本过高，就不支持当前设置下继续扩大；再检验数据量或目标是否成为限制。

验收自测与解析

1. 快速流水线运行成功最直接支持什么？

  1. 完整多折LOSO和DNA模型都已经训练
  2. 预训练探针必须优于所有基线
  3. 其中实际实现的步骤可按当前配置端到端执行
  4. 模型已经通过真实临床验证

参考答案：C。运行状态只覆盖命令实际执行的组件；科学收益与其他拓展任务需要各自证据。

2. 下列哪项最应保留在最终模型卡中？

  1. 把合成数据写成公开真实队列
  2. 预训练探针未优于LR及对应数据范围
  3. 只保留最漂亮的训练曲线
  4. 删除所有低于随机的测试结果

参考答案：B。负面结果和适用范围直接影响使用判断，是透明报告的重要组成。

3. 当模型规模扩大十倍时，哪种做法最合理？

  1. 用固定评价与资源记录检验新增容量是否带来收益
  2. 自动把模型名称改成基础模型并发布高效能结论
  3. 取消简单基线以免结果不够突出
  4. 反复改测试集直到新模型获胜

参考答案：A。模型规模本身不是收益证据，应有同协议对照、数据身份与计算成本记录。

4. 模型文件哈希一致能够证明什么？

  1. 模型已经学习了正确因果机制
  2. 训练数据没有任何偏差
  3. 模型适用于所有人群
  4. 比较的文件内容身份一致

参考答案：D。哈希用于文件身份核对；算法有效性、数据质量与泛化能力需要其他验证。

5. 下一阶段最先需要完成哪项工作？

  1. 把已有论文最高分写进结果页
  2. 先做跨模态模型再补样本对应关系
  3. 定义真实数据任务、来源与划分，并复现适当强基线
  4. 先购买最大显存设备再考虑数据

参考答案：C。明确数据、任务和对照是判断新模型是否有用的基础，后续规模和模态扩展应据此推进。
