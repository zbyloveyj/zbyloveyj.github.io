## 二、15个完整章节

### 01 环境安装与数据准备

**核心问题：** 为什么先用虚构数据而不是联网搜索？

Jupyter Notebook 可以把说明文字、Python代码和运行结果放在同一个文件中。先使用可重复的虚构微生物研究记录，能够排除网络延迟、API权限和模型费用的干扰，验证每一步输入与输出。实验数据明确标记为教学模拟，不能当作真实论文证据。

**步骤：** 运行环境检查，观察Python版本及工作目录；加载DEMO_STUDIES，查看每一条记录的字段与数据类型；修改一条教学记录，观察搜索结果如何改变。

**验收：** 能解释Notebook单元格的执行顺序，并打印一组标明DEMO的结构化记录。

**注意：** Notebook可能因为跳着运行产生变量未定义。遇到此情况应从第一格重新运行，不要把教学数据当成发表论文。

### 02 工具调用与函数白名单

**核心问题：** Agent所谓的“调用工具”，到底调用了什么？

工具不是模型临时生成的魔法，而是开发者预先提供的、拥有明确输入输出契约的Python函数。以微生物研究助手为例，一个函数负责按疾病检索，另一个负责计算，外层的白名单决定允许调用哪些工具。加入参数校验，比直接执行模型生成的字符串安全得多。

**步骤：** 运行安全计算器，比较允许的运算和被拒绝的表达式；运行search_studies检索MDD和BD示例记录；打开TOOL_REGISTRY，理解工具名与Python函数的映射关系。

**验收：** 能够解释工具名、参数、函数体、返回值四个部分，并在程序中追加一个只读工具。

**注意：** 不应对用户输入直接使用eval、exec或未限制的Shell命令。

### 03 建立第一个规则式Agent

**核心问题：** 程序怎样知道先搜索还是先计算？

一个最小Agent由任务输入、动作选择、工具执行、观察结果和最终回答五个环节构成。这里先使用规则决策器，便于追踪它为什么选择某个函数。它能展示完整闭环，但并没有使用大语言模型，所以不能把输出称为自主推理或真正的模型决策。

**步骤：** 把“查询抑郁症研究”交给规则式Agent；观察决策器选择search_studies的记录；把问题改成比较两种疾病，观察规则适用范围。

**验收：** 能顺着执行轨迹复述“问题→决策→工具→结果→回答”。

**注意：** 规则覆盖范围有限；模型能力与程序规则必须清楚区分。

### 04 Function Calling完整链路

**核心问题：** 模型说“调用函数”，是谁真正执行了Python？

Function Calling是模型与程序之间的结构化约定。模型根据函数描述返回一个调用请求，宿主Python程序负责验证工具名称和参数、执行真实函数，再把结果交回模型。模型并不会凭空操作本机文件。理解这一点以后，就能看懂多个模型服务为什么可以复用相同工具代码。

**步骤：** 读取模拟模型输出的JSON工具请求；解析name和arguments，并通过执行器完成调用；故意请求不存在的工具，观察程序如何拒绝。

**验收：** 能够画出模型、函数调用消息、Python执行器和工具结果的往返关系。

**注意：** 模型建议的参数不是可信输入；必须在执行层再验证，不可直接反序列化成任意代码。

### 05 短期记忆与长期存储

**核心问题：** 聊天记录为什么不等于长期记忆？

短期记忆是当前任务中有限的上下文与工具轨迹；长期记忆是明确保留的知识、偏好或经历，必须有独立存储、更新和删除策略。本实验使用本地JSON与SQLite分别演示会话上下文、持久化和安全查询。真实研究系统还要考虑隐私、权限、信息过期和跨用户隔离。

**步骤：** 向AgentMemory写入两个对话回合；保存示例偏好到本地JSON并重新读取；使用SQLite参数化SQL插入与查询教学记录。

**验收：** 能说明内存中的变量、JSON文件和SQLite各自怎样保存状态。

**注意：** 不能把敏感患者记录、API Key或个人信息直接写进公开GitHub仓库。

### 06 推理、规划与逐步执行

**核心问题：** 复杂任务为什么要先拆解？

“比较抑郁症与双相障碍证据”并不是一个单独函数，而是由确定疾病、分别检索、对齐字段、比较结果、形成结论等环节组成。规划器明确依赖顺序，再逐步调用工具，这种分解也便于定位错误。初学阶段采用固定规划流程；接入LLM后仍需对每个行动进行约束。

**步骤：** 调用ResearchPlanner生成两疾病比较计划；逐步执行计划并记录中间输出；故意让一个步骤缺少参数，观察失败处理。

**验收：** 获得包含顺序动作和工具返回值的结构化执行轨迹。

**注意：** 计划文本不是事实；每一步的结果必须有实际工具输出支撑。

### 07 RAG检索增强生成

**核心问题：** 为什么不能直接让模型凭记忆回答科研问题？

RAG先把资料整理成文档片段，再根据问题检索证据，最后把检索到的片段交给生成模块组织回答。这里使用简单TF-IDF来演示索引与排序，而不是声称已经实现高性能语义搜索。重要的是理解：检索命中并不必然意味着证据支持答案，科研场景还需检查研究设计、效应方向和来源。

**步骤：** 建立包含ID、标题、正文与来源的文档集合；比较不同问题的检索排序与得分；运行grounded_answer并检查每一句依据了哪些记录。

**验收：** 得到带教学来源ID的检索结果和保守回答。

**注意：** 本节TF-IDF适合演示，不等于向量数据库；“有引用”也不等于“引用支持结论”。

### 08 多智能体协作

**核心问题：** 多Agent是不是必须购买三个GPT账号？

多智能体首先是一种任务分工方式：研究员检索资料，审查员判断证据是否合规，报告员将已经审核的数据整理成结果。三个角色可以运行在同一Python进程里，也可以未来再分别连接模型。只有明确职责、状态交接与审查边界，增加Agent数量才可能产生价值。

**步骤：** 运行EvidenceResearcher取得资料；交由EvidenceReviewer检查记录合法性；由EvidenceWriter生成包含来源ID的报告。

**验收：** 能区分单个模型多角色提示、多个独立执行器和真正多模型系统。

**注意：** 增加角色会增加成本和错误传播；审查步骤必须有可检验的规则。

### 09 评估、安全与日志

**核心问题：** 能生成答案，是否就代表Agent可靠？

科研Agent需要评估任务成功率、工具调用准确率、证据覆盖、误引率、拒答质量与可复现性。程序日志应记录动作、参数类别、耗时和错误，而不记录密钥。还要把检索到的网页、论文与提示词明确隔离，避免把外部资料中的恶意指令当成系统命令。

**步骤：** 运行内置断言检查工具白名单和检索结果；观察模拟提示注入如何被当成不可信资料；写入JSONL轨迹并读取复核。

**验收：** 得到一组通过/失败的检查结果，以及结构化日志文件。

**注意：** 只检查JSON结构正确不能证明科研内容真实；提示词隔离仍需要权限、审批和输出校验配合。

### 10 MCP与外部工具协议

**核心问题：** Function Calling和MCP究竟有什么区别？

Function Calling描述模型如何提出工具调用；MCP提供客户端发现工具、读取资源、与外部工具服务通信的标准。通俗说，前者是模型提出‘我想做什么’，后者是外部能力如何用一致接口接入。课程先模拟工具描述与Client调用，帮助你看清Host、Client和Server的职责。

**步骤：** 列出模拟的MCP工具元数据；选择search_studies并通过执行器调用；与上一节本地工具白名单比较。

**验收：** 能说清楚Host、Client、MCP Server、Tool四者的关系。

**注意：** 教学模拟不等于实现完整MCP协议；接入真实服务需要权限、传输与版本兼容性检查。

### 11 接入PubMed真实文献

**核心问题：** 如何从模拟数据切换到真实研究信息？

使用NCBI E-utilities可在授权范围内查询PubMed记录。首次试验只获取PMID等元数据，不批量下载受版权保护的全文，也不把检索关键词匹配结果直接当成因果证据。真实资料必须与前面虚构的DEMO研究记录隔离，保持可追溯来源。

**步骤：** 阅读pubmed_esearch函数并确认它使用HTTPS；联网后手动打开RUN_PUBMED开关；检索有限数量的PMID并记录查询式。

**验收：** 获得真实PMID列表；如网络不可用则清楚显示跳过，而不是伪造结果。

**注意：** PubMed需要网络并遵守NCBI使用规范；返回PMID不意味着已阅读论文全文。

### 12 接入真实大语言模型

**核心问题：** 真正让LLM决定什么时候调用函数，需要哪些代码？

在本节中，程序向Responses API声明只读工具的JSON Schema，模型可以返回函数调用请求，Python通过允许列表执行后，把调用结果连同关联标识传回模型。为防止误用或意外费用，联网默认关闭，需要自行配置模型和API Key，并设置最大调用轮数。关闭开关时只运行离线流程。

**步骤：** 检查ENABLE_LIVE_LLM默认是False；理解LIVE_TOOL_SCHEMAS中的函数名、参数和strict设置；配置自己的API Key后手动打开开关，比较模型选工具与规则选工具。

**验收：** 在已授权且计费可用时看到真实模型的工具调用轨迹；未启用时明确跳过。

**注意：** API Key不能提交到GitHub；模型调用可能产生费用，且需要支持函数调用的可用模型。

### 13 多模态与Transformers选学

**核心问题：** 看论文图表是否只需换个Prompt？

文本Agent处理的是字符串或结构化信息；多模态任务还需要图像输入、特定模型接口以及图表解析评估。课程演示本地文件加载与Hugging Face Transformers的可选模型调用，默认关闭下载和推理，避免无意中消耗大量磁盘、显存和网络额度。

**步骤：** 识别本地图片路径并确认文件存在；只在需要时开启图像加载演示；在环境支持时再试可选Transformers模型。

**验收：** 能够区分文件读取、OCR、视觉推理和科学图表理解，不混淆不同能力。

**注意：** 图表识别结果必须与原图坐标轴、图例和统计方法逐项对照。

### 14 把Agent封装成API并部署

**核心问题：** Jupyter里能跑的程序怎么变成网页功能？

实际部署时，Notebook更适合研发与验证；长期提供服务通常要把稳定函数封装成FastAPI接口，让React前端通过HTTPS发请求。服务端负责管理凭据、访问权限、数据库连接和计算任务。课程生成一个本机只读API示例，不宣称它已经具备公开生产部署所需的认证、限流和监控。

**步骤：** 运行生成demo_api.py的代码单元；安装fastapi与uvicorn并在本机启动服务；访问/docs检查接口，再理解云服务器和域名如何指向后端。

**验收：** 能理解浏览器→HTTP API→Python函数→JSON响应的运行路径。

**注意：** 不要把未经鉴权的演示接口直接开放公网，更不能在网页JavaScript中放API Key。

### 15 微生物科研助手综合挑战

**核心问题：** 从一个研究问题到带证据的报告怎样闭环？

毕业练习整合问题输入、疾病识别、文献检索、证据审查、报告生成和审计记录。整个离线版本仍基于教学模拟数据，目的是训练你对每个环节的控制能力。未来可把检索替换为PubMed真实文献，把摘要替换为LLM，并加入规范化抽取、元分析和人工审核。

**步骤：** 运行MicrobiomeTeachingAgent处理一个疾病问题；检查报告中的记录ID、检索范围和局限说明；改变问题，比较新旧报告与工具轨迹。

**验收：** 生成可查看的教学报告及操作日志，能够说明哪些部分真实执行、哪些是模板或规则。

**注意：** 不要把模拟分析报告作为真实疾病生物标志物结论；正式科研必须接入可核查来源与独立评估。

## 三、运行方法

### 方式A：Google Colab（适合新手）

在上方点击Colab链接，连接Python运行时环境，从上往下逐格运行（Shift+Enter）。联网练习默认关闭，是否启用应由你主动决定。

### 方式B：本地Jupyter

1. 安装Python 3.10或更高版本，确认命令行可运行 `python --version`。
2. 在终端运行 `python -m pip install notebook`。
3. 下载Notebook到单独文件夹，运行 `jupyter notebook`，在浏览器中打开该文件。
4. 按从上往下的顺序执行代码格；不要只执行后面的实验而跳过前置变量。
5. 执行结果、日志与模拟数据库存入 `agent_lab_output/`，请不要将其中真实个人数据提交GitHub。

### 可选依赖

默认15讲离线主体仅用Python标准库。开启真实LLM、Hugging Face或FastAPI时，按需安装：

```bash
python -m pip install openai
python -m pip install fastapi uvicorn
python -m pip install transformers torch
```

依赖请按需选择，不建议首次安装所有依赖；Transformers及其模型下载可能占用较大资源。

## 四、真实模型调用与安全边界

Notebook中的 `ENABLE_LIVE_LLM=False`、`RUN_PUBMED=False`、`RUN_TRANSFORMERS=False` 均默认关闭。只有在确认所需网络、模型权限与计费条件后才手动开启。**必须使用自己合法持有的API Key，切勿把密钥写入Notebook或提交公开仓库。** 真实大模型示例使用OpenAI Responses API，并在宿主Python中校验唯一的只读工具。模型调用的响应质量与模型版本、账号权限有关，离线代码测试不代表真实模型已完成测试。

## 五、工程部署注意事项

GitHub Pages仅托管本教程静态HTML、CSS、JS和可下载的`.ipynb`文件，**不会替你在服务器上运行Python Notebook或FastAPI**。要让外部用户调用Python程序，需要另行使用云服务器、Render等运行环境部署API，配置HTTPS、跨域、身份验证、限流、日志、备份与费用控制。`demo_api.py`是Notebook生成的本地只读教学示例，不具备直接公网发布所需的生产安全措施。

## 六、科研数据与资料说明

所有以 `DEMO` 标记的微生物记录都是**为了展示机制而虚构的示例**，不是可靠的论文样本，不可用作结果分析、医学建议、研究结论或投稿材料。真实PubMed工具只展示官方ESearch访问方式。检索命中不代表支持结论，严肃科研还需做论文筛选、独立复核、版本记录和引用审查。
