## 01 · 理解概念

### 轨迹记录动作，不展示隐藏思维链

本课程的trace包含可观察的节点、工具调用与结果状态，帮助回答“检索了什么、在哪一步停止”。这些是程序事件，不是模型内部完整的推理过程。

排查错误时从输入、参数、工具返回和输出验证逐层定位。不要为了得到看起来详细的解释而要求模型编造内部思维；执行日志应当来自真实发生的操作。

### 耗时需要测量，不能预先写死

observability中的耗时来自当前实际运行，受机器负载、输入规模与执行路径影响。两次运行数字不同并不一定是错误，重要的是测量范围与单位一致。

离线词法检索的耗时无法代表真实模型或网络服务性能。迁移到真实provider后，还要区分等待、模型生成、工具执行和重试耗时；比较时保持任务与环境尽量一致。

### 未知用量不应该伪装成零

离线规则流程没有提供模型token报告时，相关字段应为null；价格不可确定时cost_usd也应为null。零费用是一个有含义的数值判断，不能用它代替“未测量”或“未定价”。

真实服务返回的usage也需检查定义，包括输入、输出、缓存等分类。估算费用必须同时记录适用模型、单价来源、计价日期和公式；本课不把可能变化的价格写成永久常量。

### 日志足够排错，也要控制信息范围

记录问题、引用ID和状态能帮助复现，但真实项目还要考虑数据最小化与保留时间。凭证、私人原文和敏感数据不能因为“方便排错”就自动进入可分享日志。

本课使用教学材料。你可以学习如何将调用预算max_steps与实际停止原因对照；后续接入真实模型时，先检查哪些字段会被发送和保存，再扩展日志。

## 02 · 一步一步做

命令在解压后的 practice 文件夹执行。Windows可使用 .\.venv\Scripts\python.exe；macOS/Linux可使用 .venv/bin/python 替代 python。

### 1. 找到本课的输入与配置

**为什么做：**先知道程序读什么，后面才能解释输出为何改变。

在 VS Code 中打开 experiments.json，定位 day25。用下面的命令确认当前目录正确，并把各参数的作用写在笔记中。

```text
python -c "import json; print(json.load(open('experiments.json', encoding='utf-8'))['day25'])"
```

**预期结果：**终端显示本课配置；键名与文件中的内容一致。

### 2. 运行本课基线

**为什么做：**保持默认设置的一次运行，是后续比较的参照。

执行命令，打开新生成的 outputs/day25.json。先检查 day、mode 和 result，不急着修改代码。

```text
python run.py day 25
```

**预期结果：**结果写入 outputs/day25.json；主线 mode 明确为 offline，代表规则教学流程。

### 3. 沿输出检查机制

**为什么做：**不能只看程序有没有报错，要检查它实际做了什么。

格式化阅读输出，重点检查answer.status、answer.trace 与 observability。把一个输入参数和一个输出字段用箭头对应起来。

```text
python -m json.tool outputs/day25.json
```

**预期结果：**能够定位answer.status、answer.trace 与 observability，并用自己的话解释该结果。

### 4. 改变一个条件并比较

**为什么做：**主动制造可解释的变化，才能验证自己理解的机制。

完成下面“改一改”实验。对比基线与新结果，记录哪些字段改变、哪些保持稳定；不要同时改模型、材料和参数。

**预期结果：**留下一组前后结果和一句解释；失败状态也可以是正确的实验产物。

### 改一改 · 缩小调用步骤预算，观察停止记录

- 先执行 python run.py day 25，将 outputs/day25.json 复制为自己的基线备份。

- 在 VS Code 打开 experiments.json，只修改 day25.max_steps 为 1，保持其他键不变并保存。

- 执行 python -m json.tool experiments.json 检查语法，再执行 python run.py day 25。

- 对比两份结果，重点观察answer.status、answer.trace 与 observability；解释改变原因后恢复原设置或明确记录保留值。

**观察什么：**步骤预算降低后，应在有限步骤内停止，并在answer状态或轨迹中反映预算限制；耗时按实际结果记录，不预设一定更快。

**机制解释：**步骤预算控制流程是否能走完。只有观察到真实执行路径，才能解释输出与耗时的变化。

## 常见问题

### 修改配置后结果没有变化

原因：改了其他天的字段，或编辑后尚未保存。

处理：核对 experiments.json 中的 day25，保存后重新运行；检查实际执行目录。

### 把受控失败误当成程序坏了

原因：本课实验主动制造了边界条件。

处理：先对照 expected 和状态字段，区分设计内拒绝与未处理异常；保留错误信息再修复。

## 自测与解析

### 1. 没有可确认的模型单价时，cost_usd最合适的值是什么？

- A. 0，代表免费

- B. 随便估一个数

- C. null，并说明原因

- D. 上一家服务的价格

**答案：C。** null表示未知或不适用，避免把未测量结果误写成确定费用。

### 2. 课程trace表示什么？

- A. 模型内部完整思维链

- B. 真实记录的可观察执行事件

- C. 模型所有隐藏状态

- D. 答案正确性的充分证明

**答案：B。** 程序事件能帮助复现和排错，但不等于内部思维，也不能单独证明结论正确。

## 小词典

- **Observability**：通过事件、指标与日志了解系统实际运行状态的能力。

- **Usage**：服务返回的资源用量记录，其字段定义随接口而异。

- **Null**：没有可用值或不适用的显式表示，不等同于数值零。
