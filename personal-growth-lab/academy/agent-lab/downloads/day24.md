## 01 · 理解概念

### 先规定什么叫成功

检索是否找到相关证据、可回答问题是否答对、未知问题是否明确拒答，是不同的评价目标。只看最终回答是否流畅，无法判断证据链是否工作。

本课输出 evaluation，其中记录各项指标和逐题结果。先打开 data/eval_dev.json 与 data/eval_test.json，理解每个样例的预期结果；不要只复制一个总分而忽略失败类型。

### 开发集用于改进，测试集用于阶段检查

你可以在开发集上调整top_k、措辞和规则；测试集用于在固定阶段观察变化后的表现。若反复查看测试答案并据此调参，测试结果也会逐渐变成开发反馈。

课程附带的两个小集合都公开给学习者，所以它们不是盲外测，也不是秘密基准。课程中保留名称是为了练习流程，不能据此宣称系统在未知真实科研问题上达到同样水平。

### 多个指标帮助定位错误

retrieval_recall关注相关证据是否被找到；answerable_accuracy关注有依据的问题；abstention_accuracy关注系统是否会对材料外问题保留不确定。三个数可能朝不同方向变化。

扩大top_k可能找到更多相关材料，也可能加入噪声；当前词法检索与规则回答有自己的特征。用逐题结果说明变化，而不是假设参数越大越好或平均分越高就全面改进。

### 小数据集适合发现问题，不适合夸大能力

几道教学题能快速发现回归错误，但分数对单题变化很敏感。还要考虑样例重复、资料泄漏和问题覆盖范围，才能判断评估是否代表真实任务。

本课的产物应包括本次参数、数据集合、逐题失败原因和下一步补充的样例类型。未来加入真正保留的外部题目时，应冻结题目与标准，并控制根据测试结果继续调参的次数。

## 02 · 一步一步做

命令在解压后的 practice 文件夹执行。Windows可使用 .\.venv\Scripts\python.exe；macOS/Linux可使用 .venv/bin/python 替代 python。

### 1. 找到本课的输入与配置

**为什么做：**先知道程序读什么，后面才能解释输出为何改变。

在 VS Code 中打开 experiments.json，定位 day24。用下面的命令确认当前目录正确，并把各参数的作用写在笔记中。

```text
python -c "import json; print(json.load(open('experiments.json', encoding='utf-8'))['day24'])"
```

**预期结果：**终端显示本课配置；键名与文件中的内容一致。

### 2. 运行本课基线

**为什么做：**保持默认设置的一次运行，是后续比较的参照。

执行命令，打开新生成的 outputs/day24.json。先检查 day、mode 和 result，不急着修改代码。

```text
python run.py day 24
```

**预期结果：**结果写入 outputs/day24.json；主线 mode 明确为 offline，代表规则教学流程。

### 3. 分别运行开发集与测试集

**为什么做：**不能只看程序有没有报错，要检查它实际做了什么。

运行两条评价命令，保存终端结果，并分别检查split、top_k、三项指标与items。它们都是公开教学题；找到至少一项逐题判断并解释其依据。

```text
python run.py evaluate --split dev --top-k 3
python run.py evaluate --split test --top-k 3
```

**预期结果：**两份结果标注各自集合与参数，可逐题检查；分数不能作为盲外测结论。

### 4. 改变一个条件并比较

**为什么做：**主动制造可解释的变化，才能验证自己理解的机制。

完成下面“改一改”实验。对比基线与新结果，记录哪些字段改变、哪些保持稳定；不要同时改模型、材料和参数。

**预期结果：**留下一组前后结果和一句解释；失败状态也可以是正确的实验产物。

### 改一改 · 缩小检索规模，比较哪些题受到影响

- 先执行 python run.py day 24，将 outputs/day24.json 复制为自己的基线备份。

- 在 VS Code 打开 experiments.json，只修改 day24.top_k 为 1，保持其他键不变并保存。

- 执行 python -m json.tool experiments.json 检查语法，再执行 python run.py day 24。

- 对比两份结果，重点观察evaluation 的指标、样例数与逐题 items；解释改变原因后恢复原设置或明确记录保留值。

**观察什么：**在相同split上比较top_k=3与1的逐题结果；可能有题变化，也可能整体分数不变，必须按真实输出记录。

**机制解释：**小样本和规则流程可能使某些参数变化不影响最终标签。逐题观察比预设“分数一定下降”更可靠。

## 常见问题

### 修改配置后结果没有变化

原因：改了其他天的字段，或编辑后尚未保存。

处理：核对 experiments.json 中的 day24，保存后重新运行；检查实际执行目录。

### 把受控失败误当成程序坏了

原因：本课实验主动制造了边界条件。

处理：先对照 expected 和状态字段，区分设计内拒绝与未处理异常；保留错误信息再修复。

## 自测与解析

### 1. 不断查看test答案并据此调参后，test结果应怎样解释？

- A. 仍然完全独立

- B. 已受到开发过程影响，独立性降低

- C. 题目越少越独立

- D. 可以称为盲外测

**答案：B。** 测试反馈参与了优化，它不再提供同等独立的验证。

### 2. 所有问题都回答一段话，可能损害哪个指标？

- A. 未知问题的拒答准确性

- B. 只会提高所有指标

- C. 与评价无关

- D. 自动提升证据召回

**答案：A。** 对材料外问题也给出确定回答，可能牺牲拒答能力。

## 小词典

- **Development set**：用于调试和改进系统的样例集合。

- **Test set**：用于阶段性检查的样例集合；独立程度取决于使用方式。

- **Abstention**：证据不足时明确停止推断或拒绝给出确定结论。
