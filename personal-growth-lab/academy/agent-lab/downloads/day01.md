# 第01天 · 把第一个 Agent 项目跑起来

先拿到一次完整运行，再认识模型、工具与任务边界。

**标准路线：60分钟；忙碌日：20分钟；扩展练习另计。**

## 今天的目标

- 在 VS Code 中打开并运行实践包。

- 区分聊天、固定工作流和模型参与决策的 Agent。

- 写出输入、允许动作、交付物和停止条件。

## 开始之前

- 一台可以安装Python的电脑；主线无需GPU或API密钥。

- 下载实践包并解压，能找到practice目录。

## 一小时安排

- 15分钟 · 理解概念：阅读四节讲解，记下今天最关键的一个区别；外部资料按指定小节选读。

- 30分钟 · 操作与修改：先完成四步带练，再改变一个参数，保留修改前后的结果。

- 10分钟 · 验收与自测：对照三项验收，完成两道自测并阅读解析。

- 5分钟 · 记录与收尾：写下结果、未解决的问题和下次打开项目后的第一步。

## 01 · 理解概念

### 一个月的目标，是做出可以解释的作品

这一个月围绕科研证据助手展开：输入一个问题，查找指定材料，按需要调用工具，最后留下能够核对来源的结果。每天以一次小实验和一个具体文件衡量进展。30天是学习顺序；忙碌时可以分两次完成，不需要为了连续打卡而跳过理解。

课程主线采用Python标准库和明确标注的离线规则。它让没有GPU或API账号的电脑也能检查接口、数据和控制流程。第3天提供真实模型路径；离线运行成功与真实模型能力是两项不同的验证。

### 把聊天、工作流和 Agent 分开

让模型将一段话改写成三句话，可以是一次模型调用。读取CSV、检查缺失、输出固定报告，可以预先写成工作流。如果系统需要根据不同问题选择下一步工具、观察结果后调整行动，才涉及模型参与的行动决策。结构越复杂，越需要明确成本与停止条件。

本课的offline模式是教学工作流，不会隐藏调用大模型。你将先学会外围程序如何约束、执行与检查，再接上模型。这能帮助你判断：一个结果来自检索、计算、固定规则还是模型，而不是把所有输出都归功于所谓智能。

### 让环境准备尽量简单

先安装Python 3.10或以上版本与VS Code，再解压实践包。用VS Code的“文件→打开文件夹”选中能直接看到run.py、agentkit和data的practice目录，然后点“终端→新建终端”。网页负责阅读与记录，Python命令在你电脑的终端运行，不要输入到带有>>>的Python交互窗口。

Windows先试python --version，找不到时试py --version。建议建立.venv环境并直接使用其中的解释器：Windows是.\.venv\Scripts\python.exe，macOS/Linux是.venv/bin/python。这样无需修改PowerShell执行策略。下文统一写python，你可以替换为环境内的完整路径。

### 先写任务边界，再增加功能

合适的起步任务是“依据给定教学资料解释关联与因果的区别，并列出没有得到支持的部分”。它有有限输入和可检查的终点。“自动完成所有微生物研究”则缺少输入、权限、交付标准和结束条件，不能靠一次运行判断成功。

今天先写四句话：材料从哪里来；允许读取或写入什么；最后得到哪个文件；遇到什么情况停止。后面会把这些文字逐渐转成JSON参数、工具白名单、预算和人工批准。现在只生成任务卡，不宣称已经实现整个行动循环。

## 02 · 一步一步做

命令在解压后的 practice 文件夹执行。Windows可使用 .\.venv\Scripts\python.exe；macOS/Linux可使用 .venv/bin/python 替代 python。

### 1. 确认目录与解释器

**为什么做：**先排除路径问题。

在practice目录打开终端；最后一行必须为True。

```text
python --version
python -c "from pathlib import Path; print(Path.cwd()); print(Path('run.py').exists())"
```

**预期结果：**Python版本不低于3.10；当前目录存在run.py。

### 2. 创建独立环境并执行第一课

**为什么做：**避免影响已有科研环境。

Windows运行下面两行；macOS/Linux改为python3 -m venv .venv和.venv/bin/python run.py day 1。

```text
py -3 -m venv .venv
.\.venv\Scripts\python.exe run.py day 1
```

**预期结果：**终端输出本课JSON，生成outputs/day01.json。

### 3. 读懂结果的层次

**为什么做：**知道本次程序真正完成了什么。

打开输出，找到day、title、mode和result，确认是offline教学结果。

```text
python -m json.tool outputs/day01.json
```

**预期结果：**JSON可正常格式化；你能指出任务卡与模式标记。

### 4. 把目标写成四句话

**为什么做：**让后续每个功能都有检查依据。

在学习笔记写输入、允许动作、交付物、停止条件；对照experiments.json的day01配置。

**预期结果：**留下一张小任务卡；不把任务卡误认成已执行的自主Agent。

### 改一改 · 改变目标与预算，观察任务卡

- 打开experiments.json，将day01.goal改成“从给定资料整理关联与因果的证据说明”。

- 保持day01.max_steps不变，保存后运行python run.py day 1；这一轮只修改目标文字。

- 对比result.task_card中的goal；恢复原值。若还有时间，再单独将max_steps改为4做第二轮实验。

**观察什么：**任务卡中的目标随配置变化；单独改变步数时只改变预算说明，第1课不会自动执行模型调用。

**机制解释：**把任务说明写成配置，是可检查程序的第一步；真正的行动循环在第6课出现。

## 常见问题

### 提示找不到run.py

原因：终端没有位于practice目录。

处理：用VS Code重新打开practice文件夹，再开终端；检查Path('run.py').exists()。

### PowerShell不允许激活环境

原因：系统阻止执行激活脚本。

处理：直接使用.\.venv\Scripts\python.exe执行命令，无需调整系统策略。

### python命令不存在

原因：解释器未安装或未加入路径。

处理：Windows尝试py；macOS/Linux尝试python3。仍失败则从Python官网安装后重开终端。

## 自测与解析

### 1. 离线示例运行成功，能够证明什么？

- A. 某个真实模型已能自主科研

- B. 这组输入下教学流程能够运行

- C. 所有未来输入都可靠

- D. 研究结论已经得到验证

**答案：B。** 运行成功证明当前流程可执行，不能替代模型测试、真实数据分析或科学论证。

### 2. 第一版助手最适合哪种任务？

- A. 处理一切科研事务

- B. 自动作出临床判断

- C. 从给定三份资料整理可复核证据卡

- D. 无限搜索直到得到肯定结论

**答案：C。** 有限输入、清楚输出与可检查的来源，使任务能够逐步实现和验收。

## 小词典

- **Agent**：模型参与选择下一步动作，外围程序负责约束、执行和检查的系统。

- **Workflow**：主要步骤与转移规则预先确定的工作流。

- **虚拟环境**：隔离一个项目的Python解释器和第三方依赖。
